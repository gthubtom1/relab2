# 审查表（审查附录）

整盘 / 全局 / 出口：没有这张表，不许戴帽子、不许写 CLEAN。这一刀复核用小表（只列本刀碰到的人可见句子），不要假装整盘已审。

表必须从**这个项目**长出来，不能从通用清单、FEATURES、旧版、现有测试、作者自评长出来。桌面 / 网站 / 命令行 / 接手都这样。不要把某一家产品的按钮文案写进技能当考题。

## 先分析，再填表

对着人会碰到的表面拆，不要对着模块名拆：

1. 人看见什么：每一屏、每条命令输出、每个数字、每个状态词、每个按钮、每层开关。
2. 这句话对谁成立：配置世界、从现在起还剩的世界、库存还剩、重试还剩、开关还剩、上次结果、登录态。
3. 中途现场：不是从零、不是窗起点、不是空沙箱。已经消耗过、中途才打开、目录不够、只开了一层门、上次不明、没登录。
4. 同屏 / 同输出一起出现的数字：必须能指到同一个公式。对不上就是洞。
5. 很久没改的核心：整盘范围内。没 diff ≠ 不用审。

## 表头（照此列，不要另造一套绿勾表）

| 人看见的句子| 这句话对谁成立| 怎么证伪（中途现场）| 什么不算绿|
|---|---|---|---|
| 界面/命令里那句原话| 配置窗 / 剩余窗 / 库存 / 重试 / 开关 / 上次结果 / 登录| 具体输入、时刻、剩余量| 旧测试、满额公式、空沙箱、只跑本轮 diff、钉死窗起点时钟的断言|

一行一句。一句里有两个数字，拆成两行，再加一行「这两个数字是否同一公式」。

## 口径窗（各类项目都会中，举例要发散，不当考题）

人看见的句子常常像「还剩 / 余量 / 今天最多 / 进度 x/y / 还能做 N 次」。代码和测试却按**配置好的整段**算。两边自洽，对人是错的。

常见差（想到同类，不要只交这一道）：

- **时间：** 配置窗是 05:00–22:00，人下午才打开。人读「今天最多 / 余量」应是从现在到窗结束；按满窗长度算出的数不是绿。
- **次数：** 人填了每天 N 条；库存只剩更少。余量不能大于还在的东西。
- **重试：** 上限是 3；这一次已经用了 2。人看见的应是还剩 1，不是上限 3。
- **开关：** 总闸 / 任务开关 / 平台开关。只开了一层时，「在跑」不成立。
- **上次结果：** 进度条在走，上次是 UNKNOWN / 失败。不明不能当已完成。
- **登录 / 就绪：** 「待发」但没登录、文件夹没扫过。字面就绪不是真就绪。
- **账单 / 配额：** 月额度按整月算，人月中才开通。剩余天数与剩余额度必须同一套钟。
- **队列：** 「还有 N 条」按入队总数算，人已经处理过一批。未处理才是 N。

同屏反例：一个数按剩余窗走（下次 21:24），旁边一个数按满窗走（余量 25）。人会信两个都对。

## 什么不算绿（写进每一行的最后一列）

- 现有测试按配置窗 / 满额 / 空数据 / 窗起点时钟断言，并且绿了
- 代码和测试在同一错误口径上自洽
- 本轮没改这段核心，所以没看
- 隔离沙箱从零开始，人却是中途进来
- FEATURES / 旧版 / 作者 STATUS 写过「已有」
- Cursor Bugbot / 安全审查的 diff 全绿
- 运行皮两列对上了，但口径窗没打

钉死满额公式的测试，是**反证**（公式被保护成配置窗），不是剩余窗已经过了。

## 按表审

- 表先出现在本会话，再读代码。代码是给表找证据。
- 表外但人会碰到的，补进表再打，不要口头「也看了」。
- 每一行写清：打了什么中途现场、证伪没证伪、不算绿的东西用过没有。
- 四顶帽子、运行皮、假设清单对着行用，不另开一套通用考卷。
