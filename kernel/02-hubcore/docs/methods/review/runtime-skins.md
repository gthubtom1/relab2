# 运行皮对账（审查附录）

客户真正执行的那一层叫**运行皮**。审查必须先写两列：这次实际跑了什么 / 客户会跑什么。两列不等，那一层就是未验证；测试绿、窗口亮、源码能跑，都不能顶。

不要点主人正在用的窗口或生产数据。自己的包、生产构建用隔离用户数据或另装目录跑。别人的未知 EXE/安装包/载荷不许在日用机当攻击脚本，停下来等人点头。

## 各形态常见差（举例要发散，不当考题）

| 形态| 常被误当成「已测」| 客户皮| 必须另打的差|
|---|---|---|---|
| 桌面| 开发运行器、源码目录、空配置| 安装目录里的产品主程序、打进包的资源、覆盖安装留下的数据| 产品文件名/中文路径、子进程怎么说话、归档内外、升级后旧会话|
| 网站| 本机开发服、mock 接口、未打包前端| 预发/生产构建、真网关、真租户| 构建后的前端、环境变量、CDN 路径、登录态|
| 命令行| 直接跑脚本、当前 venv| 安装后的命令、冻成的 exe、PATH 里那一份| 入口是否还是脚本、工作目录、没有终端|
| 接手| 工作拷贝里直接跑| 部署后客户用的那一份| 按真实形态走上面三行，不要另造一套|

还有一层常漏：主程序旁边的帮手（子进程、工具进程、工作线程、边车、定时任务）。测试若关掉它们或换了一种说话方式，等于没测客户皮。

## 接缝（绿而真红常藏这里）

不要只问「这段逻辑对不对」。问：**测试认死的环境和客户认死的环境是不是同一套。** 两套各自绿、合起来挂，审查若只读函数会认为没问题。

常见差（举例要发散，不当考题）：

- 测试给主程序加了环境变量/解释器标志，进程已经不是客户点的那个身份
- 测试用空数据目录、临时用户目录；客户带着旧会话、旧配置、中文路径
- 测试不归档、不安装、不走生产构建；客户跑的是包内文件
- 测试直接调内部函数；客户走的是主程序 → 帮手 → 磁盘这一串
- 门禁/CI/单测绿了，但命令序列、工作目录、准备好的目录和客户皮不同

帮手怎么拉起、怎么说话（管道、消息、文件、退出码），算运行皮的一部分。测试换了说话方式，不能顶客户皮。

## 对账怎么写

- **客户皮：** 人实际点的主程序 / 主命令 / 真页面是哪一个文件或哪一次部署。
- **审的皮：** 这次命令、解释器、环境变量、工作目录、数据包。
- **差：** 只写真有差别的项。没有包、没有部署时，写「客户皮尚未存在，本层未验证」，不要写成已测。
- **自己的包：** 隔离用户数据，跑包内主程序。开发运行器绿了，只能证明开发皮。
- **覆盖/升级：** 还要打旧数据、旧会话、旧配置还在时的那一刀，干净机装新的不能顶。
- **口径窗：** 皮对上了，人看见的「还剩」仍可能按配置整段算。隔离测试钉在窗起点、空库存、全部门开着，只能证明那一窗，不能顶中途现场。见 [review-table.md](review-table.md)。
