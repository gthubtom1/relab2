# 排障方法

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。排障只是中途一刀。做完按 WORK-HANDOFF 的方法调用链，回到直接调用方尚未做完的动作；主线的授权、打包与交付要求继续有效（见 `docs/ENGINEERING-CONTINUITY.md` 的当前工作包）。堆栈/traceback 印出来 ≠ 修好。

> 找根因，不是打补丁盖症状。

## 顺序

1. **稳定复现**：先找到"每次都能触发"的最小步骤。不能稳定复现就先收集触发条件。
2. **读真实信号**：日志、栈、返回码、进程/网络观察——看事实，别脑补。
3. **二分缩小**：砍掉一半、看还犯不犯，快速圈定范围。
4. **提假设 → 最小实验验证**：改一处看变化，一次只动一个变量。

## 和 state 配合

- 卡住、找不到、钻死角：先走 AGENTS「卡住开会」，不要一个人磨。轻量不要开会；开会不是换产品线。开完仍无新证据 → 停，用 `state attempt` 记账并出决策卡。

## 别假装

- 症状消失 ≠ 根因解决（可能只是掩盖或时序变了）。
- 改了就不犯 ≠ 知道为什么——说不清根因就是没修好。
- 单元测试绿 ≠ 真实场景不犯。
