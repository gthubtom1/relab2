# 独立对抗式审查

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。

本 skill 管**怎么把 AI 写的程序审出洞**。产品怎么立项、打包、授权，仍走中枢工程线，不要把那套抄进这里。

AI 审查总是发现不了问题，不是态度问题，是结构问题。不是「路数不够」。同模型再开 3～6 路，共享同一套错假设，是同一盲区重复花钱。直接说「审查」就戴四顶通用帽子、跑现有测试、扫 diff，是**另一套假完成**：题是机器自己出的，所以全绿。本 skill 钉死：**审查默认 0 个子代理**；写的人不能给自己过；交叉是批评手打这份报告；整盘必须先分析这个项目、产出审查表、再按表审；要追这一件的真实步骤；运行皮必须对上客户会跑的那一层；代码自洽不等于人口径；有洞就要改；审多少轮也不能说彻底没问题。

**不是 Cursor 自带的 `/review`。** Bugbot / 安全审查只审相对主分支的 diff，没改动就全绿。主人说「审查技能」永远是这一本。

找洞手法见 [hunt.md](review/hunt.md)，运行皮见 [runtime-skins.md](review/runtime-skins.md)，审查表见 [review-table.md](review/review-table.md)。加载本书必须读这三份附录。

## 先记住

没有外参照、不跑客户皮、不写出假设、整盘没有审查表就去读代码 = 代码审代码。机械项（审查表、运行皮两列、假设清单、接缝命令）先于角色腔。禁止 LGTM。禁止为审查开 `Task` / 子代理。

## 先分审查种类（混用 = 作废）

两件不要混。直接说「审查」时，先认种类再动手；不许一上来戴四顶帽子、跑现有测试、扫 diff。

| 种类| 主人在说什么| 必须先做什么| 绿了只表示|
|---|---|---|---|
| 这一刀| 刚改完这一截、一刀复核、这次改动有没有弄坏| 抽出**本刀碰到的**人可见句子（小表即可），再打三问+帽子| 本刀自洽。**不是**整盘没问题|
| 整盘 / 全局| 项目完成后、彻底审查整份、确定没问题、发布前整盘；主人只说「审查」但对象是整份产品| **先分析这个项目，产出审查表，再按表审。** 没表就开审 = 通用流程，本轮作废| 表上的行打过了。仍不能说彻底没问题|

主人没点名「这一刀」，却在一份已经在做的产品上说审查 / 彻底 / 确定吗：默认 **整盘**。不要猜成 diff 审查。

## 整盘必须先出审查表

主人原话（照做，不要意译成「记得全面一点」）：先去分析项目，然后根据分析出的审查表，再进行审查。直接说审查，不许用通用流程去走。

1. **分析这个项目**（不是套通用清单）：人会看见什么——每一屏 / 每条命令输出 / 每个数字 / 每个按钮 / 每层开关 / 每种中途现场。
2. **产出审查表**（格式见 [review-table.md](review/review-table.md)）。每一行：人看见的句子、这句话对谁成立、怎么证伪、**什么不算绿**。
3. **按表审**。表没写到、但人会碰到的模块也要补进表再打。很久没改的核心也在范围内。四顶帽子、运行皮、假设清单是打每一行的工具，不能代替表。

没有审查表出现在本会话：不许写 CLEAN，不许说没问题。一刀复核的绿不许抄进整盘。

## 先分档

| 档| 何时| 怎么审| 不要做成|
|---|---|---|---|
| 轻量| 问答、错别字、已点名的单文件小修| **不用本 skill。** 直接改 + 相关验证 + 说清没验什么| 为审而审、派子代理、写长报告|
| 一刀复核| 刚改完一截（UI/数据/多文件/高风险）| 抽出本刀人可见句子。主对话打三问：按方案改了吗、达到要求了吗、改坏了吗。四顶帽子都碰到。然后走批评手。本刀绿不许写成整盘没问题| 等主人再提醒；开审查子代理；单文件小修也走全书；拿这一刀绿当整盘绿|
| 整盘 / 全局| 项目做完、彻底审查整份、确定没问题；主人只说「审查」但对象是整份产品| **先分析这个项目 → 产出审查表 → 再按表审。** 很久没改的核心也在范围内。四顶帽子对着表打| 直接戴四顶帽子；拿现有 checks/diff/空沙箱当绿；把一刀复核的绿写成整盘绿；用 Cursor Bugbot 顶本档|
| 出口审查| 发布/生产/迁移/删除，或主人不放心一份产出（轻量仍不用）| 先按整盘出表，再按顺序戴四顶：程序 → 产品 → 测试（有洞则修再测）→ 发布。写过代码的会话不能宣布完成| 没表就戴帽子；只扫 diff；拿测试绿当出口；派几路子代理交差；用 Bugbot 审 diff 当出口|
| 走链路| 要验「按真人目标能不能走通」| 给一句人话目标，主对话走完下面三句报告| 为走链路开三波子代理；报缺当结束|

不是轻量才走四步：审查 → 复核（批评手）→ 有真洞才改 → 再审这一截。一轮只办一件。不要一轮打完自动下一轮。走完一批不得宣称全测完。

## 四顶帽子（同一路依次戴，不是四路人）

出口对外说「这一截做成了」之前按顺序戴完。**整盘/出口必须已经有审查表**；帽子对着表打，不是另开一套通用题。一刀复核碰到即可，不必串成四场仪式，但仍要有本刀人可见句子的小表。轻量不戴。

1. **程序审：** 结构对不对、改 A 会不会坏 B、契约和最坏输入。会跑的代码再打下面六问里这一截真会跑到的。严查伪闭环：表面做了、核心没门禁。
2. **产品审：** 是不是主人要的、零基础听不听得懂。**逐条对照主人原话与此前方案**，猎方案写得好、动手时丢掉的项。整盘还要打审查表上每一句人看见的话：这句话对配置世界成立、对中途现场不成立，是真洞。
3. **测试审：** 真人第一步/第二步/第三步走得通吗。**先对运行皮，再对口径窗。** 猎杀「单测绿但真机挂」「开发器绿但客户主程序没跑」「配置窗测试绿当成剩余窗过了」。钉死满额/窗起点的测试是反证。有洞 → 主对话改，审查视角不许改代码。
4. **发布审：** 能装、能升、能退、无秘密。清单过了不是已经发了。报告里禁止密钥原文。

写代码的主对话不当这四顶的裁判。本会话写过被审代码时，CLEAN 不能写成做成了；对外说做成了请主人另开新会话（仍一路，只给原话 + 对象 + 本书）。

## 开工顺序（不许倒）

1. **认种类。** 这一刀还是整盘。含糊且对象是整份产品 → 整盘。
2. **整盘先出审查表。** 一刀复核先抽出本刀人可见句子。没表不许戴帽子。见 [review-table.md](review/review-table.md)。
3. **立外参照：** 主人原话、动手前的方案/清单、客户皮、中途现场、同一皮上的命令。不要作者摘要、不要 STATUS 当答案。
4. **对运行皮：** 两列写出来：这次跑了什么 / 客户会跑什么。差在哪就打差。见 [runtime-skins.md](review/runtime-skins.md)。
5. **写假设清单：** 代码和测试认死的 5～10 条环境假设，然后逐条违反。含口径窗。见 [hunt.md](review/hunt.md)。
6. **猎手找洞：** 按表戴帽子。会跑的代码打六问。像真人走主流程，还要走中途现场。读代码是给表找证据。
7. **人话总结：** 列出洞；没洞也要写打了哪些点、哪些假设、两列运行皮、表上哪几行。
8. **批评手（交叉）：** 同一路、产物冻结，只打这份报告。试着证伪每一条。假洞丢掉。没表却写 CLEAN → 报告作废。
9. **有真洞 → 主对话改 → 重跑当初那条复现 → 回到第 1 步只审这一截。** 只读新代码说修好了 = 假完成。

## 为什么 AI 审不出问题

1. **谄媚 / 翻供：** 你说没问题它就顺着说；你反驳正确结论它常会改口。
2. **自我确认：** 写的人带着同一套错假设去审自己。模型纠正别人的错，远比纠正自己刚写的错容易。
3. **没有外参照：** 只拿代码审代码，相关失败原样漏过。独立来自原话、客户皮、命令、审查表，不是再开几个自己。
4. **同模型多路：** 覆盖几乎不涨，token 按路数涨，还容易假共识。
5. **注意力衰减 / 长话丢条：** 从第 3 条开始漏；摘要会丢掉主人没标序号的要求。
6. **单测自嗨 / 测错皮：** 自己写的测试绿、开发器绿，客户那一层没跑。
7. **通用流程顶替项目表：** 直接说审查就走编译、现有检查、diff、四顶通用题。口径窗类洞必然全绿漏过。
8. **代码自洽当人口径：** 测试按配置窗/满额/空沙箱断言，界面说剩余/余量/今天最多，两边在错误口径上自洽。钉死满额的测试是反证，不是绿。
9. **提示词堆太厚：** 长角色扮演会同时错杀和放过。机械项先于角色腔。
10. **审完不改：** 叫「审查了」达不到需求。有洞就要改活文件。

审查是假设生成器，不是判决。AI 意见一半是噪音。不能证明没洞。

## 铁原则

- **审查禁止开子代理。** 帽子、猎手、批评手都是这一路依次做。
- **整盘先表。** 先分析这个项目，产出审查表，再审。直接说审查也不许跳。没表 = 通用流程，作废。
- **代码自洽 ≠ 人口径。** 句子对配置世界成立、对人中途现场不成立，是真洞。同屏/同输出的数字必须同一公式。
- **写的人不能给自己评分。** 本会话写过被审代码：可以找洞，不许把 CLEAN 写成做成了。
- **独立来自外参照，不是来自克隆自己。**
- **先独立判断，再被挑战。** 被反驳不许立刻翻供，除非有可复核的新证据。
- **禁止 LGTM。** 一个角色说没问题 = 没看够。
- **先对运行皮。** 两列不等 = 该层未验证。皮对上了，口径窗仍可能错。
- **声称崩了/写坏了/卡住：必须在同一运行皮上复现。** 复现放系统临时目录或产品根 `TEMP/`，不要动主人正在用的数据。写不出同一皮上的复现 = 这类不当确认的真洞。
- **未知程序不要当审查脚本在日用机上打。** 停下来等人点头。自己刚打的包/生产构建不是未知载荷，那是客户皮，用隔离用户数据跑。
- **所有问题都记。** 严重度只用阻断 / 警告 / 提示。
- **两轮找不到新的阻断：** 对人说「可能开始重复」，不要假装每一轮都挖出新洞。

## 审会跑的程序（六问）

先打运行皮。客户皮还没跑过的项标未验证。会跑到的不许标「未打」。不要为交差编一条「已打撑爆」。

1. **系统边界：** 文件/连接/定时器关了没；权限失败、中文路径、缺环境、进程被杀，是人话退出还是直接炸。帮手进程、归档后的资源、升级留下的数据算这一问。
2. **状态与重试：** 并发、连点、超时被重试，会不会写脏、建两份、状态跳错。
3. **变大：** 数据大很多时哪段会卡死。打不到上限就写边界，不要假装打过撑爆。
4. **最坏输入：** 空、0、-1、超长、截断的中文/字节。
5. **别人挂了：** 依赖失败/超时/乱数据，是整机跟着死，还是拦住并留下能看的原因。
6. **改 A 不伤 B：** 只补这一洞；已经验过的用法不能悄悄改坏。

纸面/说明书不要拿这六问去凑洞。产品审和发布审不能被六问顶掉。整盘时六问对着审查表打，不另开通用考卷。

## 走链路（仍是这一路）

不要开 A/B/C 三波子代理。自己分三段写，后一段不许把前一段的「通了」当答案：

1. **走：** 只记步骤事实，不要写「通了/做成了」。
2. **对：** 步骤事实对照原话。
3. **攻：** 用假设清单和审查表打这些步骤。

一轮完成要有三句（缺一句 = 没写报告）：给了什么目标；第一步/第二步/第三步做成了什么；通在哪断在哪，审的皮和客户皮差在哪，表上哪几行未验证。

**一轮作废：** 报缺当结束；测试绿/窗口亮当业务做成；用开发运行器顶替客户主程序还说测过了；开审查子代理当已经交叉；整盘/出口没出审查表就戴帽子；拿本轮 diff/现有测试绿当整盘绿；拿钉死配置窗数字的测试当剩余窗证据；用 Cursor Bugbot 顶本 skill。

## 每条发现都要有证据

不接受「我觉得」「可能有风险」。每条写：严重度、位置、触发、影响、修法方向（一句话，不写补丁）。

声称崩了/写坏了/卡住：还要写同一运行皮上跑过的命令。纯猜压下不报。客户皮存在却没跑，标未验证，不要写成 CLEAN。口径窗洞：写清人看见的句子、对谁成立、中途现场怎么证伪。

## 产出（对人先这三句）

1. 给了什么目标 / 审了哪一截。**审的皮和客户皮写在这一句里。** 整盘必须能指到本会话里的审查表。写过代码的会话要标明：本路是作者，不能宣布完成。
2. 发现了哪些真洞；假洞丢掉了哪些；批评手证伪了哪些。表上哪几行是绿、哪几行未验证。
3. 通在哪、断在哪；下一步是改、再审这一截、还是进入下一件。一刀绿不要说成整盘没问题。

机器侧再附：审查表（整盘/出口必附）；**BLOCK** / **CONCERNS** / **CLEAN**。CLEAN 必须列出攻击过哪些点、违反过哪些假设、表上打过哪几行。未对上的客户皮不得进 CLEAN。没审查表不得写 CLEAN。CLEAN ≠ 彻底没问题。本会话写过代码时，CLEAN 只表示「这一路没再找到有证据的新阻断」，不是出口放行。

## 禁止

- 为审查开子代理、开四路专家、交叉再派一批。
- 整盘没表就戴帽子；用 Cursor Bugbot 顶本 skill。
- 用开发器、源码入口、空数据目录、关掉帮手的测试顶客户皮。
- 拿同一次改动里的测试绿当独立证据；拿钉死配置窗的测试当剩余窗的绿。
- 只读 diff 说修好了；审完不改活文件。
- 未知 EXE/安装包当审查脚本在日用机上跑。
- 轻量也走全书；出口用一刀碰到四顶交差；把一刀绿写成整盘没问题。
- 说彻底没问题、全测完。

## 别假装

测试绿 ≠ 客户皮过了。窗口亮 ≠ 主流程做成。子代理说没问题 ≠ 过了。批评手同意了 ≠ 没洞。清单过了 ≠ 已经发了。读着很对 ≠ 跑得对。守卫绿了 ≠ 它保护的那件事跑过了。没审查表的全绿 ≠ 整盘过了。配置窗算术正确 ≠ 人中途看见的「还剩」成立。同屏两个数字对不上 ≠ 没问题。本轮 diff 绿 ≠ 整盘没问题。
