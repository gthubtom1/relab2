### 3.2 逐条断言判定（每格写实测结果）

| 宿主 | ① 原内容一字不丢/不改/不重排 | ② 我们的块在最上方 | ③ 一对明确标记、摘得干净 | ④ 卸后逐字节回到装前 | ⑤ 装前没有也能装、卸后删干净 | ⑥ BOM 原样 |
|---|---|---|---|---|---|---|
| A | **通过**·原文 1003 B / 37 行 / `b07b7f9b94a7df44` 整段落在文件末尾，字节比对一致 | **通过**·第 1 行即 `# >>> hubcore hub >>>` | **通过**·块 1246 B，BEGIN×1 END×1，手工摘掉后 = 装前 1003 B / `b07b7f9b94a7df44` | **通过**·卸后 1003 B / 37 行 / `b07b7f9b94a7df44`，与装前完全相同 | 不适用·装前就有文件，卸后文件仍在，`hub/` 已删 | **通过**·无 BOM → 无 BOM |
| B | **通过**·原文 283 B（BOM 之外）整段落在末尾，一致 | **通过**·第 1 行即 BEGIN（BOM 之后） | **通过**·块 1246 B，BEGIN×1 END×1，摘掉后 = 装前 286 B / `3bddefe1cc462969` | **通过**·卸后 286 B / 14 行 / `3bddefe1cc462969`，与装前完全相同 | 不适用·同上 | **通过**·有 BOM → 有 BOM → 有 BOM，3 个字节 `EF BB BF` 全程在第 1–3 位 |
| C | **通过**·原文 234 B / 15 行 / `00442141e9668b8d` 整段落在末尾，一致 | **通过**·第 1 行即 BEGIN，主人的 `# 我的项目` 被顶到**第 15 行** | **通过**·块 1245 B，BEGIN×1 END×1，摘掉后 = 装前 234 B / `00442141e9668b8d`；主人自己的 `<!-- MY-OWN-BLOCK -->` 一字未动 | **通过**·卸后 234 B / 15 行 / `00442141e9668b8d` | 不适用·同上 | **通过**·无 BOM → 无 BOM |
| D | 不适用·装前无此文件 | **通过**·新建的 `AGENTS.md` 第 1 行即 BEGIN | **通过**·块 1253 B，BEGIN×1 END×1，摘掉后 = 空 | 不适用·装前无此文件，见⑤ | **通过**·装出 1253 B / 14 行 / `2724d7bdaf1bbfb3`；卸后该文件**被删**，家目录只剩 `主人自己的笔记.md`，无任何临时残余 | **通过**·无 BOM → 无 BOM |
| E | **通过**·原文 168 B / 13 行 / `cdf272947b5be97f` 整段落在末尾，CRLF 未被改写 | **通过**·第 1 行即 BEGIN | **通过**·块 1244 B，BEGIN×1 END×1，摘掉后 = 装前 168 B | **通过**·卸后 168 B / 13 行 / `cdf272947b5be97f` | 不适用·同上 | **通过**·无 BOM → 无 BOM |

另附两项（不属于六条断言，但一并验了）：A–F 每个家目录自带的 `主人自己的笔记.md` **全部逐字节未变**；A–D/E 装完再卸，家目录里**没有** `.hubcore-stage-*` / `.hubcore-old-*` / `.hubcore-check-*` / `*.tmp-*` 任何残留。

六条的通俗解释：

- **① 原内容保留**：装后文件去掉开头的标记块，剩下的部分与装前文件**逐字节相同**。
- **② 置顶**：装后文件**第 1 行**就是 `# >>> hubcore hub >>>`，主人的内容原封不动排在后面。
- **③ 标记成对**：每个宿主装后 `BEGIN` 出现 1 次、`END` 出现 1 次；手工把这一块摘掉，剩余内容与装前逐字节相同（D 宿主摘完为空）。
- **④ 逐字节回装前**：卸载器自己打印的分支是「摘掉 1 个标记块后与备份逐字节相同 → 整体还原备份」，卸后 sha16 与装前 sha16 完全相同。
- **⑤ 新建与清场**（D）：装完新建 `AGENTS.md` 1253 B；卸完该文件**被删掉**，`hub/` 整棵删除，家目录只剩主人自己的 `主人自己的笔记.md`。
- **⑥ BOM**（B，刚修的坑）：装前 286 B（第 1–3 字节是 `EF BB BF`）→ 装后 1532 B，**开头仍是 BOM** → 卸后 286 B，**BOM 还在，sha16 与装前完全相同**。没有出现「双 BOM」或「BOM 掉了」。

## 4. 专项：装完之后主人自己改一行，再卸

这是「不覆盖主人后续修改」的唯一证明。对 A/B/C/D/E 各做一遍：装 → **由主人在自己的内容末尾加一行**「这是我装完之后自己加的一行，不许被卸掉。」→ 卸。

| 宿主 | 主人那行还在 | 我们的标记摘净 | 卸后整份 = 原文 + 主人那一行 | 卸后字节 / sha16 | 卸载器走的分支 |
|---|---|---|---|---|---|
| A | 是 | 是 | 是 | 1064 B / `f9e7078c44def925` | 摘掉 1 个标记块（主人后来改过）→ **只摘块不覆盖** |
| B | 是 | 是 | 是 | 348 B / `2f247a838f83561c` | 同上 |
| C | 是 | 是 | 是 | 295 B / `17ab2b7eb1c3b056` | 同上 |
| D | 是 | 是 | 是 | 61 B / `c7615da8a65b0e26` | 同上（D 是新建文件，主人后写的一行也保住了） |
| E | 是 | 是 | 是 | 229 B / `ea54d601f7a61b19` | 同上 |

也就是说：**主人一个字没改时，卸载走「整体还原备份」；主人改过之后，卸载自动切换成「只摘块」，主人的修改一个字节不丢。** 这个分叉是卸载器自己判的，不是靠调用方告诉它。

## 5. 不成立的那一条：主人的文件里抄了我们的标记行（宿主 F）

**判定：断言 ①（原本内容一字不丢）在这种情形下不成立，而且是「装的那一下」就已经毁了原文，不是卸载才出的事。**

### 5.1 复现（3 步，全部现成）

1. 造一个家目录，入口文件 `AGENTS.md` 内容如下（这就是 F 宿主，233 B / 7 行 / sha16 `c10bd86ff4a3e85b`）：

   ```
   # 我的笔记

   装完之后，hubcore 的块在文件最上面，从 `# >>> hubcore hub >>>` 开始，
   到 `# <<< hubcore hub <<<` 结束。

   - 这两行是我自己写的说明文字。
   - 卸载的时候别把它当标记吃掉。
   ```

2. 正常跑 `install.py --source dist/hubcore --host-home <这个家目录>`，退出码 0，**不报错、不警告**。
   装完文件 1420 B / 20 行，文件里 `# >>> hubcore hub >>>` 只剩 **1 个**（忠实插入应该是 **2 个**：我们写 1 个、主人自己写了 1 个）——**主人在装之前就已经少了两行**。
3. 跑 `uninstall.py --yes`，退出码 0。卸完 174 B / 6 行，**不是 233 B**，整份少了 59 字节，第 3 行变成一句被揉坏的残话：

   ```
   装完之后，hubcore 的块在文件最上面，从 `` 结束。
   ```

   整份文件比装前少了 59 个字节：第 3 行和第 4 行被粘成了一句不通的话。

### 5.2 根因（精确定位）

- `03-bundle/_bundle_lib.py:158-175` 的 `strip_marker()`：在**整份文件的文本**里 `find(MARKER_BEGIN)`，找到就从那里一路删到 `MARKER_END`，然后循环删到一处不剩为止。它**不判断这串字是不是我们写的那一块**（不看成不成行、不比内容、不对清单）。
- `03-bundle/uninstall.py:50-67` 是同一段逻辑的复制粘贴，同样的问题。
- 致命的一步在 `03-bundle/_bundle_lib.py:178-187` 的 `insert_marker()`：**装的时候也是先 `strip_marker()` 再插新的**。所以第一次安装就已经把主人那两行删掉了——重装一次结果一样（实测：重装后仍是 1 个标记，主人那两行不在）。
- 换句话说，现在这个「框住」是靠**文字搜索**实现的，不是靠「我们自己写的那一块」。冷咖啡要求的「框在一个范围之内、能精准定位」，在没有同名文字时成立；一旦主人的文件里出现过同样那串字，框就框错了，而且**静默发生、不报错**。

### 5.3 影响面与建议（只报告，不代改）

- 触发条件：主人或别的工具在自己的规则文件里**引用了** `# >>> hubcore hub >>>` 这串字（比如写安装说明、做文档、贴日志）。
- 后果：装一次就永久改主人的文件，且当场没有任何提示。概率低，但踩中就是「静默改主人原文」，正好是这次验收最不该放过的事。
- 修的方向（属于 T1 的 `03-bundle` 分区，我没有动）：`strip_marker()` 只认**独占一行**的标记，或者按清单里记录的**块指纹**精确匹配后再摘；`insert_marker()` 在插入前不应删除任何不是自己写的那一块。
- 复跑验证：改完直接 `cd 06-verify && python probe_marker.py`，退出码应从 1 变 0。

## 6. 顺带看见的（不算缺陷，写清楚免得以后误会）

- **标记块大小随家目录路径长度变化**：实测 1244–1253 B（首行那句「本机中枢在 …」里带着宿主家目录的真实绝对路径）。装前自检的 1200 B 上限只管**底线正文**（实测 974 B），不包含首行指针行，所以不会误报。整块常驻 1.25 KB，远低于规格书 §4 要求的 3 KB。
- **块里出现 `D:\临时项目\...` 是正常的**：那不是源仓路径泄漏，是这次假宿主家目录本身就在 `06-verify/TEMP/` 下。装到真机上时这一行会是宿主自己的家目录。
- **装完自检是真跑过的**：每个宿主装的时候都抽 3 个文件对 sha、真跑了一次 `ctxiso status` 和一次 `state.py --help`，全绿；A–F 装/卸退出码全是 0。
- **卸干净清单**：每个宿主都删掉 91 个受管文件 + `hub/` 整棵（含清单、备份、侧车状态），家目录里只剩主人自己的东西。
