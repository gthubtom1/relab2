## 一、找到技能包

你可能在任意目录开工，所以**不要用相对路径**。三级递进，命中即停：

```powershell
# 1) 环境变量（换机/换盘时设这两个覆盖约定值）
$env:REVERSE_SKILL_ROOT    # 技能包根，本机例：C:\relab2
$env:REVERSE_TOOL_ROOT     # 工具根，   本机例：D:\Tools

# 2) 本机约定位置
C:\relab2        # 技能包根
D:\Tools         # 工具根

# 3) 都不行 → 自己搜。TOOL-CHAIN.md 全仓唯一，可当标记文件
Get-ChildItem C:\ -Filter TOOL-CHAIN.md -Recurse -Depth 4 -ErrorAction SilentlyContinue
```

定位到 `<技能包根>` 后，你只需要这两个：

| 相对技能包根 | 什么时候读 |
|---|---|
| `skillpack/skills/SKILL.md` | **每个阶段开始前**（见下） |
| `skillpack/TOOL-CHAIN.md` | 需要定位/安装工具时 |

> 读它们必须加 `-Encoding UTF8`：`Get-Content x.md -Encoding UTF8`。
> 本机代码页 936(GBK)，不加会读出乱码，然后你会误判成「文件不存在」。

## 二、★ 每个阶段都要重新判断技能（不是一次路由到底）

用户会直接说「帮我逆向这个 exe，绕过卡密」，**他不知道有没有壳、不知道该用哪个工具** ——
这本来就该由你判断。`SKILL.md` 里有一台**四阶段状态机**
（侦察排壳 → 动静反解 → 动态追踪 → 仿真验证），
每个阶段要的技能和工具都不同，`SKILL.md:169` 的 `reverse-engineering` 阶段门闩
（triage→static→dynamic→synthesis）就是给你逐步推进用的。

```text
每推进到一个阶段 → 重读 SKILL.md → 重新判断这一阶段该用什么 → 动手
```

**别在第一个阶段选定的技能里死磕到底。** 静态看不出东西就该转动态，
判定点不在你以为的那一层就该换层重新看。

## ★ 动手前必知三条（来不及等到读完文档才知道）

1. **GUI 程序不能进 bash。** 它弹窗等输入、零 stdout、进程永不退出 —— 同步等它等于整轮卡死，
   而且卡住时你察觉不到（那时你不在运行）。找它的 CLI 孪生：
   `die.exe`→`diec`　`Wireshark.exe`→`tshark`　`ida.exe`→`idat`
   `dnSpy.exe`→`dnSpy.Console`　`x64dbg.exe`→控制台 headless 版。
2. **不许猜工具路径。** 没查到就是没装，不是「可能在某个地方」。
   四级递进与登记模板 → `TOOL-CHAIN.md`。
3. **★分三层，别在最外层打转。** 「壳 / 加密容器 / 真正的程序」是**三层**，
   不是「资源里藏了个 payload」这种一个勾。判定点（卡密/授权/到期）**几乎从不在最外层的壳里** ——
   壳只负责解密 + 落盘 + 启动。在壳上折腾栈 cookie / GS / FLS 回调，是在**改症状不是改原因**，
   会在外面那层耗掉整个任务。分层判据与出判据 →
   `<技能包根>/skillpack/skills/reverse-engineering/references/re-agent-workflow.md` §2.1。
