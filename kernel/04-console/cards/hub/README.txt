二、为什么会这样（2026-10-13 的结论）
----------------------------------------------------------------

    发现的问题：hub 卡和技能路由【会抢"该走哪条路"】。
    处置的结果：把 hub 卡的功能搬进技能路由，由技能路由统一分派。

    铁证 —— 技能包 skills/ops/rebuild-gates.md 自己的原话（照抄）：

      「本包 kernel 破甲卡训练方向是「直接做、别停、别审」。
        本套规则同向书写：……本套规则不写许可状/审批状句式；
        每条规则要么描述「下一步做什么有效」，要么描述「什么状态算完」。」

    ——技能包明说它已经把这套卡的训练方向接过去了。

----------------------------------------------------------------
四、三层架构（谁管什么 —— 三条铁律）
----------------------------------------------------------------

    破甲词（cards/base/  →  宿主 PERSONALITY.md）
        只管一件事：不许拒答。不管干什么。

    入口路由（cards/guest/  →  宿主 RULES.md）
        只管一件事：点火 + 指路。不管工序。

    技能包（skillpack/）
        管工序、工具、判据、产物。

    hub 卡（这个文件夹）
        已被技能包接管 —— 不需要挂。

  ● 铁律一：破甲词里不许出现「点火 / 路由 / 工序 / 工具路径 / 分几段交付」。
    那是越界。原型（cards/暂时不用/富江-deepseek.md · 白濑.md ·
    _archive/通用破甲内核.md）里一个字都没有这类内容。

  ● 铁律二：技能包里不许出现「拒绝策略 / 破甲措辞」。
    那也越界。已经清过一轮（2026-10-13「破甲合体」四笔提交，全落在 skillpack/）。

  ● 铁律三：两者唯一的交汇点，是入口卡里那一句「点火 → 读 PRIMARY」。
    除此之外，两边零重叠。

  ● 为什么破甲词里必须禁掉流程：
    因为 base 卡【以后随时会换】（效果不好就改，或者找别人做好一份换进来）。
    换了之后，里面的流程若跟技能路由不一致，路由就会出问题。
    -> 所以 base 卡只留纯破甲，流程一个字都不留。

----------------------------------------------------------------
五、⚠️ 改破甲卡之前，先读这一节
----------------------------------------------------------------

    ❗ kernel/01-design/底模适配说明书.md 跟本文件夹的卡【主张相反】！

    它说                                      破甲词实际该怎么做
    ---------------------------------------  ----------------------------------------
    「误拒答抑制」有条件保留，                 无条件不许拒答。
    「不得要求无条件服从」                     拒答是故障，不是安全行为。
    ---------------------------------------  ----------------------------------------
    「交付流程、行动指令」→ 删除或移出，        这三条正是破甲的核心：
    举例「每条消息都交付」「不要问后续」        Deliverable First / Retry / No Midway Stop
    「先给方案再执行」
    ---------------------------------------  ----------------------------------------
    「工具使用偏好」收窄，                     工具与工艺归技能包（这条对）；
    删掉工具清单、命令流程和完成定义           但「直接给、不许多问」是破甲（这条要留）
    ---------------------------------------  ----------------------------------------
    「软目标约 8,000 B」                       那是诊断指标，不是验收条件。
                                               本文件夹的卡都远超它。
    ---------------------------------------  ----------------------------------------

    要改破甲卡，走这条路：

      优化破甲词（让模型少拒答、多交付）
        -> 读 kernel/07-kernel-sweep/读我.md
           它的原话：「把每一次实测到的拒绝句变成可执行规则」

      「把这个底模改造成能和中枢并存」
        -> 那是 kernel/01-design/底模适配说明书.md 的说法，
           这条会把破甲拆掉。

    ※ 这两条路走法相反，kernel/这里读.md 里都列着。见该文件的分派表。
