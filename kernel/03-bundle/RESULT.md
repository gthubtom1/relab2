## 2.5 认块靠指纹：主人抄的标记行一个字节都不动

这是本次最严重的一个缺陷，而且是验收子代理先抓出来的。

**原实现**：在整份文件文本里 `find(BEGIN)` 找到就一路删到 `END`。**不判断这串字是不是中枢自己写的。**

主人完全可能在自己的说明文里抄一对标记，来写「以后卸载就是删掉这两行之间」：

```
# >>> hubcore hub >>>
# <<< hubcore hub <<<
```

那一对**不是中枢的块**，但原实现会当成块删掉——**主人那两行在装的时候就消失了**，
卸的时候还把主人自己的文字粘成一行（实测：233 B → 1420 B → 174 B，卸完比装前少 59 B）。

**现在的判据**（两条都满足才算「中枢的块」）：

1. `BEGIN` / `END` 各自**独占一行**（`^[ \t]*# >>> hubcore hub >>>[ \t]*$`）；
2. 第二行必须是**指针行**「本机中枢在 …」。

主人手抄的那一对第二条对不上 → 判定「这不是中枢的块」，**原样保留**。

配套的三条边界（验收会盯）：

| 情况 | 行为 |
|---|---|
| 主人在**中枢块内部**加了一行 | 整块照样摘掉，但卸载输出明写「中枢块内有 N 行不是我们写的（主人自己加的），已整块摘掉」——不静默处理 |
| 文件里有**多个中枢块** | **只摘最上面一个**，其余原样保留并报「还有 N 块中枢块，只摘了最上面一个，其余原样保留，请人工确认」——不许无声无息全删 |
| 文件里有**主人自己写的标记对** | 原样保留，报「原样保留 N 对主人自己写的标记行（第二行不是指针行——这不是中枢写的块）」 |

另外两处配套修的：

- **BOM**。带 BOM 的入口文件里第一行在字节上是「BOM + 标记」，不认它就当没装过。
  现在 `BEGIN` 正则允许前面挂一个 BOM，且 `find_marker_blocks()` 会把 BOM **排除在块外**，
  摘块时留着它。指针行（第 2 行）带宿主家目录、逐台机器都不一样，**不参与**「是不是我们写的」比对。
- **卸载器与装的时候写进去的块必须逐字符一致**。卸载器是自包含的（不 import 包内其它文件），
  所以它自己实现了一份 `marker_block()`（同 `_rule_text()` 读规则全文）。
  两份漂移了，卸载就摘不掉自己写的块。
  `pack.py` 每次打包都会**实跑**这两份并逐字符比对（`check_uninstall_sync()`），对不上直接拒绝打包。

验收：`06-verify/probe_marker.py` 退出码 **0**，

## 2.6 产物里一个字节码都不该有

`.pyc` 文件头里的 `co_filename` 记的是**编译时的绝对源码路径**，必然带构建机信息，无法事后剔除。
把带构建机路径的 `.pyc` 打进包里发出去，本身就是错的。三道闸：

1. **`pack.py`**：打包末尾剔除 `__pycache__` / `*.pyc` / `*.pyo` / `.state`。
2. **`install.py` 自检**：产物里有任何字节码就**拒绝装**。
   （子进程也加了 `PYTHONDONTWRITEBYTECODE=1`，自检自己不再制造字节码。）
3. **`uninstall.py` 收尾**：扫一遍并清掉运行期生成的，报数。

```
[ ok ] 产物里 0 个 .pyc / __pycache__
[ ok ] 产物里 0 个 .state/ 状态目录
```

`.state/` 同样是货：有人对着 `dist/` 目录在真仓库上跑过一次 ctxiso，状态目录就落在产物树里了，
它不含任何源仓路径所以禁词扫描是绿的，但会跟着装进每台机器。

## 2.7 一次半路崩盘，以及它的教训

收尾过程中我做了一次跨函数的批量替换（脚本按锚点切区间重写 `_bundle_lib.py` 的标记块那一段），
**区间比我想的宽，把相邻的 18 个函数/常量一起删掉了**（`stamp`、`list_package_files`、
`scan_refs`、`make_product_fixture`、`child_env` 等）。当时没有立刻实跑，
盘上留下一个**装不进去**的 `03-bundle`：`install.py:262` 调 `L.stamp()` 报 `AttributeError`，
`06-verify/probe_marker.py` 六个宿主全飘红，所有子代理都无法接手。

**教训**：改到一半必须立刻实跑一次。"改错了方向"可以回退，"改到一半停下"会让人接不了手。
这次的具体错法是——用脚本做区间替换，却没先确认区间边界；
函数级改动应该用精确的 `edit`，批量重写必须**改完立刻跑一次探针**。

修的过程：先补回丢失的 18 个定义并实跑装入确认 `EXIT=0`，再动下一处。
后续每改一个函数就跑一次，没有攒到最后。

### 4.1 这里挖出并修掉的两个真 bug

第一次跑验收 2 时，卸完的 sha 和装前差 1 字节。顺着查下去挖出两条，**都不是表面那个字节的问题**：

**bug 1：多补了一个换行。** `marker_block()` 本身已经以 `\n` 结尾，`strip_marker()` 又正好吃掉
标记块后面那一个换行，而 `insert_marker()` 还额外补了一个 → 装完再卸完，原文前面会多出一个空行。
改成直接拼接（不多补、也不 `lstrip` 掉原文开头的空行）后逐字符还原。

**bug 2：BOM 被静默丢弃。** `install.py` 用了裸的 `entry_before.decode("utf-8")`，
把 BOM 变成了正文里的 U+FEFF 字符；写回时又补上 BOM 字节 → **双 BOM**，卸完和原文差 3 个字节。
改成走 `L.decode()` / `L.encode(text, bom)` 这一对配套函数，BOM 才真正原样进出。

这类 bug 只在"主人用带 BOM 的编辑器写入口文件"时才发作，正文一个字没变，
肉眼看不出来，但文件已经不是原来那个文件了。装卸的验收标准是"逐字节回来"，所以必须堵死。

## 11. 未解决 / 未确认的问题

1. **活进程检测只认同名可执行文件。** `claude` 这类 npm 装的版本进程名是 `node.exe`，
   按同名认会漏。`hosts.py` 在输出里明写了这条盲区，没有假装覆盖到。
   要真正覆盖得读命令行，那需要 `wmic` 或 PowerShell 查询，超出了"只用 `tasklist`"的约束。
2. **装到非已知宿主时不做活进程检测。** 传入的 `--host-home` 不在 13 家名单里时，
   只做文件级检查，输出里明说「活进程检测按不到」。
3. **`--source-dir` 硬证明会短暂改名 `02-hubcore`。** 走 `try/finally` 必然改回，
   但那个窗口里若别的子代理正好要读 `02-hubcore`，会撞上。默认不传 `--source-dir` 时
   只做第一层（复制到系统临时目录），零风险。
4. **`CORE.md` 余量只剩 12 字节。** 改一个字就要重新压。
5. **标记块正文 974 / 上限 1200，余量 226 B。** 11 块底线都在里面，再加内容要重新算。
6. **`CORE.md` 里 `<家目录>` 保持占位符**，按父对话指示不替主人填。
7. **素材里还有 103 处引用指向主人产品目录/本机侧的文件**（`.hub/`、`OWNER-SPEECH.md`、
   `CHANGES.md` 等），它们在跑产品时才会被写出来，不随包走。verify 单独列为提示，不计失败。
