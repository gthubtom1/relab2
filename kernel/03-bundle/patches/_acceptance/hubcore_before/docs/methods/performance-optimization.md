# 性能优化方法

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。

压测/变快只是中途一刀。做完必须按 WORK-HANDOFF 的方法调用链，回到直接调用方尚未做完的动作；主线的授权、打包与交付要求继续有效（见 `docs/ENGINEERING-CONTINUITY.md` 的当前工作包）。交一组数字 ≠ 这一单结束。

压测要打**主流程**，不是只打一个空接口。前后同口径：并发（同时多少人）、失败率、延迟。单线程延迟数字不算压过。

## 先测量，后动手

- 用剖析器 / 计时 / 资源监控找到真正的热点，别猜。时间通常集中在少数几处。
- 定一个可观察目标（启动 < X 秒、内存 < Y MB），优化前后**同口径**对比。

## 常见方向（按证据选，不是全上）

- I/O、重复计算、N+1 查询、无谓拷贝、主线程阻塞、启动时全量加载。

## 别过度

- 达到目标就停；别为不构成瓶颈的地方牺牲可维护性。

## 别假装

- "感觉快了" ≠ 快了：要有同口径的前后数字。
- 本机快 ≠ 目标机快（低配 / 大数据量下再测一遍）。
