# 逆向方法（先锁层）

> 这是 EXE 二开 `1-access`（核心可用，含第二道门）的"怎么做"。唯一出口是：可回退 access 候选真实达到 `mission.success`，入口门和写动作门分开取证，或有证据的 `BLOCKED` 决策卡。探针候选 ≠ 给客户的包。阶段/停点见 `workflows/exe-rebuild.md`；公共铁律见 `../INVARIANTS.md`。
>
> **对主人先白话：** 做到什么、还缺什么、下一步看哪。「人话锁层」只写给自己（判定在哪一层），不要拿层名/工具名交差。一次只说一扇窗、一个键、不要点什么。机械项自己跑；进核心/下载/进游戏给人话清单等人测；点不了浏览器、UAC、进游戏要当场说。两句不能互相吞掉。

## 读完立刻做（别停在"我准备好了"）

1. `NOW`：读 `state status` 的 mission、当前候选和未满足制品；不知道当前访问目标就先停在阶段 0 补 `state plan`。执行面是不是主人日常 OS（H0）：未隔离默认不跑未知程序；仍要跑须这一次点头。见词汇表 isolation。
3. `NOW`：分开写"观察事实 / 1～3 条带相反预测的假设 / 未知项"。假设没写满，禁止开监控。
4. `ACT`：做一个能让两条假设对同一现象打架的最小实验（触发拒绝时看判定，或小范围静态圈定，都可以）。连续做到 access candidate 或 BLOCKED。没有用户决定、没有危险动作时，不为每个工具索要"继续"。access 须含 `entry_gate` 和 `action_gate`（不能 UNKNOWN）；禁止 launcher-only 冒充核心访问。入口门过了必须**自己触发一次写动作**（证据不要写「进页」）；仍拦着就 `state reopen --from 1-access`。

## 死规则（思考环压过查表）

公共全文在 `../INVARIANTS.md`「思考合同」。这里只强调四条：

1. **先锁层，再开工具/补丁。** DIE 标签、工具清单、壳名填不了「判定在哪一层」。
2. **一层一证。** 进页 ≠ 门已定位。拒绝文案换一句 = 新门。缺一层禁止毕业。
3. **同一拒绝只认一次。** 空闲挂钩、再截图、数连接、空日志、OCR、附近下一个跳转，都不是新证据。
4. **只动许可判定。** 禁止公共序列化 / 全部开关一刀切。脏候选不叠刀。旧地址、旧许可文件不当新 access。

反面教材仍在：静态全量反编译九小时没进核心。那**不是**「一律先动态」的许可证——动态 = 你触发会被拒绝的动作的同时，在判定点看见分支。空闲进程上挂工具、扫像素、数 TIME_WAIT，不是动态。

「进入核心页」是常见访问目标，不代表所有程序都有页面。以 `mission.success` 的可观察结果为准。不要预设一定是 keygen、改跳转或 launcher；成功标准是落到判定所在的层，不是叫出类型名。

禁令（不是路线图）：没有私钥就不能假装能签；见工具就停先当观察门，不要开绕过手册；壳不改变第一问，禁止「看见壳就 dump」当第一刀；本地已经决定进不进页时，禁止先拆对方站。

主人说「编译 / 别耗在页面上」= 工作拷贝里打最小可回退补丁，不是去重编没有的上游源码，也不能拿「没有 rustc」继续看网。

H0 已写在「读完立刻做」第 1 项，不要排到触发拒绝之后才想起来。

## 需要更深时，怎么开分析技能（默认客人，vendor 是后备）

**缺工具时停，不跑 vendor 安装脚本。** vendor 的 `bootstrap-reverse.ps1/.sh`、`browser-automation/scripts/setup.ps1`、`ida-reverse/scripts/install-autostart.ps1`、`kali/scripts/quick-setup.sh` 等会装全局工具、写 MCP、注册计划任务——等同 `AGENTS.md` 危险动作。分析缺工具：`tools.json` → Everything → `TOOLING.md` 报缺。清单见 `SOURCE.md`「高危脚本」。

**对外网络主动动作：** CTF「默认沙箱」不等于已获授权。探测/利用前绑定 scope + 目标 + 用户确认；只读/离线分析可直接做。

**默认不要当第二套入口：** `malware-analysis`、`edr-bypass-re`、OLLVM/UPX 脱壳笔记、`thick-client`、CTF 编排、任意 bootstrap。有壳 ≠ 养沙箱。目标自毁：从未跑过的原件重拷。投放恶意代码：停工换干净环境，不是改开 malware 找 IOC。

用它们的**方法**，证据 / 停点 / 候选仍回到 `state` 和 `INVARIANTS`。案例是别人怎么做的参考，不是当前产品的事实，别搬地址。

未知类型：无匹配 ≠ 停问「技能完整吗」≠ 套最近行 ≠ 先建 skill。先调查、写假设、做区分性实验。见 `../README.md`「没有匹配的 skill」。

## 步骤 1 · 自适应分诊（短，不全量）

至少判清：这次拒绝发生在启动前还是某个动作之后；判定在哪一层；哪些未授权就可观察。类型名填不了层，禁止六选一当闭集。壳只当约束。

先看这条拒绝（用户怎么描述、或已经做过的实验）。未过 H0 时只做静态只读，不要把「先跑样本触发」写成第一步。操作手册（DIE / PE / 字符串 / 路由跟进）交给客人或自加技能；中枢要的是能打架的区分性实验和层笔记。DIE/PE/字符串只当约束或线索，不是门的证明。

产出第一版功能—授权门假设图：入口层和写动作层分开写。用户不需要先告诉你完整功能。

## 步骤 2 · 锁层后的实验（动态或静态，没有规定先后）

动态：在工作拷贝上**你自己触发**会被拒绝的动作，记录输入、页面/动作、进程、请求、文件变化。空闲窗口挂工具不算。

静态：只看已经跟这条拒绝有关的函数/模块。禁止把「先动态」写成静态的前置。

无论哪条，都要：1～3 个可区分假设且带相反预测；没有信息增益就换**层**，不许磨同一跳；字符串、路径、域名只能当线索。没有调用链、状态差分或可重复分支，不能登记成已定位 gate。进页成功后必须再对自己点一次写动作。

回答：判定输入来自哪里；成功/失败改变什么；它控制进页、写动作，还是两者；是否还有第二道门；最小访问会不会破坏无关逻辑；下版如何靠语义特征重新找到。

用 `anchor` 记以后还用得上的原文，不把说明书套话写成结论，不把 RVA 当未来真。

## 步骤 3 · 开发访问候选

生成/应用核心补丁等危险动作先给用户看影响和回退、取得本次确认。候选必须：

- 从 upstream/working 候选产生并记录 parent SHA；
- 只改变当前访问目标需要的最小范围（禁止公共序列化一刀切）；
- 原始输入不动；
- 有明确回退；
- 同一候选真实达到 `mission.success`（入口+写动作）。

登记（路径必须是产品里的工作拷贝，不要对 `TEMP/` 或产品外的 ASCII 工作区 `--set`；解包/工具输出若在那些地方，先拷回来再登记）：

```text
state record --kind anchor --phase 1-access --data-file <锚点JSON>
state record --kind patch --phase 1-access --data-file <补丁JSON>  # 只有方法确实是补丁才记
state candidate --set <访问候选文件> --role access                 # 多文件用 --set-files
state record --kind access --phase 1-access --data-file <访问证据JSON>
```

目标只要求进入核心页时，不提前索取游戏目录。进了页仍不算写动作门已定位。

## 步骤 4 · 用户测试与边界收敛

用户只测试同一 access candidate。失败就留在本阶段。成功后仍在 `1-access` 记下 function-map，和 access 一起才能点「核心可用确认」。**按故事，下一停点是产品边界，不是自有授权。**

发现第二道门时 `state reopen --from 1-access`。未受控功能不再逆向、不重写。

## 时间盒（`../INVARIANTS.md` 止损的具体化）

- 「还在动」（又截一张图、又挂一次空闲工具）≠ 新证据。页面没变、假设没被排除 = 没有新证据。
- 同一假设两次无新证据 / 约 20 分钟无新证据 → 决策卡，不换工具壳继续磨。
- 合法叶子：`mission.success`（两层都有自己触发的证据），或两条**不同层** BLOCKED。DIE 标签、缺技能行、换过工具、到了 20 分钟、叫出 VMP，单独都不是 BLOCKED。

## 完成自检（声称 access ready 前 MUST 过）

- [ ] mission 的 goal/success/route 已锁定？
- [ ] 自己锁过层（笔记，不是交差）？对主人说过白话？假设 1～3 条且带相反预测？
- [ ] 当前实验是判定所在的层（触发拒绝时看见分支，或小范围静态圈定），而不是空闲挂钩/字符串？
- [ ] 入口层和写动作层都有自己触发的证据？
- [ ] 锚点能按命令名/字段名/文案重找，不是只记 RVA？
- [ ] access candidate 不是 upstream 原文件，且有角色、parent SHA、清单哈希和回退？
- [ ] 同一候选真实达到 mission.success（主功能，不是 toast）？
- [ ] 未隔离是否已这一次点头？用户数据缓存是否冒充了这一次成功？
- [ ] 做不到时是否明确 BLOCKED（两条不同层），而不是转游戏目录/UI/打包/先建 skill？

## 别假装

见 `../INVARIANTS.md`。尤其禁止：

- 字符串存在 = 找到授权门；
- 抽前端改了一个 JSON 键 = 整扇门已定位；
- 看见 IP = 该抓包；
- 有壳 = 该脱壳/养沙箱；
- 空闲挂钩/截图像素 = 动态；
- topology 写出来 = 授权语义成立；
- 原始 EXE 登记为 candidate = 产生访问候选；
- 授权页消失 = 核心功能正常；
- 当前路线失败 = 可以擅自改做替代核心；
- 用户回复“继续” = 用户确认了技术结论；
- 把缺口写进 evidence 去 confirm。
