# 保险点（4 里中 2 的打法）

点完不算数。默认两组都要过：**current**（这一步留下的痕迹）和 **next**（下一步已经出现）。

每组：至少 **4 个独立标记**，**命中 ≥ 2 且不少于半数**。4 要 2；5～6 要 3。

current 过、next 不过 = **卡在这一步**，不是下一步做成了。next 过、current 不过 = 串台或乐观 UI，不能收工。

计票抄 [scripts/proof.py](scripts/proof.py)。下面是这套规则会被打穿的地方，合同必须补上。

## 1. 独立，不是同一句话写四遍

四个标记必须是**不同事实、最好不同节点**。下面这种算一个，不是四个：

- 「上传成功」「成功上传」「已成功」「success」（同一句换皮）
- 同一个按钮的 text、innerText、accessible name
- 整页 `innerText` 里碰巧出现四次「成功」

自检：拿掉其中一条，另外三条还在讲**另一件事**。拿掉一条其余全没 = 不独立。

建议四类配齐：可见文案、可点控件、对象属性（名/大小/ID）、进度或计数。

## 2. 否决项（一票否决）

多数通过之前，先扫否决。命中任一否决 = 这步没过，哪怕 4 里已经中了 2。

合同每步都要有否决列，例如：

- 登录墙、验证码、风控
- 「再添加一条」（叠任务）
- 「重新上传」当「上传成功」用
- 骨架屏、占位「加载中」
- 错误 toast 还在

否决用**精确短语**，不要用「成功」这种短词。

## 3. 近义禁词（最容易假阳性）

保险点禁止子串乱配。合同写「必须精确」和「绝不能当成它」：

| 看到| 不准当成|
|---|---|
| 重新上传 / 更换视频| 上传成功|
| 添加视频 / 再添加| 空投放区|
| 操作成功，请重试| 提交成功|
| 登录成功请绑定手机| 已进入工作台|
| 下载中| 文件已在磁盘|
| 暂无权限| 列表为空|

「上传」两个字出现 ≠ 空态，也 ≠ 成功。用完整句 + 控件角色，不要用两字关键词。

## 4. 乐观 UI 与骨架屏

next 标记刚闪出来可能是假的：骨架、占位卡片、本地先改再被服务器打回。

过线还要 **耐久**：多数命中之后，等一段合同里的 settle（默认 1～2 秒，进度类跟冻结时限），**再采一次**，两组仍过、否决仍无，才收工。

至少要有一个**服务器回执型**标记（唯一 ID、持久对象名、磁盘文件头）。四个全是本地瞬间文案 = 废。

## 5. 采点纪律

- 可见 + 可点 + 在当前层。`aria-hidden`、`pointer-events:none`、被粘性头盖住的，不算命中。
- Playwright 点成功 ≠ 页收到。`page.evaluate` / `dispatchEvent` 的点击 `isTrusted=false`，很多站当没点。主路径只用 locator 的真实输入。
- 不要对整页 HTML 做「包含这四个词」。按节点采。
- toast 一闪只进否决或材料拒绝，不进 current/next 持久组。
- 截图相似度不当保险点。

## 6. 计票结果（不要发明第三种成功）

| 结果| 含义|
|---|---|
| `veto`| 否决命中，按桶走|
| `waiting_current`| 下一步还没留下痕迹|
| `waiting_next`| 本步痕迹有了，下一步还没出现|
| `waiting_settle`| 多数过了但不耐久|
| `moving`| 进度指纹还在变|
| `passed`| 两组多数 + 无否决 + 耐久|
| `stalled`| 超时且指纹冻住|

`passed` 才能做合同下一步。其它都不是成功。
