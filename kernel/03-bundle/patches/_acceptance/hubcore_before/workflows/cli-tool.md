# 原创 CLI 工具流程

施工、换技能和交接时，按 `docs/ENGINEERING-CONTINUITY.md` 把原话、有效决定、最终消费者、影响面、真实观察与返回动作接到已有工作包。只展开当前这一项；材料有字不算完成。

## 怎么用这份文档

阶段清单、停点、进度真源都在 `state`，不在这份散文里。对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。**轻量不要走本流程、不要 init。以后要卖不要收成直接写代码。无产品账不要对当前工作区跑 status。方案能推进、产品夹不在中枢里面之后再 init。**

```
python tools/state.py status  --product <产品目录>
python tools/state.py confirm --product <产品目录> --stop-point "<停点名>" --evidence "这一步验证了什么（具体可复核）"
python tools/state.py record  --product <产品目录> --kind spec|arch|module|build|follow|cover|replay-order --data '<json>'
python tools/state.py candidate --product <产品目录> --set <当前构建产物> [--bless]
```

> Windows / PowerShell 传内嵌引号的 JSON 容易被吞——复杂 JSON 用 `--data-file <文件>`（BOM 也能读）。

阶段是数据，见 `templates/cli-tool.phases.json`（已知产品线的默认阶段 id、顺序和物理检查不可删、改名或重排；可增加步骤并按业务适配实现）。每个停点都有 `requires`：没记对应制品，`confirm` 过不了。不要套二开停点；能交给别人用必须有 `build`。

**不算（防换皮，未用真产品打穿）：** `--help` / `-V` / 退出码 0 ≠ 核心命令对真实输入做成；只交一个本机包 ≠ 声称的每个平台都能装。架构确认不得一口吞掉未测平台。机器：架构须写动作+分发才能点绿；这格不能 SKIP 点绿；工程问题先查现有实现与可行方案；确实缺业务取舍时，给推荐和理由再问主人。缺证据不能 confirm，不要把 SKIP/未决写进 arch。实现格写动作未证不能点绿。空成功只拦表里金句、按停点中文名；未入表的格不拦。未用真产品打穿，不算五类都能管。

spec 须 `acceptance`；arch 须 `decision`；实现/干净安装/更新/交付的 test 须 `evidence_level=product|human`。退出码 0 不算。构建候选须 `--bless`。边做边留下以后还能用的记录（`record --kind anchor`）；还在做不拦，要点「做成了、进下一阶段」时账本里必须已有这些记录。

## 开场先讨论，后面和二开同一套卖路（只换前面，仍抱本书，不要换成 exe-rebuild）

用户只说了一句简单需求：禁止立刻写代码。先用人话把方案补全：这个项目怎么做、要哪些功能、什么组件、怎么衔接、失败怎么办、数据放哪、缺什么、以后怎么卖。常见坑你挡住，不要主人当产品经理补洞。方案没补到「可以一步步推进」之前不算开工，也不要把「进度更新」当成开写许可。卖路径别丢；该换书仍要换，不要把「只加载本 skill」读成整场不换书。命令行的「改界面」= 提示文案、帮助信息、命令体验，不是画窗口。

改功能时：先读已经记下的 spec / arch / module；改 A 之后复验 B 还在、加过的命令/选项没被拿掉。靠项目账，不靠聊天记忆。

主流程能用之后走**后半段**。不要直接跳到分发包。先改命令体验，再**问**主人接不接自己的授权。可以不接——把「这场不接」写进 spec/arch，走改体验 + 打包；不要为过关硬接。若接，把「接自己的授权」写进 spec/arch。spec/arch 里没有这两句之一，就不要开始打分发包。开场或架构格里的「不接」不能当已问。不要用 confirm 的 SKIP 去点绿「需求合同确认」或「分发包与跨平台确认」；这场不接不是 SKIP。「不要抄二开」不是砍掉这一问；命令行没有窗口也要问，不是去做启动器授权页。若接：这一条线默认没有图形窗口，不要为过关造授权页、造窗、造启动器。三种基础真跑（卡密对才放行主命令；不对或一进来就过期则不放行；用到一半到期则停主命令。作废/断网按这场要不要测，不是每场必测）。还要第四种：卡仍有效，但这台 `DEVICE_NOT_BOUND` / 被挤掉 / 已解绑时必须停主命令。开着还要周期性 verify，只 activate 不算；一句「激活/验证/解绑都要」不够。两套钟不准改混：到期靠 expires_at 本地关，不要改成到期也必须再问才关。挤机必须再 verify，下一次验证内停。expiry 是卡还剩多久，禁止把验证间隔/cache_until/next_verify_at/20 秒/60 秒交给核心或标题栏。测试/验收间隔默认 60 秒，不要 20 秒硬刷。只有一台时超过验证间隔还在，没人挤不会自己关。RATE_LIMITED 不是停机。宽限不是多台同时登录。购买/联系/更新仍是同一套接口：购买网址和联系字跟这张卡的下游，原文原样；更新带版本号问平台，有新版才提示，点了打开网盘；设备码 `缩写-XXXX-XXXX-XXXX-XXXX`；激活后还要周期性验证、解绑后停；测试只用 `ceshi1`、新发卡；已售卡锁快照；不要另写一套协议。人能跑通主命令那天锁清单+总图+改动图当**原创基线**，一版一个 `work/vX`，发出去冻进 `freeze/vX`。→ 先在测试环境测通，再连正式自己的平台（先测再连正式；共享平台先孪生）。接了授权后对人测两段：先只有一台、等过验证间隔还开着（没人挤不会自己关）；再第二台挤第一台，第一台下一次验证内停（被挤掉会停）。再打包。过关不要靠后来加窗。真做成有窗口产品，是另一次形态变更，再按桌面有窗测，不要为这一场过门去造窗。命令行登录/API 钥和收费授权是两件事，对人分两句问。开场一次只问一件能看见的事，不要一次丢三件。

不要抄的是逆向、把没源码的核心当载荷再套一层、挡对方授权页、产品怎么分三选一、把二开 `record --kind license` 抄过来交差。**要抄的是后半段整段和授权 A 全表。** 开场不要拷功能表、不要建档案夹给主人签字。已有表则开工先 `python tools/map_show.py --product <产品>`（不要 `--id`），改哪再 `--id`。禁止整仓重读。可以不接授权。不要为过关造窗。三种基础落在主命令。先测再连正式。

**还没答完不准开工。** 部长自己答，不准印给主人当考卷，不准每格把十四问全问一遍。不要抄二开「原件接/关/替」。不要为过关造窗。

- 主命令人看见什么？
- 失败时人看见什么？
- 数据放哪？坏了怎么回去？
- 清单从哪天写？

## 四条贯穿所有阶段的纪律

1. **退出码 0 ≠ 业务成功。** 命令跑完不报错、返回 0，只是信号；验收要看**真实输入产生的真实输出/副作用**是否正确。别拿"没崩"冒充"做对了"。（§16.2）
2. **本机能跑 ≠ 目标平台能装能跑。** 你在开发机上 `python main.py` 能跑，不代表用户 `pip install` / 下载单文件二进制后能跑。**声称支持的每个平台都要有对应制品**；无开发环境真装真跑主命令在第 5 格。PATH、权限、依赖、行尾、路径分隔符都是常见坑。
3. **同源制品链 + 候选登记 + 一版一目录。** 代码 → 测试 → 构建产物（二进制/wheel/npm 包）→ 安装后可执行，分别登记源码、构建产物和包的身份与转换关系；包内与安装后的同一主程序比较哈希，不要求源码和安装包哈希相同。当前分发候选用 `state candidate --set` 登记，里程碑 `--bless` 记回退点。这一版只在 `work/vX` 里改，下一版新开目录。功能定档认 git（一块测好了提醒提交，再开下一功能）；`--bless` 不能当功能相册。解包/日志/草稿只进产品根 `TEMP/`；`work/vX` 和冻本不进 `TEMP/`。
4. **需求先补全再动手；新需求先记再做。** 阶段 0 就把错误处理、空/边界输入、大输入性能、跨平台、配置与数据位置、更新售后逼出来；接不接自己的收费授权等到核心能用、改完命令体验之后当面问，不要提前到需求格。中途新需求先 `state record --kind spec` 再做。

## 阶段 0 · 需求与验收　→ 停点「需求合同确认」
- **用户该看到**：谁来用、核心命令与主流程、输入输出与退出码、可观察成功标准。还要看见后面怎么卖（命令体验 → 问接不接自己的授权 → 打包），**本格不要当面逼答卡密**。
- **做**：先讨论再记。逐项过一遍——错误处理、空输入/边界输入、大输入性能、跨平台(Win/Linux/mac)、配置与数据位置、更新与售后。命令行登录/API 钥 ≠ 自己的收费授权。**接不接自己的收费授权等到核心能用、改完命令体验之后当面问**，不要提前到本格，没问不能当成已经问过，也不能拦本格 confirm。`state record --kind spec` 记需求合同。
- **别假装**：列了几个命令 ≠ 需求确认。一句话直接写脚本 = 没做到零基础那条。

## 阶段 1 · 架构与地基　→ 停点「架构确认」
- **做**：定命令结构与参数解析、配置/数据存放、分发形态（单文件二进制/pip/npm）；建 Git 基线。关键决定 `record --kind arch`、模块 `record --kind module`。
- **别假装**：目录建好 ≠ 能跑。

## 阶段 2 · 分阶段实现　→ 停点「核心命令实现确认」
- **做**：动手前先读 manifest 的 arch/module；小步实现命令 + 相关测试；核心主命令端到端真跑（真实输入→真实输出/退出码）；每个可跑构建 `candidate --set` 登记。新需求先 `record --kind spec`。**每改完一刀，复验旧命令还在、加过的选项没被拿掉。** 记过的模块名必须写进本格 test，机器才认复验过。一块功能主人测好了就提醒定档（git 提交），再开下一功能。核心能用之后先改命令体验并当面问接不接自己的授权，不要提前到需求格，不要直接进构建/分发包格。人能跑通主命令那天，部长自己写下功能名和**作用是什么**，并锁**原创基线**（清单 + 总图 + 改动图 + 这一版 `work/vX`）。空表不得说完善。旧场表空：先从 Git、源码、交接、原话和实际候选恢复，标清仅源码推定与仍待运行的部分；只问无法恢复的业务决定。不要先建档案夹。
- **别假装**：单测绿 ≠ 主命令对真实输入做对了。改了新命令、旧选项没了 = 没挡住通病。模块表在、测试没点名 = 没读表。

## 阶段 3 · 构建候选　→ 停点「构建候选确认」（requires: candidate，且必须 --bless）
- **没答句就停：** 核心能用、改完命令体验之后当面问的答句须已写入 spec/arch。开场或架构格不算已问。没有就不要点「构建候选确认」，不要 `record --kind build` 打 zip，不要 `gh release`。
- **若接了就停：** 答句是「接自己的授权」时，本格不要打 zip，除非已按形态看见三种基础，并且按顺序看见：先没人挤不会自己关，再被挤掉也停；购买/联系/更新也看见了。不接仍可打。
- **没看见就停：** 本格测试结果「做成了什么」里要写清：主人已经看过换成这个产品的命令体验（写看见了什么、主命令还在不在）。只写计划或看起来不算。记录实际看到的对象、行为和对应版本；标点或换一种说法不能制造观察证据。不要只写证据栏。不要把短句当完成口令抄进测试结果。没有看见就不能点「构建候选确认」。
- **做**：构建与源码同源的分发产物（二进制/wheel/npm 包），落哈希，`candidate --set <候选> --bless` 记为 last-good。
- **别假装**：能 build ≠ 能安装；status 催你改命令体验再问 ≠ 你可以先点构建。

## 阶段 4 · 打包与跨平台　→ 停点「分发包与跨平台确认」（requires: build）
- **没答句就停：** spec/arch 里须有主人当面写下的「接自己的授权」或「这场不接」。没有就不要打分发包，不要 confirm「分发包与跨平台确认」。开场或架构格里的「不接」不能当已问。若接：不要为过关造授权页、造窗。三种基础加第四种真跑（对才放行主命令；错不放行；用到一半到期停主命令；被挤掉/`DEVICE_NOT_BOUND` 也停。过关不要靠后来加窗。作废/断网按这场要不要测，不是每场必测）。购买/联系/更新仍一次做全（跟下游原文；更新带版本号问平台，有新版才打开网盘）。confirm 证据须含这三种基础（含用到一半）、被挤掉会停、没人挤不会自己关、开着还在周期性验证，以及购买/联系/更新，三种基础不能单独点绿。一句「激活/验证/解绑都要」不算第四种。还须一段未连正式的孪生/测试分身/先测，另记已连正式；一句「先测再连正式」不算。这场不接不套三种基础。本格须已有原创基线（清单+总图+改动图+`work/vX`）。
- **做**：打出声称支持的每个平台的分发包，产物在该 OS 上对得上；核对 PATH/权限/依赖配方。真装真跑主命令留到第 5 格。`record --kind build` 只记磁盘上的分发包（`artifact` + 当前候选哈希），不要把脚本或配方文件当成包。最新 spec/arch 写了跨平台 / Linux / macOS / Darwin 时，磁盘上须有不止一份包文件，一份本机包机器拒。其它平台未真装未真跑，对人说未验证，不要写进 `--evidence` 当全平台做成。
- **别假装**：一个平台过了 ≠ 全平台过；一份本机包 ≠ 声称的每个平台都有制品。

## 阶段 5 · 干净安装与首次运行　→ 停点「干净环境首次运行确认」
- **做**：在无开发环境的干净机器上安装并成功跑通主命令。对着刚打的那份包哈希，不要换一份没打包的候选再点这一格。本格只验一台干净机；其它声称平台未装未跑，对人说未验证。
- **别假装**：本机好好的 ≠ 别人装得上（真实教训：缺运行时/缺依赖/PATH 没进）；一台干净机 ≠ 所有声称平台都装过。

## 阶段 6 · 更新与回滚　→ 停点「更新回滚演练确认」（requires: build + 本阶段新 test + follow + cover）
- **没答句就停：** 和分发包同一条。打包格写了「这场不接」，本格改口「接自己的授权」仍要两段，不能只改口过门。
- **做**：真跑 v1→v2 升级、配置/数据保留、回滚到上一版本后同一主命令对同一真实输入复验。必须是已装旧命令升包，不是开发机再装一次。接了社区授权平台时：带版本号问平台，有新版才提示，点了打开网盘，就是客户路径。半成品不准放到客户会下到的地址。定档冻本对照上一份原创基线的位置。先 `state record --kind follow` 写下三句：我们改过哪些、这一版新改了什么、哪些还能认哪些是新门。另 `state record --kind cover` 记下客户路径（已装旧命令升包，覆盖做成）；本项 SKIP、吃新上游不能顶。不许照抄清单。没有这三句和客户路径不能点更新回滚确认。`replay-order` 不是更新正路，禁止拿旧脚本或重放顺序交差。
- **别假装**：能装新版 ≠ 能退回旧版；退出码 0 / `--help` ≠ 回滚后同一主命令对同一真实输入做出同一结果。开发机再装一次 ≠ 客户已装那份命令升了。

## 阶段 7 · 交付与验收　→ 停点「交付验收确认」（requires: build + 本阶段新 test）
- **没答句就停：** 和分发包同一条。前面写了「这场不接」，本格改口「接自己的授权」仍要两段。授权测试与更新演练分别留实际观察；测试环境验证、正式接线是两段不同事实，未执行就保留未完成，不能靠措辞过门。
- **做**：把分发包/使用说明/回滚预案真正交到用户手上；用户在真实机器跑通一次主命令并明确点头验收。当前候选必须仍是更新格那份 v2 包哈希，不能退回 v1 或另换没更新过的字节去交货。`record --kind build` 记最终交付物哈希。
- **别假装**：前面全确认 ≠ 已交付验收。

## 交付出口

最终结论同时列：已验证、未验证、残余风险，以及"从哪看起 / 怎么验 / 怎么回退 / 唯一下一步"，让第三方能独立接手。
高风险交差前换加载 `review`（一次一本）：按四审帽子走完（程序→产品→测试→发布），写的人不能给自己过，也不能自己宣布完成。`state` 全绿不是完成。
交付后再改同一产品：用 `state reopen` 从受影响阶段重开，清单还是这份 `.hub`，不要 `init` 当新项目，也不要走整条线只改错别字。更新演练在合同第 6 格，不是再开一份合同。
## 硬门：命令行必须真实执行主命令

- **探针先行与防丢清单**：涉及子命令、参数解析、授权控制与退出码改动前，先在 `.hub/physical-gates.json` 配置机器断言并在会话中列出防丢清单。严禁以局部单测通过向主人宣称搞定；单测必须在临时沙箱目录运行，严禁直接读写或污染用户真实的环境变量与生产配置。
- 命令行实现、打包、干净安装、更新回滚和交付阶段必须用当前候选运行 `state probe`。`command_flow` 要执行真实主命令、输入错误/边界输入和成功路径并检查可观察输出及副作用；打印帮助、进程退出 0、单元测试绿或模型文字不能代替。

`package_install` 必须安装真实分发包；`clean_install` 必须在干净环境执行主命令；`update_rollback` 必须实际升级、失败回退并复跑主命令；`handoff` 必须由另一个执行者按资料安装和运行。若命令行接自己的授权，三种基础加第四种必须是对才放行主命令、错不放行、到期本地关、被挤掉则下一次验证内停主命令，不要为了过门造窗口或启动器。打包及之后的格还要 `license_dataflow` 机器观察卡还剩多久（不是 20 秒/60 秒间隔，也不是 next_verify_at）、用到一半真卡过期停、被挤掉停、只有一台超过验证间隔还在、RATE_LIMITED 不是停、周期性 verify；须在 `.hub/physical-gates.json` 里配置。这场不接不套。

物理收据缺失、绑定旧候选或旧探针配置时，confirm/build/gate 一律停。没有主人真实验收和物理门，不调用打包器、上传器或发布命令；账外包不得称为正式候选。
