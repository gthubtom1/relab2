# 安全检查方法

**先看谁在加载：** 二开（exe-rebuild）没有「这场不接」，不能「不接仍打包」，须走授权页启动器。可以不接、不接仍打包，只留给网站/桌面/命令行/接手。接手还在「安全网与改造计划」、改前审计、或还没改完界面/命令体验：只查密钥、权限、泄漏，不要当面催接不接卡密，不要把「这场不接」写进这一格。收费授权那一行只在改完界面或命令体验之后。

## 秘密不落盘到不该去的地方

- 密钥 / token / 密码 / 私钥 / 完整许可证 不进 Git、日志、报告、安装包、hub 核心。pre-commit 会扫一道，但别依赖它兜底。
- 发现秘密：隔离、移出、说明恢复；输出里不要再重复它。

## 最小权限

- 只要必需的权限；能不联网就不联网；对外影响（发消息 / 上传 / 写系统）逐次确认。

## 授权别只看接口 200

- 接口 200 / 配了登录页 ≠ 鉴权生效。无效、过期、越权要真跑，看它真的拦住。收费授权另走三种基础，不要用登录页顶替。
- **仅 exe-rebuild：** 主人定过产品边界 → 界面回归 → 先把通用授权页改成这个产品的样子（主人看过）→ 才做自有授权检查。核心一点头不是授权停点。真跑路径必须是主人的授权页（启动器）。脚本/elev 直开核心不能当闭环。三端闭环：平台状态 ↔ 客户端 ↔ 产品门。三种基础：有效才开核心；无效或一进来就过期不开核心；用到一半过期则关核心且授权页一起退。藏页/关页是附加，不能顶第一种。作废/断网按这场要不要测，不是每场必测。检查授权 ≠ 进入程序。客户包不要依赖本机 PATH 里的 Python。开发探针不得留在出货候选；`direct_launch` 必须证明不是 launcher-only。license 记录必须含 `updater_treatment`（移除/禁用/重定向上游更新）。接到共享授权平台：先测试孪生+对照产品，禁止在已有其他软件的正式机上试第一刀。互攻不是停点，评比不能选一刀切、不能当闭环证据。
- 被网站/桌面/CLI/接管加载时，不要把上一款二开手续套过去。登录鉴权仍要验。接手还没改完界面或命令体验、还在安全网/改前审计时：只查密钥、权限、泄漏；不要问接不接卡密，不要写「这场不接」。问接不接、不接仍打包、把答句写进 spec/arch，都不在这一格办。
- **改完界面或命令体验之后才问：** 问接不接自己的收费授权：可以不接，不接仍打包。问完关掉本书，换回产品线；若接了按形态看见三种基础再打包，不要问完就打包。不要从本书打安装包、不要 `gh release`。若接：按产品形态，不要一律先改通用授权页。桌面有窗（含桌面接手）：先把通用授权页改成这个产品的样子（主人看过）→ 三种基础真跑（对才开；错不开；到期关程序和授权页）。藏页/关页是附加，不能顶第一种。命令行/无窗口（含无窗接手）：不要为过关造页、造窗、造启动器；三种基础是对才放行主命令、错不放行、到期停主命令。网站/有页面的服务（含网站接手）：站点自己的收费门（对才提供服务，错不提供，到期停服务；不要关软件、不要藏授权页）。有页面的服务只走网站这条，不要进「有窗口接手」。作废/断网按这场要不要测，不是每场必测 → 先测再连正式。仍不要抄启动器包没源码核心。本场不接 = 写进 spec/arch，不是用 SKIP 点绿「需求合同确认」或安装包/上线格。安全网/改前审计这一格不能代写「这场不接」。

## 别误伤合法逆向

- 本地逆向 / 调试 / 抓包 / 分析自有样本是正常工作，安全检查不该拦它。

## 别假装

- 配置了安全机制 ≠ 生效。登录鉴权仍要真跑拦住。二开：始终走授权页启动器，没有「这场不接」，不能「不接仍打包」。网站/桌面/命令行/接手：收费三种基础只在这场接了自己的授权时才要——桌面有窗（含桌面接手）：对才开；错不开；到期关掉程序和授权页。藏页/关页是附加，不能顶第一种。命令行/无窗口（含无窗接手）：对才放行主命令，错不放行，到期停主命令，不要为过关造页、造窗、造启动器。网站/有页面的服务（含网站接手）：对才提供服务，错不提供，到期停服务访问，不要关软件、不要藏授权页。有页面的服务只走网站这条，不要进「有窗口接手」。仅网站/桌面/命令行/接手本场不接：不要为过关硬接、不要三种基础、不接仍打包。本场不接须改完界面或命令体验之后当面问再写，不是安全网/改前审计这一格能代写的。作废/断网按这场要不要测，不是每场必测。
