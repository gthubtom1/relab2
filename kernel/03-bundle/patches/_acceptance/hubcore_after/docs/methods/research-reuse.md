# 调研与复用方法（DEC-05）

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。调研只是中途一刀。调研完成把采用决定、版本前提和下一实验交回 WORK-HANDOFF 中的直接调用方；例如接SDK中发起调研，就先回SDK完成接线，再回产品实现。见 `docs/ENGINEERING-CONTINUITY.md`，主线授权与交付要求仍有效。

## 动手前先花几分钟查

- 官方文档 / 发布说明：这技术现在怎么用、有没有坑、版本差异。
- 同类产品 / 开源实现：别人怎么解的，有没有能直接复用的。
- 用户 / 社区反馈：已知的雷。

## 产出要能改变下一步动作

- 调研不是走过场：得出"采用 X / 避开 Y，因为……"，并落到"第一步怎么做"。

## 边界

- 无网络：用本地证据，明确标"外部调研未完成"，别编来源。
- 别把"没查到"推断成"没有依赖 / 没有坑"。

## 别假装

- 收藏一堆链接 ≠ 调研；没有"所以下一步这么做"的结论，就是没查。
