# 发布就绪检查

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。

做到一半说「可以发布了」仍接当前产品线。界面或命令体验没改完、还没问授权，不要换到本书当场催答句。后半段走完才做发布清单。装/升/退清单过了不是发 Release；做本清单时不要自动对外发布。真要发、主人点名了才换。

## 过关清单（每条要真验，不是打勾）

- 桌面/命令行/二开：干净环境 clean install + 首次启动（命令行是主命令）通过。网站不要按这句交差：要预发冒烟 + 上线回滚后同一主流程复验，不要拿本机容器/打开页顶替。接手按产品形态走上面桌面、命令行或网站那一条，不要只核授权答句，也不要把有页面的网站收成「有窗口」去走首次启动。
- 桌面/命令行/二开：v1→v2 升级 + 数据迁移 + 失败回滚 + 回滚后再启动 都真跑过。网站走合同里的数据迁移格和上线回滚格，不要按桌面「再启动」交差。接手同样按形态走装/升/退，不要只核授权答句。
- 正式包 = 已验证候选（同一哈希）；无"验 A 发 B"。空功能表不得称为正式分发包。没有定档冻本对照（二开对原件；原创对上一版人看见的）、半成品、试包 → 不准放到客户会下到的地址，不得当更新源，不得让旧客户去点。第一包未定档可以是未验证测试输入，但不得挂到那个地址。网站/桌面/命令行/接手同样要管，不要说「只属于二开所以不管」。不要考主人认冻本文件夹。不要抄二开那种核心载荷加启动器，不要抄 record --kind license。接了授权的桌面仍要授权页。冻本与包哈希要对上才能当更新源。
- 客户路径更新做成才算「能升」：已经在用的那一份走到新的（桌面/二开：已装软件里点更新；命令行：已装旧命令升包；网站：生产租户还在用的那份，不是本机容器）。开发机再装一次不算。吃新上游要能用人话写出：我们改过哪些、上游新改了什么、哪些还能搬。写不出不准当更新源。
- 无秘密进包 / 进 Git。先看是哪条产品线，不要把下面两句抄串。
- 二开（exe-rebuild）：没有「这场不接」过门。须已过授权页启动器确认。不要把有源码线的「可以不接」抄过来。二开的三端闭环不要套到网站/桌面/命令行/接手。
- 桌面/网站/命令行/接手：须有当面写下的「接自己的授权」或「这场不接」（开场或架构格不算；接手测绘格、接手安全网格也不算）。不要把早格「这场不接」抄进发布格。不接仍可发布。若接：按产品形态，不要一律改通用授权页，也不要用「有没有窗口」把网站收成桌面。桌面有窗（含桌面接手）：先把通用授权页改成这个产品的样子（主人看过）→ 三种基础加第四种真跑（对才开；错不开；到期关程序和授权页；被挤掉/`DEVICE_NOT_BOUND` 也停）。藏页/关页是附加，不能顶第一种。命令行/无窗口（含无窗接手）：不要为过关造页、造窗、造启动器；三种基础加第四种是对才放行主命令、错不放行、到期本地关、被挤掉则下一次验证内停主命令。网站/有页面的服务（含网站接手）：站点自己的收费门（对才提供服务，错不提供，到期本地关、被挤掉则下一次验证内停服务；不要关软件、不要藏授权页）。开着还要周期性 verify，只 activate 不算。两套钟不准改混：到期靠 expires_at 本地关，不要改成到期也必须再问才关。挤机必须再 verify，下一次验证内停。expiry 是卡还剩多久，禁止把验证间隔/cache_until/next_verify_at/20 秒/60 秒交给核心或标题栏。测试/验收间隔默认 60 秒，不要 20 秒硬刷。只有一台时超过验证间隔还在，没人挤不会自己关。RATE_LIMITED 不是停机。宽限不是多台同时登录。有页面的服务只走网站这条，不要进「有窗口接手」。作废/断网按这场要不要测，不是每场必测。先测再正式。没问过不能跳过。主人说「可以发布」也不够。
- 交接资料齐：从哪看起、怎么验、怎么回退、唯一下一步。
- 高风险：已换加载 `review`，走过四审帽子（程序→产品→测试→发布）→总结→批评手；写的人不能给自己过，也不能自己宣布完成。审查不要开子代理。本书是发布审的方法清单，不是第二本主审查。

## 别假装

- 打好包 ≠ 就绪；上面任一条没真跑过，就标未就绪，别发。过关清单过了、写就绪了，都还不是发 Release；做本清单时不要自动对外发布。真要发、主人点名了才换。
- 测试绿 / 自评 PASS ≠ 真人验收。高风险发前按 `review` skill 走一档出口审查（四审帽子→总结→批评手）；`state` 全绿不是完成。装/升/退清单过了不是已经发了。审查不要开子代理。
## 硬门复核：发布清单必须重新对照机器收据

发布前不要只看清单、截图或“测试全部通过”。重新查看 `state status`，确认已确认阶段的物理收据仍绑定当前候选、合同指纹、物理阶段 epoch、探针配置哈希和命令哈希；改过探针配置或候选后，旧 PASS 自动失效。

逐线复核真实链路：桌面/二开/命令行跑干净安装与首次主流程，网站跑预发和上线回滚，接手项目按其真实形态跑安全网/回归/装升退。二开必须确认核心裸双击打不开、动态授权数据进入核心、启动器网络不阻塞 UI、错误在原生横幅显示。没有真人验收、没有物理收据或只通过 `state gate`，仍是未就绪。`state gate` 拦账本，拦不住终端乱打。客户会下到的地址上若挂着半成品、空功能表或没有定档冻本对照，发布清单不得写成就绪。未见主人看见主界面 / 主命令 / 真页面，不得调用打包器。

本书不负责发 Release；发版、上传、打 tag 仍是单独危险动作，需要主人本次确认和独立交叉审查。
