# 第三方集成方法

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。接 SDK 只是中途一刀。做完按 WORK-HANDOFF 的方法调用链，回到直接调用方尚未做完的动作；主线的授权、打包与交付要求继续有效（见 `docs/ENGINEERING-CONTINUITY.md` 的当前工作包）。

主人没点名第三方时，先按现有技术栈、功能、费用、地区、许可和数据归属调查并给出推荐；只把影响成本、账号、数据去向或业务方式的取舍问主人。可逆的本地试接按授权范围继续；不能擅自开户、付费或连接生产。Python 自带的 `json` 之类标准库不能顶「接过某某 SDK」。没凭据先做接口分析和本地可行工作，报缺不是接完。商户钥 / 支付钥 / API 钥 ≠ 自己的收费卡密；接了第三方不等于已经问过接不接自己的授权。

## 先证明能通，再深用

- 用最小调用跑通一次真实往返（真实凭据、真实返回），再往产品里接。
- 读官方文档的版本 / 限流 / 错误码；别照抄过时示例。（配合 `research-reuse`）
- 在已有工作包写清生产者→接口→最终消费者，核对本次字段、单位、时间基准、空值和版本。最小调用通后，要从产品入口触发并观察最终使用结果；缓存、重启与异步完成按实际场景验证。

## 边界与失败

- 处理失败 / 超时 / 断网 / 凭据过期——第三方一定会挂，想好降级。
- 凭据走安全存放，不进 Git / 日志。（配合 `security-audit`）
- 对会写入、扣费或发起任务的调用，验证重试幂等、取消及失败后的副作用；配置环境、错误反馈与恢复动作交回直接调用方，不能只交一段示例响应。

## 别假装

- 示例能跑 ≠ 你的场景能跑；沙箱通 ≠ 生产通（限流 / 权限不同）。
- SDK 装上 ≠ 真调通：要看真实返回。
