# 集成 / 交接方法

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。两个仓库各自测试绿 ≠ 已经接上。接缝要真跑一遍主流程。接完把双方版本、实际数据消费者、接缝观察与失效范围交回 WORK-HANDOFF 的直接调用方，继续它的未完动作；主线尚未完成的授权与交付保留。见 `docs/ENGINEERING-CONTINUITY.md`。

## 接缝处最容易断

- 明确每个部分的输入 / 输出 / 所有权边界；接缝上做真实端到端验证，不是各自单测绿就算。
- 版本对齐：各组件版本 / 哈希要能对上，别 A 版配 B 版。

## 仅 exe-rebuild：三端就是一次集成

- 核心 ↔ 启动器/授权页 ↔ 平台，是二开的典型集成——按功能—授权地图接线，端到端真跑。（见 `exe-rebuild` 自有授权闭环）
- 被网站 / 桌面 / 命令行 / 接手加载时，不要把这三端抄过去当典型。

## 交接

- 留"怎么跑、怎么验、怎么回退、谁负责什么"，让第三方能独立接手。

## 别假装

- 各部分都绿 ≠ 拼起来通；接缝没真跑就是没集成。不要口头说「两边都绿就算接上了」。
