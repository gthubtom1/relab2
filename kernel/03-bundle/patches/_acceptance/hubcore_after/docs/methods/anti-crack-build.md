# 加壳 / 编译加固（防破解逆向）

对主人先白话：你要保护哪个程序？我找到哪些壳/混淆器？加完还能跑吗？坏了怎么退回去？

## 一、先找工具（不要问主人路径，也不要写死路径）

1. 读本机工具表 `<product>/hub/tools.local.json` 的 `tools` 数组：里面有 name / path / launch / notes。
   按类别找：**加壳器**（VMProtect、Themida、Enigma、ASProtect…）、**混淆器**（ConfuserEx、.NET Reactor、
   Dotfuscator、Obfuscar、OLLVM、Tigress…）、**压缩壳**（UPX、MPRESS、ASPack…）、
   **打包器**（PyInstaller、Nuitka、Inno Setup、NSIS、WiX…）、**混淆/编译器**（MSVC、clang、mingw、Go、Rust…）、
   **签名**（signtool、osslsigncode）。
2. 表里没有？用 `everything_cli`（表里有绝对路径，通常是 `<install_root>\es\es.exe`）搜盘：
   `es.exe -i 关键字`，先按已知 exe 名找（`upx.exe`、`confuserex.exe`、`VMProtect.exe`、`signtool.exe`…）。
3. 还是没有 → 告诉主人「这台机器上没有 X，要装就装这些：…（写清从哪拿）」，**不要静默下载/安装**。
4. 找到的路径要 `Test-Path` 确认真存在，新工具写回 `tools.local.json`（只写绝对路径 + 一句话用途），
   下次就不用再搜。重工具（加壳器 GUI/大编译器）命令行调用必须带超时，输出落盘。

## 二、流程（一步一个窗口，别一次做完十件事）

1. **定目标**：要防的是「随便被人反编译看逻辑」还是「被人改一版盗用」还是「过杀软/CDN 分发」。
   目标不同，选的工具完全不同（例如只要减体积 → UPX 就够；防 .NET 反编译 → 必须混淆器，UPX 没用）。
2. **出方案给主人看**：选哪套、为什么、**代价是什么**（体积涨多少、启动慢多少、杀软误报概率、
   以后自己还能不能调试）、坏了怎么退。主人点头再动手。
3. **留原件**：先把未加壳的成品**复制一份**到安全位置（`..._unprotected/`），并在交付记录里写明。
   没有原件备份就不许加壳。
4. **加**：
   - 编译档：release + 优化 + 去掉调试符号（`/O2`、`-O2 -s`、`--release`），这一步最便宜也最有效；
   - 混淆/加壳：按工具的命令行或 GUI（GUI 类工具让主人自己点，你只给参数建议和清单）；
   - 签名（可选）：`signtool sign /fd sha256 …` 或 `osslsigncode`；自签证书要告诉主人「自签会被 SmartScreen 拦」。
5. **实测（不许跳）**：加完**必须**跑一遍 —— 主流程能开、关键功能能用、之前验过的探针/回归重跑一遍。
   只凭「加壳成功」不算做过。起不来的常见原因：壳与杀软冲突、缺运行库、被保护的段里有自校验。
6. **记录与退回**：写清用了哪套工具什么参数、体积变化、误报情况、原件在哪。要退回就用原件覆盖回去，
   并把「已加固」的标记去掉，不许两份混着发。

   再用工具**自测一遍**（工具都在 `tools.local.json` 里）：DIE 查壳看壳有没有真加上；
   .NET 用 de4dot 试着脱（秒脱说明保护不够）；动态用 x64dbg 看反调试是否生效。
## 三、硬规矩

- **自己的程序才加壳**。别人的软件、别人的 EXE 不做加固后分发（那是盗版/侵权，直接拒绝）。
- **不许把壳当安全证明**：壳只抬高成本，挡不住有耐心的人；真正的授权/计费必须走服务端校验。
  跟主人说实话：能拦掉 90% 顺手的人，拦不住专门研究你的人。
- **不许静默安装**工具、不许静默下载；需要主人点 GUI 的步骤就让他点（给清晰步骤，别抢鼠标）。
- 反调试/反虚拟机/反沙箱这类**会误伤正常用户**的手段，必须先跟主人讲清楚副作用，他点头才用。
- 加壳失败要能一眼看出：报错原文落盘，别只说「失败了」。
- 常见脱壳/绕过手段要如实说（例：UPX 有 `upx -d`；.NET 有 de4dot；原生壳有 dump+修复 IAT），
  主人知道上限才不会被忽悠。

## 四、不同成品配什么（速查）

| 成品类型| 首选| 次选| 不要用|
| ---| ---| ---| ---|
| C/C++/Rust 原生 EXE| 编译优化 + 原生壳（VMProtect/Themida 类）| OLLVM 插桩编译| 只上 UPX（只减体积，几乎无保护）|
| .NET EXE| 混淆器（ConfuserEx/.NET Reactor）| 原生壳包外层| UPX|
| Python 成品| PyInstaller/Nuitka 打包 + 商业壳| Nuitka 编译成 C| 只 PyInstaller（源码可解包）|
| Go/Rust CLI| 编译加 `-s -w` / strip + 原生壳| 字符串混淆| —|
| 带授权页的桌面产品| 服务端校验 + 壳做外层| 壳 + 混淆| 只靠壳|

## 五、跟产品线怎么接

- 桌面/命令行/二开产品线：**主功能验收之后、正式发布之前**进这本书；做完回到原产品线继续
  （不要在这里宣布「可以发布了」，发布就绪检查在 `release-readiness`）。
- 加固完必须重跑该产品线的机器门/探针；**加固不能改变「能装、能升、能回滚」三条**。
- 交付给客户的那种（有安装包、有更新器），加固要跟安装包/更新器一起验一遍：升级后还能跑才算完。
