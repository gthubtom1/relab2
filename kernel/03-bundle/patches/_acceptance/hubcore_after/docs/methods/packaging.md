# 打包 / 分发方法

对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。

网站/桌面/命令行/接手：打完安装包/分发包就关掉本书，按工作包返回直接调用方的未完动作。首次分发回产品线继续干净安装、主命令或预发冒烟；更新或修复期间重打包则回当次更新或修复，不倒退到首次安装阶段。二开停在给别人的包：不要关书，仍在本书做干净安装和第一次打开。

术语真源：`docs/VOCABULARY.md`。这里的「分发 / package」= 精确候选的安装包或便携包，不是 ZIP 骨架，也不是仅启动器。覆盖更新 / 迁移 / 回滚是另一步，不能写进第一包就算故事完成。

当前产品**只有**合同类型是 exe-rebuild 时，才跳过下一段原创说明，去「仅 exe-rebuild」和「无源码二开」。接手不是 exe-rebuild：必须先读下一段，不要往下翻启动器。不要把原创段的「不接仍打包」套到二开。

**原创桌面 / 网站 / 命令行 / 接手先看这里，不要往下翻二开启动器：** 先问接不接。若接了：有窗须先看见授权页验卡密再进主页面，再按形态看见三种基础加第四种（被挤掉会停、开着还在周期性验证）以及购买/联系/更新，才能打包。不接仍打包。spec/arch 须有当面问之后写下的「接自己的授权」或「这场不接」。开场、架构格、接手测绘格、接手安全网格里的不算已问。禁止把早格里的「这场不接」抄进发布格来过门。没有就停：不要点构建、不要 `record --kind build` 把 zip/包记进账本当过门、不要打安装包、不要装人、不要 `gh release`（发前 `state gate` 须退出 0）。机器拦账本，拦不住磁盘上自己打的文件，也拦不住终端里的 `gh`。不点 confirm 也不能没问就打包。不接仍打包。不要造二开那种核心载荷加启动器，不要 `record --kind license`。若接了，桌面有窗才要授权页验卡密再进主页面；不接只改界面再打包。不要把「不要抄二开」读成扔掉授权页（这一句也只在若接了时成立）。打完关掉本书，返回工作包的直接调用方；首次分发继续干净机第一次打开（或网站预发冒烟），更新重打包继续当次更新验收。真要对外说做成了才换 `review` 戴四顶。若接：按产品形态，不要把接手一律当成没窗口。桌面有窗（含桌面接手）：才把通用授权页改成这个产品的样子（主人看过）；三种基础加第四种是对才开、错不开、到期本地关、被挤掉则下一次验证内停；藏页/关页是附加，不能顶第一种。购买/联系/更新一次做全（跟下游原文；更新带版本号问平台，有新版才打开网盘）。命令行/无窗口（含无窗接手）：不要为过关造授权页或启动器，三种基础加第四种是卡密对才放行主命令、错不放行、到期本地关、被挤掉则下一次验证内停主命令。网站/有页面的服务（含网站接手）：站点自己的收费门（对才提供服务，错不提供，到期本地关、被挤掉则下一次验证内停服务，不要关软件、不要藏授权页）。开着还要周期性 verify，只 activate 不算。两套钟不准改混：到期靠 expires_at 本地关，不要改成到期也必须再问才关。挤机必须再 verify，下一次验证内停。expiry 是卡还剩多久，禁止把验证间隔/cache_until/next_verify_at/20 秒/60 秒交给核心或标题栏。测试/验收间隔默认 60 秒，不要 20 秒硬刷。只有一台时超过验证间隔还在，没人挤不会自己关。RATE_LIMITED 不是停机。宽限不是多台同时登录。有页面的服务只走网站这条。人能看见主功能那天须已有原创基线（清单+总图+改动图+`work/vX`），发版冻进 `freeze/vX`。作废/断网按这场要不要测，不是每场必测。须一段未连正式的孪生/测试分身/先测，另记已连正式（两段账；一句「先测再连正式」不算），再打包。更新回滚 / 发布回滚 / 上线回滚 / 交付验收看最新答句：打包格写了「这场不接」、后面改口「接自己的授权」，仍要两段。授权测试与更新演练分别留实际观察；测试环境验证、正式接线是两段不同事实，不能靠措辞过门。命令行「分发包与跨平台确认」：最新 spec/arch 写了跨平台 / Linux / macOS / Darwin 时磁盘须有不止一份分发包，一份本机包不能点绿。包内主程序 = 刚验的候选哈希。

**仅 exe-rebuild，先看 `status` 当前阶段，再读后面哪一节：**

- 停在 `5-pack`：只做「正式包」——干净安装 + 首次启动。禁止在这一格**做**覆盖更新和官方改道，禁止 `record --kind dossier`。
- 停在 `6-update`：才做「覆盖更新 / 官方更新 / dossier」。对着刚验过的那份包哈希。
- 旧四格停在 `2-license` / `3-ship`：**不要为过门去 record build 或 dossier，不要 confirm。** 授权/出货格作废，不要执行。缺测对人说未验证，不能把出货点绿。不要把 `UNVERIFIED` 抄进 confirm。

被桌面/网站/CLI/接管加载时：用「同源制品链」「别假装」和硬门里「客户会下到的地址」；不要套下面二开启动器阶段门。桌面/CLI 的 `install_receipt` 只证明包能装、部署住；首次分发仍须回产品线验证首次启动/主命令，更新重打包仍须回当次更新验证旧用户的升级。网站按自己的实际调用位置继续，不套桌面「下一格」。

## 无源码二开：核心 EXE 是载荷

- 二开制品链（**仅 exe-rebuild**）：**access →（产品边界）→ ui / regressed → licensed → release**。先改界面并用新候选回归核心，再接启动器授权，再打正式包。逆向前不预设启动器。开发探针不得打进客户包。
- 可选「形状可行性」早验（**仅 exe-rebuild**，未改动核心 + 桩启动器）**只证明安装器工具链**，禁止写入 access/licensed/release 证据，禁止当作分发完成。其他产品线不要去造桩启动器。
- 直接启动载荷与经启动器启动，只在 **exe-rebuild** 的 access/license 记录里用 `direct_launch` 说明；launcher-only 过不了门。其他产品线不要造**二开那种** license 记录（启动器 / `direct_launch` / `updater_treatment`）。二开没有「这场不接」过门，不能「不接仍打包」；须已经过授权页启动器、须已经有过 license 记录，再打正式包。上面原创段的「不接仍打包」不要套到二开。

## 正式包（仅新合同 `5-pack`）

- `record --kind build` 必须含 `artifact`、`candidate_sha`（必须等于当前 release 候选哈希，机器会比）、`install_receipt`（干净安装 + 首次启动）。客户包不要依赖本机 PATH 里的 Python。**这一格禁止做覆盖更新和官方改道**，不是「可以先做、只是别写进收据」。中枢不会替你变出安装器，要真用 Inno 或本机已有工具。旧合同阶段 id 不是 `5-pack` 时连正式包都不要为过门去做。

## 同源制品链

- 包内主程序 = 验过的那个候选（同一哈希）。禁止「验 A 打 B」。`build.artifact` 必须是产品目录里已经存在的**安装包/镜像/分发产物**，不是迁移脚本或配方文件；只写 `installer.exe` 三个字、磁盘上没有，出货停点过不了。登记候选目录时机器会跳过 `.env` / `.env.*`，人也不要把密钥文件另打进包。**不要把产品根 `TEMP/` 打进给别人的包。**

## 仅 `6-update`：覆盖更新、官方更新、档案（**仅 exe-rebuild**）

`5-pack` / 旧 `3-ship` **禁止执行本节。** 覆盖更新不是给别人的包里两件小活：软件里下、有进度、弹出安装、默认旧路径盖成同一个软件，卡密和数据还在。平台能下 ZIP ≠ 覆盖做成，也 ≠ 软件里立即更新已改道；另装一个文件夹 ≠ 覆盖更新。软件里两扇不同的更新窗、两条通道不要合成一次交差；confirm 对着刚验过的那份包哈希。换了没打进包的字节过不了门。

对人先说三句再往下做：给客户装的仍是 exe；网站规定上传要装箱贴标签；软件里那颗更新按钮还没改道。平台能下只是链接探针，不能当本格交差。

`record --kind dossier`（字段见 `templates/dossier.v1.example.json`）只在本格写。这是给下一份 AI 的重做说明，不是第二套状态机。`replay-order` 是整表覆盖，不要当成追加。旧四格不要为过 `3-ship` 去补这份档案。status 在 `3-ship` 打出的目标句（dossier / 官方更新）也作废。

原创桌面/网站/CLI/接手的更新停点在各自主技能，不要用下面三句代替。**客户会下到的地址仍要管：** 空功能表、没有定档冻本对照、半成品/试包，不得出现在那个地址。不要因为「那三句是二开写的」就把地址放开。

`6-update` 两段故事（客户路径 vs 吃新上游）不许一次吞掉。半成品不准放到客户会下到的地址。对着刚验过的那份包哈希。冻本与包哈希要对上才能当更新源。

人话（零基础，不是口号考卷）：更新那条路还是红的，刚打的包不能当更新源。给别人的包绿了，不洗覆盖更新那一格——绿的是「能交给别人去装」，不是「已经装上的人已经升了」。工作拷贝改了 ≠ 安装后那一份也改了。两份分开说。热更新要写这两个字：改到客户机器安装目录里的那一份，才算那一份。开发机再装一次 ≠ 客户已经装上的那一份升了。网站/桌面/命令行/接手同样管客户会下到的地址。不要抄二开那种核心载荷加启动器；接了社区平台时，软件里点更新打开网盘就是客户路径。

- 维护者：隔离摄入新上游（安装包/EXE/ZIP/官方就地更新）→ 重放档案 → 新候选。
- 客户更新只有三条，不能收成一张「已签名清单」：自己的服务器、直接把文件发给客户、授权平台应用内推送。
- 客户点**上游**官方更新必须失败或进上面三条之一；`updater_treatment` 写移除/禁用/重定向，并在本格复检。字段写「已处理」不算。

## 程序与数据

- `PROGRAM_DIR` 与 `DATA_DIR`（配置/授权/设备状态）分开备份与迁移；失败恢复后要有业务复验，不只是文件复原。

## 别假装

- 目录生成 / 能编译 ≠ 装得上；本机能装 ≠ 客户机能装；HTTP 200 / 窗口打开 ≠ 分发完成。加载了本技能也不会自动变成干净机真跑。
- 给别人的包绿了 ≠ 覆盖更新那一格也绿了。更新那条路还是红的；刚打的包不能当更新源。
- 工作拷贝改了 ≠ 安装后那一份也改了。两份分开说。热更新要写这两个字：改到客户机器安装目录里的那一份，才算那一份。
- 开发机再装一次 ≠ 客户已经装上的那一份升了。网站/桌面/命令行/接手同样管客户会下到的地址；不要抄二开那种核心载荷加启动器。接了社区平台时，软件里点更新打开网盘就是客户路径。
## 硬门：打包器不是验收工具

本书只负责把已经通过产品线物理门的候选制成包，不得用“能生成目录/能编译/有 `MZ` 头/文件大小合理”代替安装器真实验证。`record --kind build` 和 `state gate` 会检查前置物理收据，但 `state gate` 不能阻止模型直接在任意终端调用 ISCC、NSIS、zip、容器工具或 `gh`；账外生成物必须标为未验证。

调用打包器之前必须：主人真实看见主程序/主命令/网站主流程；当前候选哈希与要打包的内容一致；当前阶段可在打包前完成的物理门已通过，并按产品线合同登记/锁定候选。打包器产出的包在 `package_install` 通过前只能作为未验证测试输入；随后桌面/命令行再跑 `clean_install`，网站跑真实预发链路。只有后置物理门和主人验收都通过，才能登记/称为正式分发包。二开额外要求 `core_closed`、`license_dataflow` 和启动器→核心链路通过。包内不得有开发探针、`.env`、密钥、用户数据或产品根 `TEMP/`。

空功能表 → 不得称为正式分发包。半成品、试包、没有定档冻本（带着「我们的 vs 原件」或原创「我们的 vs 上一版人看见的」对照）→ **不准放到客户会下到的地址，不得当更新源，不得让旧客户去点。** 第一包还没定档时可以先打成未验证测试输入，但那份不得挂到客户会下到的地址。网站没有「原 exe」：对照的是上一版人看见的，不要考主人认冻本文件夹。这几条网站/桌面/命令行/接手同样要管，不要说「更新那三句只属于二开所以我不管客户会下到的地址」。二开启动器手续继续只属于 exe-rebuild，不要抄到别的线。

人话（零基础，不是口号考卷）：更新那条路还是红的，刚打的包不能当更新源。给别人的包绿了，不洗覆盖更新那一格。工作拷贝改了 ≠ 安装后那一份也改了。两份分开说。热更新要写这两个字：改到客户机器安装目录里的那一份，才算那一份。开发机再装一次 ≠ 客户已经装上的那一份升了。网站/桌面/命令行/接手同样管客户会下到的地址。不要抄二开那种核心载荷加启动器；接了社区平台时，软件里点更新打开网盘就是客户路径。`state gate` 拦账本，拦不住终端乱打安装器或 `gh`。调用打包器之前主人还要真实看见主界面 / 主命令 / 真页面。

任何候选、探针配置、合同、阶段 epoch 变化都会使旧物理收据失效；必须重新验证，不能复制上一版收据。
