# 既有源码接管流程

施工、换技能和交接时，按 `docs/ENGINEERING-CONTINUITY.md` 把原话、有效决定、最终消费者、影响面、真实观察与返回动作接到已有工作包。只展开当前这一项；材料有字不算完成。

## 怎么用这份文档

阶段清单、停点、进度真源都在 `state`，不在这份散文里。对主人先白话：做到什么、还缺什么、下一步看哪。一次只说一扇窗、一个键。机械项自己跑；主功能给人话清单等人测；做不到当场说。两句不能互相吞掉。**轻量不要走本流程、不要 init。以后要卖不要收成直接改代码。无产品账不要对当前工作区跑 status。**

开场先问仓库在哪、这次改成什么样。许可证不允许闭源卖就停。**不要把 init 当第一句。无产品账不要跑 status，不要问「是这一档吗」。**

方案能推进之后才 `init --type source-takeover --baseline`，不要开场就敲。产品夹不要开在中枢里面。

有产品账之后才跑：

```
python tools/state.py status  --product <产品目录>
python tools/state.py confirm --product <产品目录> --stop-point "<停点名>" --evidence "这一步验证了什么（具体可复核）"
python tools/state.py record  --product <产品目录> --kind spec|arch|module|anchor|build|follow|cover|replay-order --data '<json>'
python tools/state.py candidate --product <产品目录> --set <当前构建产物> [--bless]
```

> Windows / PowerShell 传内嵌引号的 JSON 容易被吞——复杂 JSON 用 `--data-file <文件>`（BOM 也能读）。

阶段是数据，见 `templates/source-takeover.phases.json`（已知产品线的默认阶段 id、顺序和物理检查不可删、改名或重排；可增加步骤并按业务适配实现）。每个停点都有 `requires`：没记对应制品，`confirm` 过不了。无源码 EXE 走 `exe-rebuild`。能交给别人用必须有 `build`。

**不算（防换皮，未用真产品打穿）：** 读 README ≠ 盘点；本机缓存能编 ≠ 基线；按文件夹填模块表 ≠ 懂了控制流。架构确认不得一口吞掉未跟过的主路径。机器：测绘/架构须写动作+分发才能点绿；答不出不能点绿。改造实现写动作未证不能点绿。空成功只拦表里金句、按停点中文名；未入表的格不拦。未用真产品打穿，不算五类都能管。

spec 须 `acceptance`；arch 须 `decision`；测绘须 `module`（name/purpose）和 `anchor`（how：当时那件事以后还用得上的原文，说明书套话不算，不记本版行号）。安全网/改造/基线/发布的 test 须 `evidence_level=product|human`。能编译不算。边做边留下以后还能用的记录；还在做不拦，要点「做成了、进下一阶段」时账本里必须已有这些记录。

## 开场先讨论，后面和二开同一套卖路（只换前面，仍抱本书，不要换成 exe-rebuild）

接手不是立刻改代码。先看懂、先建基线，再跟主人讨论：这次要改成什么样、以后怎么卖。常见坑你挡住，不要主人当产品经理补洞。方案没补到「可以一步步推进」之前不算开工改造。「不要抄二开」只禁止逆向、把没源码的核心当载荷再套一层、挡对方授权页、产品怎么分三选一、把二开 `record --kind license` 抄过来交差。**要抄的是后半段整段、授权页验卡密（有窗时）、授权 A 全表、清单地图冻本、一版一目录。** 不要把这句话读成扔掉授权页。主书是本书，不是 `exe-rebuild`。卖路径别丢；该换书仍要换，不要把「只加载本 skill」读成整场不换书。开场不要拷功能表、不要建档案夹给主人签字。已有表则开工先 `python tools/map_show.py --product <产品>`（不要 `--id`），改哪再 `--id`。禁止整仓重读。可以不接授权；不要把没源码的核心当载荷再套一层。

**还没答完不准开工改造。** 部长自己答，不准印给主人当考卷，不准每格把十四问全问一遍。不要抄二开「原件接/关/替」，也不要硬做窗口。

- 上游已经会什么？我们是改、留、还是换成自己的？
- 失败时人看见什么？
- 改完既有行为还在吗？
- 清单从哪天写？

改功能时：先读已经记下的 spec / arch / module / anchor；改 A 之后复验 B 还在、加过的组件没被拿掉、既有行为没坏。靠项目账，不靠聊天记忆。

主流程改造能用之后走**后半段**。不要直接跳到发布。有窗口先改界面，没有窗口就改命令/调用体验（不要硬做窗口、不要把没源码的核心当载荷再套一层），再**问**主人接不接自己的授权。可以不接——把「这场不接」写进 spec/arch，走改界面或改体验 + 打包；不要为过关硬接。若接，把「接自己的授权」写进 spec/arch。spec/arch 里没有这两句之一，就不要开始打发布包。开场、测绘或安全网格里的「不接」不能当已问。不要用 confirm 的 SKIP 去点绿「现状盘点确认」或发布那些格；这场不接不是 SKIP。禁止在没问之前把 spec 写成「这场不接」。若接：按产品形态，不要用「有没有窗口」两分去关软件。桌面有窗：授权平台 → 授权页（验卡密）→ 主页面；才把通用授权页改成这个产品的样子（主人看过这一页；不要另写一套协议、不要拿没改过的通用页直接接正式）→ 三种基础真跑（卡密对且没过期才开后面的程序；不对或一进来就过期则不开；用到一半到期则关掉后面的程序并且授权页自己也关）。还要第四种：卡仍有效，但这台 `DEVICE_NOT_BOUND` / 被挤掉 / 已解绑时必须停。开着还要周期性 verify，只 activate 不算。两套钟不准改混：到期靠 expires_at 本地关，不要改成到期也必须再问才关。挤机必须再 verify，下一次验证内停。expiry 是卡还剩多久，禁止把验证间隔/cache_until/next_verify_at/20 秒/60 秒交给核心或标题栏。测试/验收间隔默认 60 秒，不要 20 秒硬刷。只有一台时超过验证间隔还在，没人挤不会自己关。RATE_LIMITED 不是停机。宽限不是多台同时登录。藏页/关页是附加，不能拿来交差，不能顶第一种。网站/有页面的服务：站点自己的收费门（对才提供服务，错不提供，到期本地关、被挤掉则下一次验证内停服务；不要关软件、不要藏授权页、不要做成桌面授权页包着网站）。没有窗口：不要为过关造页、造窗、造启动器；三种基础加第四种是卡密对才放行主命令/服务，不对或一进来就过期则不放行，用到一半到期则停，被挤掉则下一次验证内停主命令/服务。购买/联系/更新一次做全：购买网址和联系字跟这张卡的下游，原文原样；更新带版本号问平台，有新版才提示，有窗则点了打开网盘；设备码 `缩写-XXXX-XXXX-XXXX-XXXX`；激活后还要周期性验证、解绑后停；测试只用 `ceshi1`、新发卡；已售卡锁快照。人能看见改造后的主功能那天锁清单+总图+改动图当**原创基线**，一版一个 `work/vX`，发出去冻进 `freeze/vX`。作废/断网按这场要不要测，不是每场必测。再：先在测试环境测通，再连正式自己的平台（两步；共享平台先孪生）。接了授权后对人测两段：先只有一台、等过验证间隔还开着（没人挤不会自己关）；再第二台挤第一台，第一台下一次验证内停（被挤掉会停）。再打包。

## 四条贯穿所有阶段的纪律

1. **先看懂、先建基线安全网，再改。** 接管最大的坑是"没搞懂就动手，改坏了还不知道"。阶段 1 必须先能从干净检出**可复现地构建 + 运行 + 跑通既有测试**；没有测试就先围绕主流程补**特征化/冒烟测试**当安全网，再进改造。
2. **每次改动都要证明既有行为没被改坏。** "能编译""能启动"都不算数——用阶段 3 补的特征化测试证明改造前后行为一致。改动小步走，测试保持绿。
3. **看懂的东西记账，别塞进脑子。** 架构 `record --kind arch`、模块 `record --kind module`、关键位置**怎么重新找到**（不是这一版行号）`record --kind anchor`。长对话/换会话后：有产品账才靠 `state status` 找回；没账就继续问仓库在哪、要改成什么样，不要跑 status，不要问「是这一档吗」。别重造已有模块、别违背已定架构。
4. **同源制品链 + 候选登记 + 跟上判断 + 一版一目录。** 当前构建用 `state candidate --set` 登记、里程碑 `--bless` 记回退点。跟上新版本/发布的正路是 `record --kind follow` 三句（我们改过哪些、这一版新改了什么、哪些还能认哪些是新门）+ 改动图/冻本，不许照抄清单。这一版只在 `work/vX` 里改，下一版新开目录。`replay-order` 不是跟上/发布正路，禁止拿旧脚本交差。功能定档认 git（一块测好了提醒提交，再开下一功能）；`--bless` 不能当功能相册。解包/日志/草稿只进产品根 `TEMP/`；`work/vX` 和冻本不进 `TEMP/`。

## 阶段 0 · 接管与现状盘点　→ 停点「现状盘点确认」
- **做**：搞清这仓库是什么、语言与技术栈、入口与主流程、号称怎么构建运行、别人的开源许可证、git 现状；定义接管目标与"算正常工作"的可观察标准。开源许可证 ≠ 自己的收费授权。登录鉴权 ≠ 自己的收费授权。许可证不允许闭源卖就停。盘点格不要强制写下接或不接——那句等到核心能用、有窗口改过界面 / 没有窗口改过命令体验之后当面问，机器门只在打包。不要硬做窗口、不要把没源码的核心当载荷再套一层。方案能推进之后才 `state init --baseline` 锁关键文件哈希；`record --kind spec` 记接管合同。
- **别假装**：README 说能跑 ≠ 真能跑；先别信文档，后面阶段 1 亲自验。盘点完就交付 = 没走到能卖。

## 阶段 1 · 可复现构建与测试基线　→ 停点「构建测试基线确认」（requires: candidate + 本阶段新 test，且必须 --bless）
- **做**：从干净检出可复现地构建 + 运行 + 跑通既有测试；没有测试就先补特征化/冒烟测试。第一个可复现构建 `candidate --set <候选> --bless` 记为 last-good。
- **别假装**：本机偶然能跑 ≠ 可复现；"大概能编译" ≠ 基线成立。这一步是后面所有改造的安全网，不能跳。

## 阶段 2 · 架构与风险测绘　→ 停点「架构与风险测绘确认」（requires: arch + module + anchor）
- **做**：测绘架构/模块/数据/外部依赖/高风险区。`record --kind arch` 记架构、`--kind module` 记模块、`--kind anchor` 记关键位置怎么重新找到。
- **别假装**：读了几个文件 ≠ 懂了控制流；高风险区没标出来 = 改造时踩雷。

## 阶段 3 · 安全网与改造计划　→ 停点「安全网与改造计划确认」（requires: spec + 本阶段新 test）
- **做**：在将要改动的区域补足特征化测试，能证明改造前后行为一致；把改造计划 `record --kind spec` 记进清单再动手。
- **别假装**：没有安全网就改核心 = 盲改。

## 阶段 4 · 受控改造　→ 停点「改造实现确认」（requires: candidate + 本阶段新 test；当前哈希须与 last-good 不同）
- **做**：小步改造 + 测试保持绿 + 主流程仍真跑通过。改造后先构建再 `candidate --set`，不要沿用基线那份哈希；本阶段新 test 须绑这份新候选。新候选要重跑安全网对照，不能只比两个哈希不一样。新需求先 `record --kind spec`。**每改完一刀，复验既有行为还在、加过的界面或命令体验没被拿掉。** 记过的模块名必须写进本格 test，机器才认复验过。一块功能主人测好了就提醒定档（git 提交），再开下一功能。改造能用之后：有窗口先改界面，没有窗口就改命令/调用体验，再问授权，不要直接进发布格。人能看见改造后的主功能那天，部长自己写下功能名和**作用是什么**（产品根那一行功能表），并锁**原创基线**（清单 + 总图 + 改动图 + 这一版 `work/vX`）。空表不得说完善。旧场表空：先从 Git、源码、交接、原话和实际候选恢复，标清仅源码推定与仍待运行的部分；只问无法恢复的业务决定。不要先建档案夹。
- **别假装**：编译过 ≠ 行为没变；沿用基线候选哈希 ≠ 改造后的构建；改一大片再一起测 = 出问题定位不了。模块表在、测试没点名 = 没读表。改完代码就交付、没问接不接授权 = 没走到能卖。

## 阶段 5 · 发布候选构建　→ 停点「发布候选确认」（requires: candidate，且必须 --bless）
- **没答句就停：** spec/arch 里须有主人当面写下的「接自己的授权」或「这场不接」。没有就不要打发布候选包，不要 confirm「发布候选确认」，不要 `gh release`。开场、测绘或安全网格里的「不接」不能当已问。若接：桌面有窗才改通用授权页（主人看过）再进主页面；三种基础加第四种是对才放行后面的程序/服务、错不放行、到期本地关、被挤掉则下一次验证内停；藏页/关页是附加，不能顶第一种。购买/联系/更新一次做全（跟下游原文；更新带版本号问平台，有新版才打开网盘）。confirm 证据须含三种基础、被挤掉会停、没人挤不会自己关、开着还在周期性验证，以及购买/联系/更新；桌面有窗还须含主人看过这张授权页、从这页进了主页面。三种基础不能代替授权页，也不能单独点绿。一句「激活/验证/解绑都要」不算第四种。网站是站点收费门（对才提供服务，错不提供，到期本地关、被挤掉则下一次验证内停服务，不要关软件、不要藏授权页）；没有窗口不要为过关造页，三种基础加第四种是对才放行主命令/服务、错不放行、到期本地关、被挤掉则下一次验证内停。作废/断网按这场要不要测，不是每场必测。还须一段未连正式的孪生/测试分身/先测，另记已连正式；一句「先测再连正式」不算。本格须已有原创基线（清单+总图+改动图+`work/vX`）。
- **没看见就停：** 本格测试结果「做成了什么」里要写清：主人已经看过换成这个产品的界面或命令体验（有窗口写界面，没有窗口写命令体验；写看见了什么、主流程还在不在）。这不是授权页那句「主人看过」。只写计划或看起来不算。记录实际看到的对象、行为和对应版本；标点或换一种说法不能制造观察证据。不要只写证据栏。不要把短句当完成口令抄进测试结果。没有看见就不能点「发布候选确认」。
- **做**：构建与源码同源的可复现发布候选，落哈希，`candidate --set <候选> --bless` 记为 last-good。
- **别假装**：能 build ≠ 磁盘上有已 bless、可复现的发布候选哈希。

## 阶段 6 · 发布与回滚　→ 停点「发布回滚演练确认」（requires: build + 本阶段新 test + follow + cover）
- **没答句就停：** 和发布候选同一条：须有主人当面写下的「接自己的授权」或「这场不接」。开场、测绘或安全网格里的「不接」不能当已问。发布候选写了「这场不接」，本格改口「接自己的授权」仍要两段，不能只改口过门。没有就不要把已 bless 的候选交到发布形态，不要 `gh release`（发前 `state gate` 须退出 0）。这道门拦账本，拦不住终端里的 `gh`。
- **做**：把已 bless 的候选交到可回退的发布形态；当前候选和 last-good 须仍是发布候选那份哈希，换了没发布的字节不能点这一格。回退到上一发布后同一主流程对同一真实输入复验；配置/数据/用户资产保留。必须是客户还在用的那一份，不是开发机再覆盖。半成品不准放到客户会下到的地址。定档冻本对照接手基线/上一发布，光拷自己的图不算核对。先 `state record --kind follow` 写下三句：我们改过哪些、这一版新改了什么、哪些还能认哪些是新门。另 `state record --kind cover` 记下客户路径（客户还在用的那一份升了，覆盖做成）；本项 SKIP、吃新上游不能顶。正路是这三句 + 改动图/冻本 + 客户路径，不许照抄清单。没有这三句和客户路径不能点发布回滚确认。`replay-order` 不是跟上新版本/发布的正路，禁止拿旧脚本交差。
- **别假装**：`gh release` / CI 绿 ≠ 回滚后主流程对同一输入复验。开发机再覆盖 ≠ 客户还在用的那一份升了。发 Release 前 `state gate` 须退出 0；这道门拦账本，拦不住终端里的 `gh`。

## 阶段 7 · 交付与维护档案　→ 停点「交付验收确认」（requires: build + 本阶段新 test）
- **没答句就停：** 和发布候选同一条。前面写了「这场不接」，本格改口「接自己的授权」仍要两段。授权测试与更新演练分别留实际观察；测试环境验证、正式接线是两段不同事实，未执行就保留未完成，不能靠措辞过门。
- **做**：交付物 + 使用/运维说明 + 跟上判断（第 6 格那份 `follow` 三句）+ 改动图/冻本，让下一个人能重建与回退；用户在真实环境验收并点头。当前候选和 last-good 须仍是发布候选那份哈希，换了没发布的字节不能点这一格。`replay-order` 可留作顺序备忘，不是跟上/发布正路，禁止拿旧脚本交差。
- **别假装**：前面全确认 ≠ 已交付；维护档案缺失 = 下一个人接不了手。

## 交付出口

最终结论同时列：已验证、未验证、残余风险，以及"从哪看起 / 怎么验 / 怎么回退 / 唯一下一步"，让第三方能独立接手。
高风险交差前换加载 `review`（一次一本）：按四审帽子走完（程序→产品→测试→发布），写的人不能给自己过，也不能自己宣布完成。`state` 全绿不是完成。
交付后再改同一产品：用 `state reopen` 从受影响阶段重开，清单还是这份 `.hub`，不要 `init` 当新项目，也不要走整条线只改错别字。发布回滚在合同第 6 格，不是再开一份合同。
## 硬门：接手项目要证明安全网和可回退行为真的存在

- **探针先行与防丢清单**：接手改造涉及核心逻辑前，先在 `.hub/physical-gates.json` 配置机器断言并在会话中列出防丢清单。严禁以局部单测通过向主人宣称搞定；改造中的单元测试必须沙箱隔离，严禁直接读写生产配置路径。
- 接手不是读完代码或写一份报告就算完成。安全网、改动回归、候选构建、发布回滚和交付阶段必须按合同运行 `state probe`，收据绑定当前候选、合同和物理阶段 epoch。子代理报告、静态审查、测试绿和服务能启动都不能单独放行。

- `safety_net` 要真实证明将改区域改造前后行为一致（特征化/冒烟对照）。备份恢复若这场有数据要迁，另走对应观察，不能拿备份绿顶安全网。
- `change_regression` 要在改动后的候选上重跑旧主流程，防止改 A 丢 B。
- `release_candidate` 要检查构建产物与已验证候选同源；不能验 A 发 B。
- `release_rollback` 要真实回退并复验功能和数据；`handoff` 要由另一个执行者重放。

接手的产品形态决定授权门：有窗口才走产品样式授权页验卡密再进主页面，无窗口走主命令门，网站走站点收费门。不要把没源码的核心当载荷再套一层；不要把「不要抄二开」读成扔掉授权页。若接了自己的授权，发布候选及之后的格还要 `license_dataflow` 机器观察卡还剩多久（不是 20 秒/60 秒间隔，也不是 next_verify_at）、用到一半真卡过期停、被挤掉停、只有一台超过验证间隔还在、RATE_LIMITED 不是停、周期性 verify；须在 `.hub/physical-gates.json` 里配置。这场不接不套。未通过物理门前不要调用发布或上传工具；`state gate` 只验证账本，不能声称拦截所有终端命令。
