## 规则怎么进上下文（2026-09-28 改版）

**只有一层了：规则全文直接内联进宿主入口文件。**

| 层 | 状态 |
|---|---|
| ~~标记块（11 句压缩短句）~~ | **已废**。它是围绕"省 token"建的，主人从没要求过省 token |
| ~~`CORE.md`（底线卡，首读件）~~ | **已废**。它是"指针指过去让模型自己跳"那一跳的落点 |
| ~~`hub/AGENTS.md`（全量规则，按需读）~~ | **已废**。同上 |
| **规则全文内联** | ✅ 现在只有这个 |

装完 `~/.pi/agent/AGENTS.md` = **约 23,600 B**，就是中枢规则全文，
外面套一对定界标记。模型不读也不会漏。

**为什么改**：原来的三层赌「模型会顺着指针跳过去读 CORE.md 和 AGENTS.md」。
实测的问题是**它可能不跳**——指针那行是裸文件名（`AGENTS.md` / `CORE.md`），
在家目录根和 `hub/` 下都有同名文件，路径有歧义。而当初这么设计的理由
写的是"省 token"——**主人从没要求过省 token，只要求效果最好**。
省字节换来的风险是自己造的，所以不省了。

**不要把这个改回去。** `MARKER_BUDGET = 32000` 是**装的时候拦异常膨胀**用的，
不是设计目标：**规则该写多长就多长，不要为了凑这个数删底线。**

## 标记块不是常数

指针行嵌了宿主家目录**绝对路径**，所以同一份标记块在不同家目录下实测三个数：

| 宿主家目录 | 字节 | 对 32,000 |
|---|---|---|
| 相对路径 | 约 23,570 | 余约 8,430 |
| `<用户目录>\.codex` | **约 23,600** | 余约 8,400 |
| `<用户目录>\AppData\Roaming\Claude` | 约 23,600 | 余约 8,400 |
| `...\globalStorage`（本次测到的最坏） | 约 23,600 | 余约 8,400 |

**预算按最坏情况定**（设计方案 §3.1.1 选项 ①）。预算检查的是内联规则全文，不是短句摘要。

## 入口文件里的三段与顺序

```
宿主原文  →  底模块  →  客套指引块  →  中枢标记块（永远最末）
             ↑ 随时可换    ↑ 别人成品原样   ↑ 最后定论

覆盖模式（控制台「宿主原文」开关默认开着）：第一段整段丢掉，只留后三段。
原字节在 hub/.backups/ 里，重复覆盖安装接着上一棵树那份，卸回还原的仍是真原文。
```

**顺序是刻意选的**：标记块写最后，所以它是入口文件里的最后一段定论，
主人换任何底模、任何指引卡都不影响它生效。这是「和任何底模兼容」的实现方式——
**不靠措辞逐条压制，靠位置 + 指针行末尾那句「本块最后定论」**。

**工作流、门禁、地图、清单一个字都不在入口文件里**（它们仍在 `hub/` 下按需读）；
标记块内联的是 `AGENTS.md` 全文，当前约 23.6 KB。
