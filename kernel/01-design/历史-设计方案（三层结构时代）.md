旧中枢每场对话先吃掉 **36,685 B**（30,933 B 静态盘 + 约 5,752 B 运行时生成，其中含一份 **92 个技能名**的清单），

## 1. 三层分开：怎么落到实现

**白话**：旧中枢只有一档——所有东西都往上下文里塞。新系统分三档，每档有明确进/出规则。

### 1.1 三层的定义（写在新常驻 `AGENTS.md` §9）

| 层 | 是什么 | 默认动作 | 谁批准它进上下文 |
|---|---|---|---|
| **当前层** | 当前任务、当前阶段、当前目标、当前阻塞、已确认决策、下一步、必须守的约束 | **默认进** | 无需批准 |
| **资料层** | 项目地图、架构说明、功能资料、版本资料、长期说明 | **存盘，默认不读** | 要读得先给索引，正文要带意图 |
| **历史层** | 历史对话、历史工作记录、已完成任务、老版本资料、旧交接记录 | **存盘，按需读** | 同上，且要说明"为什么现在需要它" |

### 1.2 落到实现：每一层对应哪段代码

| 层 | 实现落在哪 | 关键机制 | 代码位置 |
|---|---|---|---|
| **当前层** | 任务包 `ctxiso pack` | 有预算的当前视图。包内分：任务意图 → 阶段 → 项目目标/可观察成功 → 本阶段**当前为 fail** 的探针检查 → 长期资料**索引** → **本包刻意不含** | `ctxiso/pack.py:37-133` |
| **资料层** | 文档索引 + 按需读 | 索引只存 `path/kind/size/lines/sha/one_line`，**正文一个字都不进**。要正文必须 `read --intent` | `ctxiso/store.py:273-308`（建索引）<br>`ctxiso/archive.py:74-120`（读正文，抛 `IntentRequired`） |
| **历史层** | 账本索引 + 事件查询 | 增量索引 26 MB 账本；`query` 只出**摘要行**（≤160 字符），不出收据正文 | `ctxiso/store.py:137-206`（增量索引）<br>`ctxiso/store.py:226-237`（只出摘要行） |

### 1.3 三个"不许"是怎么落地的

| 规则 | 机制 | 证据 |
|---|---|---|
| **知道文件存在 ≠ 读正文** | 没 `--intent` 直接抛异常，不给正文 | `archive.py:77-78`：`if not intent.strip(): raise IntentRequired("没有意图就不给正文。先说清为什么现在需要它。")` |
| **不许越界读** | 目标必须在产品目录内，且必须真实存在 | `archive.py:82-88`：`p.relative_to(product)` 失败即拒；文件不存在即拒 |
| **不许整仓重读** | 任务包有**硬预算**，超了截断并写明截了什么 | `pack.py:122-131` + `pack.py:136-151`；预算来自 `config.json` 的 `pack_budget_bytes` = **6000** |

### 1.4 任务包到底长什么样（普通新任务）

对普通新任务，任务包只出这 5 块，**没有第 6 块**：

```
# 当前任务包（ctxiso 0.1.0）
【任务意图】<这轮要干什么>
【阶段】<阶段>                     ← 没声明阶段就不出
【本项目目标】<contract 里的 goal，前 300 字>
【可观察成功】<contract 里的 success，前 300 字>

【本阶段探针检查】（N 个检查，最新一次都没有 fail）
    或【本阶段当前为 fail 的探针检查】（N 个 fail / 共 M 个；已通过的 X 个不再列）

【长期资料索引】（共 N 份 / M 字节；下面只列元数据，正文未读）
- current（X 份）
    - <路径>｜<字节>｜<行数>｜<一行用途>
- project（Y 份）
- history（Z 份）

【本包刻意不含】
- 历史事件正文、探针收据正文、observed/assertions 原文
- 长期资料正文（OWNER-SPEECH / CHANGES / 旧版本资料）
- 任何 Skill 内容
理由：保存不等于读取；要读必须自己提出读取意图。
```

**注意最后那块「本包刻意不含」。**
**白话**：任务包不仅告诉你「有什么」，还明确告诉你「我故意没放什么、为什么」。
这比"默默不放"强得多——智能体不会以为自己已经看全了。

### 1.5 索引层吃掉的那 23 KB

**白话**：账本里每条探针 23 KB，是因为内嵌了 `observed.json`（30+ 个 null 键）、`assertions`、`candidate_paths`（30 条）、`work_bindings`（逐文件 sha）。
索引只留**标量白名单**（`ctxiso/store.py:71-74`）：

```python
_SCALAR_WHITELIST = ("ts", "kind", "check_id", "phase_id", "phase", "result",
                     "stage", "verification_mode", "epoch", "stop_point",
                     "role", "id", "from_phase", "hypothesis_key", "product_id",
                     "type", "revision", "n")
```

**明确不取**（`store.py:77-78`）：

```python
_DROP = ("observed", "assertions", "candidate_paths", "work_bindings",
         "evidence", "items", "json", "files", "receipt", "manifest")
```

**并且摘要行是"人读的一句话"，不是把结构序列化出来**（`store.py:93-133`）。
探针没带断言明细时，它**不会编一个"失败 0"出来冒充结论**，而是明说「该次未记录断言明细」（`store.py:114-116`）——这是防止幻觉，不是省字节。

### 3.1.1 标记块的字节数**随宿主家目录路径长度变**

指针行里嵌了宿主家目录的**绝对路径**（`_bundle_lib.py:45-53` 的 `host_home` 分支），
所以**标记块不是常数**：

| 宿主家目录 | 字节 | 对 1,200 |
|---|---|---|
| 空（相对路径分支） | **1,167 B** | 余 33 |
| `C:\Users\Toti\.codex` | **1,188 B** | 余 12 |
| `C:\Users\Toti\AppData\Roaming\Claude` | **1,204 B** | **超 4 ❌** |

**所以把预算定成 1,200，等于把"第一次就被突破"搬到新数字上**——
`AppData\Roaming\Claude` 这种普通家目录当场就超。

**建议三选一**：① 预算按最坏情况定 **1,400 B** 并写明"含宿主路径展开"；
② 闸门只量**与路径无关**的那一份（空路径分支 1,167 B），路径展开另设每字符上限；
③ 指针行不写绝对路径（`_bundle_lib.py:52` 已有相对分支），代价是主人要自己知道家目录在哪。

**当前 `MARKER_BUDGET` 常量仍写 `1000`（`_bundle_lib.py:36`），且 `pack.py` 零引用——
定义了不等于被强制，超了没人拦。**

## 4. 为什么「核心内联 + 全量按需读」比「全量内联」好

> 白话：两种做法都在智能体每次开场时给它一段规则。区别是**给全文**还是**给目录 + 关键几行**。

### 4.1 三个好处

| # | 好处 | 具体数字 |
|---|---|---|
| 1 | **省 token** | **物理每轮注入**从 **36,685 B** 降到 **621 B**，**省掉 98.3%**。而且省掉的不是废话——是 6 条工作流、6 份文档、20 本方法书，以及那份 92 项技能名清单 |
| 2 | **可移植** | 标记块里的路径是**装的时候按宿主家目录算出来的**（`_bundle_lib.py:45-53`，`install.py:265` 传 `str(host_home)`），**只指宿主家目录内部**。换电脑重装一次就重新生成，**不用手改**。全量内联则必然把旧路径写死在常驻里（这就是旧 `hub/AGENTS.md` 里那些 `<product>` 占位符要靠 `engine.py` 运行时替换的由来） |
| 3 | **按需** | 主人做二开就读 `exe-rebuild`（42,749 B），主人改界面才需要 `ui-design`。**一次只付一次的钱。** 全量内联则是每场都为用不上的东西付费 |

再补一条实测理由：**动态那 92 个技能名就是按需没做好的产物。**
它是"每场都进，但主人可能一个都不用"的典型。新设计从根上不给它位置。

### 4.2 代价（必须如实说）

**代价只有一个，但它是真的：**

> **智能体必须自己主动去读一次 `hub/AGENTS.md`。**
> **如果它没读，就只剩 CORE.md 那 3 KB——它会丢掉全量规则里的细节。**

**丢的是什么？** 不是底线，是细节：

| 会丢的 | 例子 |
|---|---|
| 某条线的完整步骤 | `protocol-automation` 的四个物理门怎么设计探针 |
| 物理门的完整观察点 | `license_dataflow` 要观察的 7 个字段各是什么 |
| 方法书 | 审查怎么交叉、浏览器测试怎么跑 |
| 口径 | 对主人说话用哪套措辞 |
| 例外与边界 | `docs/VOCABULARY.md` 里的例外清单 |

**不会丢的（这些在 `CORE.md` 里，实测 2,988 B / 11 块）**：角色、六条线选一、三步判断、定档、证据分级、点头只认主人、保存≠读取、换班、诚实、危险动作、规则在哪。

**这 11 块是"底线"**——丢任何一条，做出来的东西都可能是主人会后悔的：
不认主人点头就会自己批；不认证据分级就会拿 `HTTP 200` 回报喜；不懂保存≠读取就又会把旧账当新任务。

### 4.3 对策：把最硬的 3 条同时放进常驻件

**白话**：既然"没读全量"是一种可能的失败模式，那就让**这 3 种失败也丢不掉底线**。

| # | 底线 | `CORE.md` | **标记块（每轮真注入）** | 每轮任务包 | 为什么要放这么多遍 |
|---|---|---|---|---|---|
| 1 | **文字报告永远不是物理证据**；探针没过就是没完成 | ✅ L18 | ✅ 第 4 行 | ✅ | 它错了，主人在屏幕上会看到一个"能用但其实不能用"的东西 |
| 2 | **点头只认主人本人** | ✅ L20 | ✅ 第 4 行 | ✅ | 它错了，系统就从"帮主人"变成"替主人拍板" |
| 3 | **保存 ≠ 读取**；开工先取任务包，读正文要带意图 | ✅ L22-27 | ✅ 第 5 行 | ✅ | 它错了，污染链立刻复活，本设计全部白做 |

**现在三条都是三道保险全覆盖**（本轮实跑核对）：

| 载体 | 怎么核对的 | 现状 |
|---|---|---|
| 标记块 621 B | 跑 `_bundle_lib.marker_block()` 渲染出来看 | ✅ 证据+点头在第 4 行、保存≠读取在第 5 行 |
| `CORE.md` 2,988 B | 读原文 | ✅ L18 / L20 / L22-27 |
| 任务包 | 跑 `python -m ctxiso.cli pack`，输出里有 `【底线·每轮都在】文字报告不是物理证据，探针没过＝没完成。点头只认主人本人。` | ✅ 证据+点头在那一行 |

> **上一轮这里我写错过一次**。我当时写「`pack` 每轮都带那 3 条底线」——
> **那是 overclaim**，当时 `pack` 只有「保存≠读取」那一句。
> 统筹后来把「底线·每轮都在」补进去了，现在证据和点头确实每轮都回来。
> **三行对照表留着，因为它回答的是"每轮到底能拿回什么"——这正是三层的意义。**

**写法上的硬要求**：这 3 条在**每一层**都必须能用一句话说清，不许压成只有作者看得懂的缩写。
因为每层都有硬预算（标记块 1,000 B / `CORE.md` 3,000 B / 任务包 6,000 B），
任何"压缩表达"都会在压缩时丢掉否定词和例外，**而规则丢的往往就是那句"但是"**。

**2026-09-28 已落地**：标记块现在覆盖全部 11 块（`03-bundle/verify.py` (d) 项逐条短语全在位，
以 `~/.codex` 真家目录验过：块在第 1 行、定界成对）。整块 1,179 B，预算见
`03-bundle/_bundle_lib.py:41` 的 `MARKER_BUDGET = 1200`（`install.py` 与 `pack.py` 都在拦，超了拒装）。

### 4.4 一个反面教材：「写了等于没写还占地方」

旧 `hub/AGENTS.md` 有 **6 处**句子在讲"完善中枢 / 优化中枢"：**L12、L46、L167、L197、L210（整节标题）、L212**。
而 `work/v0.1.0/hubdock/engine.py:802-813` 的 `_void_stale_source_identity()` **在注入前会用正则把它们作废**：

```python
def _void_stale_source_identity(text: str) -> str:
    """旧安装副本自称源仓、要走完善中枢的句子作废。"""
    out = _PERFECT_HUB_SHORT.sub("这场不要在这家智能体走完善中枢", text)
    out = _PERFECT_HUB_LONG.sub("这场不要在这家智能体走完善中枢。旧安装根不是源仓。", out)
    out = _RECOGNIZE_SOURCE.sub("不要把这家智能体的旧安装副本认成中枢源仓。", out)
    out = _OPT_ONCE.sub("这场不要完善中枢", out)
    ...
```

**这 6 处在磁盘上占 token，注入时又被系统自己声明作废。**

**这是"全量内联"最典型的失败模式**：
规则越写越多 → 其中一部分被运行时改写/作废 → 但没人回头删 → 常驻越来越胖、真正生效的却越来越少。

**新设计的对策**（`build_hubcore.py` 已经在做）：

| 对策 | 机制 |
|---|---|
| 作废的句子直接删，不留着"以后可能用" | `LINE_RULES` 整行 drop |
| 精简后变大就拒绝落盘 | `copy_slim` 的硬断言 |
| 禁词不许进交付件 | `FORBIDDEN` 列表 + `--check` |
| 被移出系统的技能名不许以书名形式残留 | `parked_leak` 校验 |

## 5. 新旧并存、旧系统失效时怎么一键卸干净

### 5.1 并存的前提（SPEC §0 全部 6 条）

| # | 硬约束 | 设计怎么保证 |
|---|---|---|
| 1 | 零外部路径 | 新系统所有路径相对宿主家目录；`paths.py` 的 `STATE_DIR` 是**自己家目录**，不是产品目录 |
| 2 | 不改旧系统 | 侧车**只读**产品目录，`paths.py:1` 写死「本包唯一的写盘位置是 `DEV_ROOT/state/`」 |
| 3 | 可一键卸载 | `install-manifest.json` 记逐文件 sha + 怎么卸 |
| 4 | 不联网 | 不带 `providers.py` / `license.py` / `adapt.py` clone 段 / `converse.py` 代理探测（`03-审计结论.md` §3.2 五件必改项） |

| 6 | 旧系统必须继续可用 | 新旧两套标记块互相不认，各写各的 |

### 5.2 并存时两个标记块长什么样

宿主的入口文件里可以同时有两块，互不干扰：

```
<宿主原有正文>
# >>> hub-dock hub >>>        ← 旧中枢的块（保留不动）
...
# <<< hub-dock hub <<<

# >>> hubcore hub >>>         ← 新系统的块
...
# <<< hubcore hub <<<
```

**两套都没勾 = 当不存在。**
旧块在 → 旧行为照旧；新块在 → 新行为照旧；**新块不写旧 `hub/AGENTS.md:97` 那段"上班必须接班"文字，污染链就断了**（见 `../00-ANALYSIS/01-真实系统分析.md` §6）。

### 5.3 旧系统先失效了怎么办

**这是最实际的一种情况**：主人换智能体、换工具，旧中枢的插头装不上去了，但盘上那些账本、资料还在。

**新系统的答案：那些资料还在，新系统读得懂。**

| 旧系统的东西 | 新系统怎么处理 |
|---|---|
| `.hub/ledger.jsonl` 26 MB | **照读不误**。`store.refresh_ledger()` 增量索引，白名单提取，旧格式的 12 种事件类型全部认得 |
| `.hub/requirements.jsonl` | 归入资料层索引，只出路径/大小/行数/一行用途 |
| `OWNER-SPEECH.md` / `CHANGES.md` / `WORK-HANDOFF.md` / `PROJECT-MEMORY.jsonl` | 同上，全部进 `config.json` 的 `archive_scan` 清单 |
| `hub/tools/state.py` 等运行核 | **原样搬进 `hub/tools/`**（SPEC §1 目录形态），功能不变、路径变相对 |
| 旧常驻提示词 | **不搬**。新系统有自己的 `AGENTS.md` |

**所以"旧系统失效"对新系统不是灾难，是一次自然的迁移**：
盘上那 342 KB 长期资料 + 26 MB 账本（`.hub/contract.json` 6,190 B、`.hub/manifest.json` 74,541 B、`.hub/physical-gates.json` 30,190 B、`.hub/shift-ticket.json` 1,971 B 另计）**一行都不丢**。

### 5.4 一键卸干净的四个保证

| # | 保证 | 机制 | 验收 |
|---|---|---|---|
| 1 | **装了什么就精确卸什么** | `install-manifest.json` 记每个文件的 sha 和归属 | 卸完跑一遍清单，文件数归零 |
| 2 | **宿主原文不动** | 只插标记块；卸时只摘块 | 摘完与备份**逐字节相同** → 直接还原备份；**不相同 → 只摘块、不覆盖**主人后来的修改（SPEC §3 卸-2） |
| 3 | **不留半装状态** | 先写临时目录再原子改名；自检失败整体回滚 | 自检 = 抽 3 个文件对 sha + 跑 `ctxiso status` + 跑 `state.py --help`，任一失败即回滚（SPEC §3 装-6） |
| 4 | **证明没动过旧系统** | `ctxiso/guard.py` 给 **34 个**中枢受控文件取 sha 基线 | `ctxiso guard check` 回「中枢原有 34 个受控文件全部逐字节未变」 |

**第 4 条的细节**（`guard.py:80-82`）：`.hub/ledger.jsonl`、`.hub/requirements.jsonl`、`.hub/manifest.json`、`OWNER-SPEECH.md`、`CHANGES.md` 这 5 个是**只追加**的，
它们变大**不计为被改动**；只有变小或消失才报。

### 5.5 卸载时的两条分支

```
卸：
  读 install-manifest.json
  摘标记块
      ├─ 摘完与备份逐字节相同 → 直接还原备份（主人一个字没动过）
      └─ 不相同               → 只摘块，不覆盖（主人后来改过，原样留着）
  删 hub/ 整棵树
  打印人能看的卸干净清单
```

**不做的事**：不删 `.hub/`、不删 `OWNER-SPEECH.md` / `CHANGES.md`、不碰主人原有的任何文件。
**这些是主人的东西，不是本系统装的。**

> ### 装上这套之后，「写一本技能」和「拉取新技能」这两个入口就没了。

### 6.3 一处**未确认**、需要复核的取舍

**索引库体积。**

- 任务书 / SPEC 记录的实测值是 **23,768 B**（原文 0.0043%）。
- 复核时 `state/ad09fb308a9b/index.sqlite` 实测是 **442,368 B**，且**在两次检查之间从 237,568 B 涨上来**。
- 索引表里 `ledger` 有 **2,236 行**，而账本只有 **1,118 行**——**每条事件被索引了两次**。

**根因（`ctxiso/store.py:147-152`）**：游标归零时 `seq` 没有跟着归零。

```python
cursor = 0 if force else int(_get(con, "ledger_cursor", 0) or 0)
if cursor > size:            # 账本被换短/重建过，从头再来
    con.execute("DELETE FROM ledger")
    _set(con, "ledger_seq", 0)
    cursor = 0
seq = int(_get(con, "ledger_seq", 0) or 0)   # ← 这里没跟着归零
```

`--force` 重跑时 `seq` 从 `ledger_seq` 继续往上加，而 `seq` 是主键 → **不覆盖旧行，只追加**。

**影响**：索引体积虚高一倍，查询会出现同一事件的两条记录。
**不影响**：账本正文一字未动（`store.py:157` 注释写明"只读；本包永不写这个文件"），`pack` 取"每个 ident 最新一次"仍能取对（`pack.py:80-81` 用 `latest.setdefault`，`ORDER BY seq DESC`）。

**这条我标为未确认，交主人定夺**：是修 `store.py` 的 seq 归零，还是接受现状。**本轮不修。**

### 6.4 一条不放进取舍表的

`build_hubcore.py` 的一次自曝事故，值得记下来当**方法论**而不是取舍：
精简器曾经把非空行 `append` 了两次，导致输出全文翻倍。
现在加了硬断言"精简后变大即拒绝落盘"（`build_hubcore.py:160-163`）。
**教训：任何自动改写都必须有一条"只许变小"的硬断言。** 光靠"改完看一眼"守不住。
