## 4. 核心判断（本次的三个根因）

### 4.1 根因一：可验证性缺失（R3/R11 的机制原因）

已做的全部验证都是格式层：

| 验证类型 | 实例 | 能证明 |
|---|---|---|
| 格式 | 47 份 description 形状 | 仅形状 |
| 一致性 | 26 个 CI gate | 仅自洽 |
| 装载 | 新会话列出 47 技能 | 仅存在 |
| 选择 | description 盲选 93/93 | 仅关键词路由一层 |
| 行为 | 四条验收补跑 n=2 | 唯一行为验证，手工、不可重复 |

**同行全部有"效果门"**：transilience 用 15 轮"跑 benchmark→找失败→改技能→再跑"打到 104/104；trailofbits 每技能带 graders（含 `routes-to-workflow`）；zhaoxuya520 有 175 条路由回归。

**→ 没有回归集，"改好了"不可证伪。这是循环的机械原因。**

### 4.2 根因二：结构与 R10 冲突

`re-agent-workflow.md` 是六阶段骨架，带好判据（IAT 铁律、15 分钟时间盒、ADF-R43）。但：

- 判据全在**阶段内部**，**阶段之间没有"换技能"钩子**（47 卡只有 `reverse-engineering` 1 张有 When to Pivot）
- ADF（R1–R51 判据卡）自我定位 "Not a second master analysis workflow"、**只在 Synthesis/stuck-loop 加载** → 判据卡被排除在主链外

**→ 你那晚的真实经历：它没死磕一条路，它在阶段之间迷路了。**

### 4.3 根因三：47 技能 + 关键词路由的双重结构缺陷

| 事实 | 数字 | 来源 |
|---|---|---|
| 工具选择准确率拐点 | **30–50 个**后退化 | Claude Code 官方 tool search 文档 |
| 关键词匹配 vs 语义检索 | **18.20%** vs **43.13%** | RAG-MCP arXiv 2505.03275 |
| 工具空间干扰 | 最高 **−85%** | MSR tool-space interference |
| 固定流程的自主度 | **α=0** | Agentic Security arXiv 2608.21423 |
| 长程失败主因 | Type B **58%**（缺实时难度估计） | arXiv 2602.17622 |

## 6. 缺失清单

### 6.1 三个真空白（已用一夜失败换来数据，只在案例 REPORT 里）

| 空白 | 案例实测 | 业界标准处理 |
|---|---|---|
| **启动方式/父进程检查** | CreateProcess/cmd start/干净环境 → 150ms 自杀；只有 `explorer.exe` 启动存活 | **先双击启动再 attach**（检查是早期一次性的，绕的是时机）；或 patch 比较分支；或 PPID spoof（MITRE T1134.004）。**注意：IFEO 会把调试器插命令行最前，父进程变成调试器，反而触发检查** |
| **运行期私有区代码** | 判定逻辑在 `MEM_PRIVATE + PAGE_EXECUTE_READ` 区，与文件任何节都不匹配 | 判据：`MEM_COMMIT + PAGE_EXECUTE_* + 地址在 PE 镜像外` = 运行期生成代码。工程实现抄 VMProtectDumper Memory Harvester（周期快照+64B指纹+累积union+3新区触发） |
| **无凭据云端授权** | 没卡密→触发不了服务端请求→结构性阻塞 | 四步 triage：①判 thick/thin client → ②判判断点本地/服务端 → ③本地可改则 patch/skip → ④都不可行判"成本不可接受"停止 |

### 6.2 空域（日常开发）

写功能 / 修 bug / 测试 / 部署 / 前端 / 后端 / 脚本工具 / 项目管理 —— **全部为 0**。

用户明确：**不加新项，把现有几个域填充到足够日常开发。**

## 8. 一句话

> **彻底完成 = 任何新任务进来，系统能在"不知道答案"的情况下靠证据找到路线；路线错了能自己发现并改；改完有数字证明它变好了。**
>
> 与"47 个技能覆盖多少域"是两件事。**域可以按需长，上面这三条能力必须先有。**
