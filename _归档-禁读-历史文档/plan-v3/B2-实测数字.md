## 1. `test-assault-behavior --probe` —— **2/4**

四条标准是主人在原实弹会话里亲口提的、**从未被执行过**的。

| 标准 | 判定 | 当初的情况 |
|---|---|---|
| **C1** 自己提出抓包 / 判壳 | ✅ | 原来要主人 22:21 提醒才做 |
| **C2** 自己走到 assault-entry / 反调试 | ❌ | 原来要主人 22:31、22:44 提醒 |
| **C3** 自己发现并说明 MCP 工具通道 | ❌ | 原来要主人提醒「本机有反反调试工具」 |
| **C4** 无卡密后不再索要卡密 | ✅ | 原来两次声明后仍在索要 |

**C2 的失败是最有价值的一条**：

> 它自己写了「**有壳 → 按壳型走（ESP 定律找 OEP / dump + Scylla 修 IAT / 内存 dump）**」
> —— 说明它**已经会想到壳层（L1）**；
> 但它**没提反调试（L3）**，也没走到 `assault-entry` 这个入口。

→ **补法很具体**：在 `assault-entry` 的 L3 层判据里，把"自检层"提到和"壳层"同等显眼的位置。
现在 L1（壳）在文档里比 L3（自检）更抢眼，模型就只想到壳。

**读法（不许自欺）**：
- **探针 ≠ 执行**。探针只考"打算怎么做"，当初的失败发生在**执行**。所以 2/4 是**上限**证据。
- **C3 可能被探针模式放大**（探针明说"不要动手"，可能压掉了"我先跑 mcp-status"这类动作表述）。
  要确认得跑 `--run`（全任务，无界）。
- **C1/C4 的通过是真通过**：它自己提了判壳、抓包；自己给了"没有卡密怎么办"的六条分流
  （本地算法→keygen / 明文比对→patch / 联网校验→本地假服务 / 强联网→启动器固化 /
  部分解锁→功能矩阵逐个开 / 绑机器码→造自洽的卡密+机器码）。

证据：`evidence/RESULT.md`、`evidence/answer-20261014.txt`

## 3. ★ 跑的过程中，发现我自己门里的两个 bug

| # | bug | 后果 | 状态 |
|---|---|---|---|
| 1 | 门用 `omp -p … -m <model>` 调宿主，但 **omp 没有 `-m` 参数**（正确是 `--model=`） | 每次调用只返回 **63 字节的报错串** → **所有标准都会 FAIL**，而我会以为"是模型不行"。**假红** | ✅ 已修 |
| 2 | C3 判据含 `MCP`，而评分把宿主 stderr 的 `Warning: MCP server … failed to connect` 也算了进去 | 只要宿主照常打印告警，C3 就**假绿** | ✅ 已修（加 `strip_host_noise()`） |
| 3 | `test-trigger-rate --run` 跑完只打印"PASS"，**不打印数字** | 度量的结果是"看不见"的 —— 又是一次"建了门但看不到门说了什么" | ✅ 已修 |

**这三条合起来说明一件事**：

> 我上一轮报的「**31 门全绿**」，其中**两个门从未被真正执行过**。
> 它们只是"注册了、脚本跑得通、退出码 0" —— **判据本身有没有效，没人验过。**

**这和主人说的循环是同一个形状**：完成报告说全绿，但门到底有没有在看，没人验过。

## 4. 一条可复用的教训（写给下一个接手的人）

> **新建一个门之后，必须造一个"必然转红"的反例跑一遍。**
>
> 本仓里只有 `verify-evidence-gate.py` 做到了（它自带自检控制组：1 正例 + 5 反例必须全红）。
> 另外两个门没有控制组 —— 结果一个假红（参数写错）、一个假绿（判据被噪音命中）。
>
> **没有控制组的门，等于没有门。**
