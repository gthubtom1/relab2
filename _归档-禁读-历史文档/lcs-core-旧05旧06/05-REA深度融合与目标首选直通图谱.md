# 一、REA 真正值得我们吸收的核心：【目标类型 → 第一个工具】极简直通表

大模型在做逆向、安全、协议分析时，最容易犯的错误是：**面对一个文件，在 60 多个技能和几十个工具之间反复纠结，不知道第一步该调什么！**

REA 极其成功地用一张直通表锁死了大模型的第一步。任何接手 AI，必须严格按照以下**文件直通映射表**执行第一动，严禁犹豫和自行脑补：

| 拿到目标的文件形态 / 场景 | 严禁行为（旧模型常犯错误） | 唯一指定第一动（首选工具与命令） |
|---|---|---|
| **Windows 原生可执行文件（.exe / .dll / .sys）** | ❌ 严禁一上来就开 IDA 反编译几万行代码！ | **第一步：查壳与基础信息**<br/>执行 `D:\Tools\cli\diec.CMD --extended --entropy <文件路径>` 检查加壳类型、熵值与编译器；<br/>执行 `D:\Tools\cli\floss.EXE --minimum-length 6 <文件路径>` 快速提取关键字符串。 |
| **Linux 原生二进制（ELF / .so）** | ❌ 严禁在无目标时盲目逐行读汇编！ | **第一步：格式与节区分析**<br/>执行 `readelf -h -S <文件路径>` 查看架构与节；<br/>若为 Go/Rust 编译，优先提取内嵌符号。 |
| **Electron / VS Code 插件 / 前端包（.asar 或提取目录）** | ❌ 严禁当成二进制 PE 用 IDA 去逆向！ | **第一步：JavaScript 与模块结构解析**<br/>解包 asar 或直接检索 `package.json`、main 进程入口；<br/>搜索 IPC 通信接口与 preload 脚本。 |
| **Android 移动应用（.apk / .dex）** | ❌ 严禁一上来就当成通用 ZIP 乱翻！ | **第一步：静态 Manifest 与反编译**<br/>调用 `D:\Tools\cli\jadx.CMD -d <输出目录> <apk路径>`；<br/>优先查看 `AndroidManifest.xml` 中的入口 Activity 与动态加载权限。 |
| **.NET 托管程序集（C# / F# / Unity Assembly-CSharp.dll）** | ❌ 严禁当成 C++ 原生程序丢进 IDA！ | **第一步：CIL 元数据与反混淆**<br/>使用 `de4dot` 或 `ilspycmd` 直接反编译成 C# 源码。 |
| **网络通信抓包文件（.har / .pcap / .saz）** | ❌ 严禁人工肉眼逐条看几万行请求！ | **第一步：关键认证与特征过滤**<br/>按域名、状态码、以及含 `token`、`sign`、`auth`、`secret` 的请求进行结构化过滤提取。 |
| **固件镜像（.bin / .img / 提取的 ROM）** | ❌ 严禁直接丢给反编译器！ | **第一步：熵值与文件系统解包**<br/>使用 `binwalk` 或 `unblob` 进行特征解包，先分离出 squashfs/jffs2 文件系统。 |

# 二、“30 分钟逆向 VMP 壳”的真实高手打法（实战旁路手册）

网上传说的“用 REA 30 分钟搞定 VMP”，绝不是靠 AI 自动去把 VMP 的几十万条虚拟化混淆指令还原成 C 代码（那需要几周！）。
**高手的实战打法是：外围旁路打击（Black-box Bypass & Hooking）！**

面对 VMP、Themida、OLLVM 等强壳保护的目标，接手 AI 必须遵守以下 4 步作战剧本，严禁在虚拟化代码里硬耗：

### 步骤 1：定位 VMP 边界（确定它在哪里）
1. 运行 `diec`，识别出 `.vmp0`、`.vmp1` 节区，确认进入了 VMP 保护范围；
2. **严禁行为**：严禁尝试用反编译器硬看 `.vmp` 节里的虚拟化解释循环！

### 步骤 2：寻找 VMP 外围的明文交互接口（锚点定位）
- VMP 虚拟化再严密，它只要和系统、网络、界面交互，就必须调用 Windows API 或解密出明文结果！
- **寻找三大外围锚点**：
  1. **网络发包锚点**：找 `send`、`WSASend`、`InternetReadFile`、`WinHttpSendRequest`；
  2. **界面交互与弹窗锚点**：找 `MessageBoxW`、`SetWindowTextW`、注册表读取 `RegQueryValueExW`；
  3. **加解密结果输出锚点**：找内存复制 `memcpy`、字符串比较 `strcmp`。

### 步骤 3：动态 Hook 与 RPC 绕过（不解密也能拿结果）
- 如果目标是一个负责签名/解密的函数：
  - **不要试图去逆向加密算法本身**！
  - 编写 Frida 脚本或利用 x64dbg，挂钩在函数的入口（获取输入参数）与出口（获取返回密文）；
  - 做成本地 RPC 接口供调用，直接“借鸡生蛋”，绕过整个算法逆向！

### 步骤 4：内存 Dump 与 IAT 修复（脱掉外层加载壳）
- 利用 `D:\Tools\cli\pe-sieve.EXE /pid <目标PID> /dmp 3` 直接把程序在内存中已解密展开的私有区镜像 Dump 出来；
- 用 Scylla 修复导入表（IAT），直接脱离保护环境。

# 三、REA 的能力边界警示（防踩坑必读）

1. **REA 依赖与平台限制**：
   REA 官方的大量高级功能（core dump 分析、tshark 深度过滤）硬依赖 Linux 环境，且在 Windows 下 Ghidra 桥接仍为实验性。
2. **严禁盲目在当前 Windows 虚拟机中无脑 `npm i -g rea-agents` 强行覆盖**：
   必须以本仓库现有已安装的 `D:\Tools` 工具链为主力，REA 仅作为架构设计参考与选配工具。
