# 端到端最薄切片（Thin Vertical Slice）

本技能管「从哪切第一刀」：把一个还没落地的新功能切到**一条能跑起来的最小闭环**，先证明链路通，再横向长功能。它产出的是一张切片清单加接口契约（输入/输出），不是完整设计文档，也不写大架构。反对 big-design-up-front：没有跑通的链路之前，任何抽象层次都只是猜测。判断入口只有一句：**切完这一刀，能不能跑起来？**

## 判据（本技能的核心）

- 若一个功能要接进既有系统 → 先切 **end-to-end 最薄闭环**（入口 → 处理 → 存储/出口各走一次真实调用），再横向铺功能；横向扩张的前提是链路上每一段都已被跑通过。
- 若「最小闭环」需要先建三层抽象 / 插件框架 / 事件总线才能跑 → 那不是最薄，是把大架构伪装成切片 → 降级：能直连就先直连，能硬编码就先硬编码，接口占位留好，实现后补。
- 若还没定接口契约（入参结构、返回结构、错误语义）就往下写 → 停；契约先落地（签名 + 字段 + 失败返回），内部实现允许 `TODO`，但**签名与返回结构后期不许改**。
- 垂直切分 vs 水平切分：判据是「切完这一刀是否有一条能跑的链路」——能 → 垂直切（优先）；不能、只是把某一层写完整 → 属水平切，只有在**该层已被证明是瓶颈或缺口**时才允许。
- 若切片依赖尚未澄清的需求（不知道验收点、不知道边界）→ 换 `../req-clarify/SKILL.md`，不要用「先做出来再说」蒙混。
- 若这一刀做完了却说不出**下一刀切哪** → 切片没结束；每次切片收尾必须写下一条切片（名字 + 一条验收点）。
- 若切片过程中引入未验证的大件（新框架/新中间件/新协议/新云服务）→ 标 `speculative`，并要求同时给一条「退回既有方案也能跑」的路径。
- 若这条最小链路只在纸面连通、从未真实运行过 → 不算切片完成（见「定义完成」）。

## When NOT to use（近邻负例）

- 需求本身还没定，验收标准写不出 → 用 `../req-clarify/SKILL.md`
- 切片已定，要动手写这一刀的实现 → 用 `../implement-feature/SKILL.md`
- 要给已切好的链路补测试 → 用 `../write-tests/SKILL.md`
- 只为一次性验证某项技术可行性、用完即弃 → 用 `../spike/SKILL.md`
- 前置条件型：连入口/出口都识别不出（既有系统无文档、无可读代码）→ 先 `../code-audit/SKILL.md` 摸清现状

## When to Pivot

信号与判据见 `../ops/skill-pivot-contract.md`。本技能去向：

| 触发证据 | 换到 |
|---|---|
| 澄清过程中发现验收标准缺失 | `../req-clarify/SKILL.md` |
| 最小链路已跑通，要开始垂直长功能 | `../implement-feature/SKILL.md` |
| 链路跑不通的根原因是既有系统行为未知 | `../code-audit/SKILL.md` |
| 需要画出切片/链路图给他人看 | `../diagram-generator/SKILL.md` |
| 引入的新件无法在本机验证（缺环境/缺凭据） | 停下，标 `speculative` 并给出回退路径，不要硬推 |

## 定义完成

本技能产出算「完成」的**外部可观测**条件（不许写形容词）：

- 一条**能跑通**的最小 end-to-end 链路：给出可运行入口（命令 / 按钮 / 请求）与一次真实运行的输出
- 接口契约落盘：输入/输出签名与错误语义（文件与函数名可被检索）
- 明确的**下一步切片**：名字 + 一条可判定的验收点
- 未验证假设清单（每条标 `speculative`）

## 输出契约

```
FACT:       <观察，带来源：命令 / 文件:行 / Evidence ID>
HYPOTHESIS: <可测试断言 + confidence: high|medium|low>（状态见 ../ops/binary-model.md）
QUESTION:   <当前最大不确定点>
NEXT:       <继续 | 换技能 | 停止（附成本判据）>
```

## 置信度词表

词表见 `../ops/confidence-vocabulary.md`。本技能特有判据：

- `confirmed`：链路的入口到出口各被真实执行过至少一次，且给出命令与原始输出
- `high`：链路跑通，但只覆盖了 happy path 的一条输入
- `low`：链路只在纸面/图上连通，未实际运行；或关键接口仍是占位实现
- `speculative`：为跑通而引入的未验证新框架/中间件/协议
