## 适用信号（Recognition signals）

- 你刚改了本包的 `../../SKILL.md`、`references/**`、`profiles/**` 中任何文件
- 你要往 `references/` 里新增一篇文档，需要判断放在哪、放多长
- 你要往 `profiles/` 里新增一个 profile，需要判断路由与依赖规则
- 你跑完一单实战，想把经验沉淀下来，但不知道该不该写、写在哪
- 有人报告「技能包好像退化了 / 路由到不存在的文件 / 结论看起来变弱了」
- 你要向别人证明「这次改动没有让技能退化」—— 需要一份可对照的通过条件

## 前置（Entry conditions）

1. **改动已落盘**。本文是对「已完成编辑」的审查，不是实施指南。
2. **知道这次改动属于哪一类**：文档改动 / 路由改动 / profile 改动 / 脚本改动 / 知识沉淀。四类的通过条件不同。
3. **能拿到自测任务套件**：`./official-self-test-task-suite.md`。没有它，「通过条件」只是一串愿望。
4. **本机没有 web 侧 MCP** —— 因此「行为层」的自测只能由**外部执行器 + 独立复核人**产出，本包自身无法生成。这是硬约束，不是可选项。

## 步骤（Working method）

### 一、静态校验（Validation）—— 改完必做

静态校验只做两件事：**解析**和**指纹**。它**不会**调用模型、不会执行候选脚本、不会替你跑那四步行为自测。因此静态 `PASS` 只能被称为「结构通过」，**绝不可**被描述为「真实前向测试通过」或「抗退化已证明」。

在宣告编辑完成之前，对 `./official-self-test-task-suite.md` 逐条对照下列通过条件。

#### 通过条件（Pass conditions）

**路由与接入**

- 路由保持 protocol-first（协议优先）：先协议后签名，不是反过来。
- 每个被判定为 `live-target` 的全新 web 目标，都必须以**顺序**的 `fingerprint-baseline` 证据、随后 `debugger-trace` 证据开头。默认顺序是 `chrome-devtools` 然后 `js-reverse`。
> （★ 本机无 chrome-devtools / Camoufox MCP —— 见 SKILL.md「来源声明」实测记录；本机基线主机是 `playwright` 的 `launch(channel="msedge")`）
- baseline 宿主**只有在**已证明存在指纹压力、或干净 baseline 失败时，才可升级到 Camoufox 或其他托管 profile。**普通低风险工作绝不默认上 Camoufox。**
- `artifact-only` 的 web 路线**不得编造**浏览器证据。
- APK / app / 小程序作为主要目标的任务，保持在本包纯 web 范围之外。
- 接入路由区分 `live-target` / `artifact-only` / `continuation` 三者，不强行做仪式化的浏览器启动，也不编造线上证明。
- 「缺失证据」的请求保持最小化 —— 只问缺的那一条，不派一大包作业给用户。
- 所选参考文档匹配**真实症状**，而不是generic cargo-cult 式的一把梭加载。
- 环境诊断报告项目根、虚拟环境一致性、运行时版本，以及**明确请求时**的 lockfile 指纹；不含硬编码机器路径，也不默认拒绝全局解释器。
- 产出报告要写真实端点、真实活动部件（moving parts）和证明产物。

**成对证据与生命周期**

- 成对证据保持**顺序**：同一时刻只有一个族持有 `TARGET_ACTIVE`，两个族**绝不**出现在同一个并行工具批次里。
- 生命周期措辞区分「`PARKED`（已挂起）」与「已确认关闭」，并用 `RETAINED_EXCEPTION` 保留唯一且不可重放的状态，而不是把它销毁。
- 浏览器模式与清理指引反映**已安装的工具能力**，不编造 `close_browser`、headless、headful 或 CloakBrowser 控件。
- 浏览器获取角色是能力感知的，允许**顺序交接**，绝不退化成「全案锁定某一条厂商路线」。
- hook 时机指引区分 preload / early-breakpoint（早期断点）/ controlled-reload（受控重载）/ post-load-only（仅加载后）四类证据，不编造不可用的方法。
- 紧凑重放与采集器交接摘要覆盖端点、活动状态的 writer 与 slot、会话刷新、证明、运行时拆分、已保存路径，**不 proliferate（ proliferating）项目文档**。
- 输出报告写真实端点、真实活动部件与证明产物。

**工具与能力**

- 工具手册只包含受支持的核心方法或显式的可选方法回退；每个 `live-target` 闸门都产出一份 capability snapshot（能力快照）。
- 环境提供方「启动了浏览器」不等于协议成功。被动抓包、PCAP 可见性同样不等于采集器证明。
- 缺失的可选工具通过**记录在案的能力快照**路由到受支持的回退。
- 运行环境不一致的用例要能区分「缺失表面」「加载顺序契约」「宿主对象契约缺口」，且**不把加载成功当作最终证明**。
- 加载顺序契约成立时，一段正确的 patch 在错误时机加载，失败程度和缺失 patch 一样重。

**契约与授权**

- 官方任务被**结构化解析**为 prompt（提问）、expected routes（预期路由）、required conclusions（必备结论），而不是只按标题校验。
- 官方套件的规范化契约摘要覆盖每一条任务的 prompt、路由、结论与失败信号；**只有在刻意审阅过套件之后**才更新它。
- 能力特定的交付闸门允许诚实地以 `evidence` 或 `local-proof` 完成，不强加「必须采集器重放」或「必须入口点」的要求。
- provider（供给方）写入要求：可写模式、非空的继承 `allowedPaths`、解析后的包含关系检查、reparse point（重解析点）拒绝。
- 实现简报（implementation brief）对**有歧义或会扩大授权**的 `compact-replay` / `collector` 工作才是条件式的，且绝不阻塞有界的 `evidence`、`local-proof`，也绝不阻塞用户**已经做出的**实现选择。
- 默认可信自检**从不执行**候选脚本；`--run-trusted-self-tests` 只对当前可信根使用。
- 可信自检递归拒绝符号链接、重解析点、硬链接依赖、以及整个本地 `scripts/` 树中的根逃逸，然后在超时时终止其进程树。
- 静态 Python 校验递归解析缓存目录外的每一个随包 `.py` 文件，包括测试与可复用示例。
- 工具生成的缓存（`.pytest_cache`、`.ruff_cache`、`.mypy_cache`、`__pycache__`、`.cache`、`htmlcov`、`node_modules`、venv）**算包错误**；扫描器可以跳过它们的内容，但**仅为避免重复噪声**。
- 生成的本地垃圾（`.pyc`、`.log`、`.tmp`、`.DS_Store`、覆盖率文件）与测试运行器转储（`tests/_err_*.txt`、`tests/_out_*.txt`）**算包错误**，且必须保持 gitignore。
- 跑单元测试时设 `PYTHONDONTWRITEBYTECODE=1`（`tests/conftest.py` 也强制这一点，它在会话结束时自动清理泄漏的缓存/转储）。
- 清除已知脏文件后重新校验：`python scripts/validate_skill.py --clean-hygiene`。
  > **本包实际做法**：本包没有 `scripts/` 目录，该命令**不可用**。改为人工执行等价动作：在 `C:\relab2\skillpack\skills\web-protocol-reverse` 下检查并删除上述缓存/垃圾目录，确认 `.gitignore` 覆盖 `.pyc`/`.log`/`.tmp`/`.DS_Store`/`tests/_err_*.txt`/`tests/_out_*.txt`，再重跑结构解析（本包无 `.py`，此项自然为空）。
- `agents/openai.yaml` 能按 YAML 解析，带有类型的 `interface` 元数据、25–64 字符的短描述、`$spider-king` 默认提示词，以及布尔型隐式调用策略。
  > **本包实际状态**：本包无 `agents/` 目录，此条**不适用**。
- 最终交付**永不**依赖浏览器自动化。
- 最终交付是 **Python 采集器优先**，JS 仅限本地参数还原。

**结构与卫生**

- 入口 `../../SKILL.md` 保持精简，只负责路由到详细参考，**不复制**它们的正文；新的可复用知识只放进最具体的那一篇 playbook/reference。
- **每一篇超过 100 个逻辑行的 Markdown 参考，都必须保留顶层 `## Contents` 目录段。**
  > **本包的实际做法**：本包统一采用六段式 + 中文导航，目录由 `../../SKILL.md` 与 `references/` 索引承担。六段式的「适用信号」段即为导航入口。源文档的英文 `## Contents` 块在改编时按改编规范删除 —— 保留它会与本包六段式结构冲突。此条已按本包形态重新解释。
- 每个 profile 交接都是能力感知的：有已安装的专用工具就用它，没有就点名一个可执行的 Spider 回退。
- 每个 profile 局部的 `references/` 或 `scripts/` 路由，能从 profile 根**或**技能根解析成功。
- profile 依赖安装**只**发生在经批准的任务本地副本中，**绝不**在技能目录里。

**前向测试证据（Forward-test Evidence）**

行为层结论的证据契约见 `../triage/forward-testing-playbook.md`。校验器不调用模型、也不执行任意命令：它只核验一份**已经产出**的报告、当前的 `../../SKILL.md`、包哈希、官方套件哈希、每一份响应产物，以及每一条独立的路由/结论判断。

- `scope=smoke` 可以覆盖一个刻意挑选的子集，且**只能**报告为 smoke 证据。
- `scope=full` 必须包含全部 160 条唯一官方任务，才能报告为全套件通过。
- 执行器与复核人身份必须不同；两个上下文都必须是全新的，且复核必须显式独立。
- 每一条路由与结论判断都需要在被引用的响应文件里找到**精确摘录**。
- 响应文件留在报告目录下，且不得是符号链接、重解析点、硬链接或路径逃逸。
- 报告与响应产物保存在技能包**之外**；不得把静态校验变成行为结论。

**报告脱敏**

- 报告默认脱敏，并要求一个**无秘密**的 `analysis/proof_manifest.json`。
- 报告脱敏要求与本包 `../../../field-journal/_template.md` 的「契约对齐（review_case.py）」一节同源：若本次改动产出了独立证据目录 `evidence/E-xxx.md`，须满足 `../../../case-review/scripts/review_case.py` 的字段契约（`severity` ∈ critical/high/medium/low/info/n/a；`status` ∈ observed/candidate/validated/false_positive/accepted_risk；`repro_command` 必填；`content_hash` 需配套 `artifact_path`；`linked_workitem` → 真实存在的 `WI-xxx`），并以 `--verify-hashes --strict` 自检：
  ```powershell
  D:\EXE\python\python.exe skillpack\skills\case-review\scripts\review_case.py work\<case> --verify-hashes --strict
  ```
- 静态 `validation=PASS` 只是结构结果，**绝不可**被描述为真实前向测试或抗退化证明。
- 行为结论需要一份由**全新执行器**产出、并经**独立复核人**签署的前向测试报告，且该报告保存在技能树之外。
  > **本包实际做法**：源文档写的 `scripts/forward_test_report.py` **在本包不存在**（本包没有 `scripts/` 目录）。实际做法是：由人工或外部执行器按 `../triage/forward-testing-playbook.md` 的契约组织一份报告目录（报告 + 每条任务的响应文件 + 执行器/复核人身份声明），保存到 `C:\relab2` 工作区内、技能树之外的位置，再按上面的 `scope` / 身份分离 / 精确摘录 / 响应文件约束逐条人工核对。本包自身不提供自动校验该报告的脚本。

**协议能力与交付正确性（当目标具备相应特征时）**

- 结构化传输、解码链、有状态会话与交付闸门，在目标具备这些特征时被正确处理。
- 挑战生成的状态与共享信封族（envelope-family）用例，在具备这些特征时被正确处理。
- 传输前置闸门、挑战产物采集与路由局部旁路，在具备这些特征时被当作**通用模式**处理。
- 原生传输升级要求：多次运行时捕获、已证明的后端表达力缺口、路由局部范围、以及干净包重放。

**可复现经验闸门（Reproducible Experience Gate）**

字段与存储生命周期见 `./experience-card-schema.md`。在把一条实战教训提升为「通用经验」之前：

- 一次性结果先留在任务本地，直到同一不变量在**两个独立任务**中复现。
- 附一个最小的、无秘密的 fixture 或确定性生成器，并记录其路径与 SHA-256。
- 定义一个**正向 oracle**，它检查决定性的下游行为，而不只是「helper 加载成功」或「输出形状看着对」。
- 定义一个**负向对照**，它会因为预期的协议原因而失败。
- 记录第一处发散的状态转移，以及这条教训**不再适用**的边界。
- 把复现的不变量提升为经验卡；只有当同一决定或同一确定性操作在**独立案例**中仍然有用时，才提升为通用 playbook 或 helper 脚本。
- **不把**纯文字提示、拷贝来的线上产物、或未评分的成功重放算作可复用经验。

### 二、沉淀规则（Deposition Rules）—— 逐条保留，一条不落

一次成功任务之后，**只保留可复用的那条教训**。下面是完整的 123 条规则。**每一条都是一条通用教训，不是某个站点的八卦。** 规则形态统一为「保留 XXX 教训：作为 <规则类别>，而不是 <错误的固化形式>」。

#### 通用化与呈现层

1. 保留**站点特有痛点 → 通用模式语言**的转化教训：把站点特有的痛点转成通用模式语言，而不是记录「站点 X 的页面长这样」。
2. 保留**族级分诊教训**为通用路由规则，而不是保留某一族的样本。
3. 保留**观察者效应教训**为通用路由规则，而不是保留单次观察的结论。
4. 保留**壳与数据之分**为「渲染契约」规则，而不是「站点 X 的 HTML 看着是空的」。
5. 保留**成功标志教训**为「响应校验」规则，而不是某厂商的 `errorCode`。
6. 保留**症状与根因之分**的教训：一个可见的滑块、短信墙或验证页，可能只是「缺失信任或 bootstrap 状态」的下游呈现，**不是第一个该攻的闸门**。
7. 保留**固定输入校验习惯**，而不是端点琐事。
8. 保留**verifier（验证器）分解教训**为 protocol / compute / perception / behavior 四路路由，而不是某个验证码项目的目录结构。

#### 环境、加载与宿主对象

9. 保留**干净匿名 baseline 教训**为「环境选择」规则，而不是拷贝来的账号 cookie。
10. 保留**请求绑定日志教训**：绑定到目标、事件、方法、URL、字段或调用者的值，比裸转储更好用。
11. 保留**方法参数与返回对象教训**：决定性的缺口可能藏在调用参数或子对象形状里，不只在具名属性读取上。
12. 保留**仅观察（observe-only）教训**：默认 hook 应当保持原有行为与返回路径 —— 除非「变更行为」本身就是那个实验。
13. 保留**页面状态与请求状态之分**为两类独立的活动部件，而不是厂商的 header 名字。
14. 保留**加载顺序教训**：环境表面、polyfill、hook、init、trigger 可以构成一份本地契约 —— 正确的 patch 在错误时机加载，失败程度和缺失 patch 一样。
15. 保留**宿主对象契约教训**：名字存在之后，接着证明 descriptor（描述符）、原型链、构造函数同一性、枚举性，以及看起来像原生的表面，然后才去加更多全局对象。
16. 保留**patch 分层教训**：先稳定基础 DOM 与 BOM，再做 descriptor 与返回对象契约，最后才在高熵指纹表面上动手 —— 且只在证据证明它们重要时才做。
17. 保留**生命周期语义教训**：宿主对象可以通过「实时集合长度」「索引槽持久性」「attach-detach 行为」来检查，而不必只看「名字在不在」。
18. 保留**原生表面缺口教训**为环境路由规则：当 cookie、storage 与脚本注入都没能补上缺口时，先测 `canvas`、WebGL、layout、style 与原生描述符表面，**再**考虑升级到更宽的模拟。
19. 保留**配置归一化教训**：bootstrap config 可能把 key、iv、salt、hash 或 cookie 形状输入藏在切片、拼接、去空白或嵌入常量步骤后面，而不是直接暴露最终值。
20. 保留**紧贴引擎教训**：在 Node、jsdom 或一层薄 shim 下失败，**不能证明**某个 VM 只能在浏览器里跑；要记录「在更贴近的本地引擎或内嵌运行时下问题就塌掉了」。
21. 保留**引擎版本钉死教训**：当 helper 的一致性依赖原生表面形状、内建可用性或函数属性表面时，钉死并校验确切的本地引擎版本，而不是假设诊断用运行时与随包运行时可以互换。
22. 保留**本地宿主运行时路由教训**：把「何时手写 Python 就够」「何时本地宿主运行时是最便宜且最忠实的 bootstrap」「何时需要真实交互（意味着采集器仍不完整）」写成路由规则。
23. 保留**浏览器无关 vs 运行时无关之分**为交付闸门规则：内嵌宿主可以是可接受的中间阶段，但**不满足**「显式移除运行时」这个目标。
24. 保留**运行时一致性教训**：解释器解析、项目本地环境、工具版本、lockfile 来源检查，而不是硬编码工作站路径。

#### 会话、身份与状态合同

25. 保留**服务端下发状态教训**为「清单 + 范围 + 有效期 + 刷新路径」规则，而不是拷贝来的 session id 或挑战配置。
26. 保留**cookie 溯源教训**为「写入方 + 刷新路径」规则，而不是拷贝来的 cookie 值。
27. 保留**签名者边界教训**：当「一条经过 hook 传输层的合成请求自动拿到了签名参数」时，把**注入边界**与**业务 payload schema** 分开记录。
28. 保留**观察边界教训**：一条安静的 cookie / storage / header / request hook 只澄清了**一个**写入方边界，不代表清掉了所有下发路径。
29. 保留**混合传输教训**：某一条 `fetch`、XHR、wrapper、worker 或 message channel 上没动静，**不能证明**兄弟通道也是死的。
30. 保留**证据表面分离教训**：initiator/source trace 证明逻辑住在哪，wire/egress 证明什么跨过了边界，环境 trace 证明宿主真相，下游业务重放证明实际是否被接受。
31. 保留**页面自有世界教训**：console 或 isolated world 的漏检可能是工具侧局限，所以**在页面自有世界里重复证明之后**再删掉假设。
32. 保留**页面状态 vs 请求状态**为两类活动部件（见上第 13 条）。
33. 保留**会话准入教训**：一个 mint 出来的 cookie 或「当前用户」成功，可能只证明了 bootstrap 可达，**没有**证明业务权限。
34. 保留**下发方可重放性教训**：在「从零重建下发方」之前，先重放一条**捕获到的下发 payload**，这样你才知道是否真的需要线上重新生成。
35. 保留**授权授予 vs 会话教训**：一个成功信封、重定向句柄或票据，在业务访问生效之前可能仍需做认证后的会话实体化（materialization）。
36. 保留**上下文分层教训**：认证会话与「当前租户/店铺/组织/工作区」上下文，可以是两个各自可变、并发语义不同的层。
37. 保留**会话链完整性教训**：首跳 HTML、初始 cookie、生成状态、preflight token、签名参数与重放请求，必须在**同一条会话链**上被证明，然后才能宣布任何产物可复用。
38. 保留**bootstrap 收敛教训**为「下发 vs 消费」规则：注入或刷新服务端下发状态，只做到**重放真正需要的程度**，而不是照原页面走到的那一步。
39. 保留**bootstrap 资产连续性教训**：关联的挑战资产必须在**同会话、同源、同 header** 条件下获取，而不是拷贝来的 runner URL。
40. 保留**响应侧刷新教训**：业务响应上的应用挑战 subcode 与种子元组，可能是**同路由刷新契约**，而不是「这个端点本身就错了」的证据。
41. 保留**续做前同族扫描教训**：在重新打开一个长期逆向之前，先在工作区里搜一遍是否已有**同目标族**的纯协议采集器或挑战 helper。

#### 挑战、验证器与风险面

42. 保留**挑战重写教训**：返回挑战 HTML 的业务 API，常常在 cookie 或加密重建之前就把「一个被导航的 URL」作为决定性产物发出来了。
43. 保留**挑战生成 cookie / storage / token 教训**为 bootstrap 状态规则，而不是拷贝来的值或浏览器 profile。
44. 保留**挑战运行时教训**：getter/egress 采集规则、调度保持规则、旁路路由规则，以及按错误类别区分的 patch 规则。
45. 保留**拦截 vs 重建教训**：如果运行时**已经**发出最终加密 body、包装 payload 或决定性 header，就记录**最近的那个稳定采集边界**与 Python 重放路径，而不是执着于完整重建内部加密。
46. 保留**共享信封教训**为 packet family 规则：版本、校验和、自定义字母表、状态派生前缀、内层 cipher、payload 锚点。
47. 保留**拦截边界选择教训**为权威拦截规则：当运行时在你脚下不断重写对象时，原型、构造函数、wrapper ingress 与 egress 打得过可被绕过的实例 hook。
48. 保留**verifier 成功范围教训**：verifier 端点成功可能是**中间态**，下游业务接受才是最终权威。
49. 保留**verifier 族教训**：滑块、点选与风控流在页面层面看着相似，但状态模型与 proof builder 可能互不兼容。
50. 保留**verifier 轮次教训**：token、回调、图片与最终 proof 属于**同一轮**，应作为一整体归档与重放，而不是从邻近样本里混搭。
51. 保留**混合 verifier 顺序教训**：verifier 产物可能属于**签名前或加密前的明文**，而不只是签名器跑完之后追加的最后一个字段。
52. 保留**verifier sidecar 教训**：在同一轮里枚举 warm-up、device、log、status 与 telemetry 路由，然后用「一次只去掉一个变量再放回去」的对照证明必要性。
53. 保留**baseline 差量教训**：先证明共享 verifier 状态的 profile / session / round 作用域，然后从**一个一致的实例**推导出完整 baseline、稀疏 delta、计数器、时间戳与校验和，而不是各自随机化各个包。
54. 保留**真实时间线教训**：区分 payload 时间戳、事件间隔与真实墙钟请求间隔 —— 当「经过的交互时长」本身是 verifier 接受条件的一部分时。
55. 保留**动态资产教训**：在把一个变化的路径当成新算法之前，先比较活跃资产哈希、公共 helper 边界、固定向量与阶段 trace。
56. 保留**verifier 接受层教训**：把 sidecar 确认、最终 verifier 语义、下游消费、项目内错误含义，当作**互相独立**的证据层。
57. 保留**图像预处理与视觉 QA 教训**为感知表面规则，而不是某一张 sprite 的布局或裁剪配方。
58. 保留**提示词 vs 几何教训**：有序点选 verifier 需要**分别**处理提示识别、背景定位与 proof 打包。
59. 保留**弱强制教训**为路由容忍度规则 —— 而不是宣称「sidecar 字段或轨迹 blob 永远无所谓」。
60. 保留**verifier 错误定位教训**：结构、sidecar、一致性、时间线、答案、环境是**有顺序的**表面；厂商代码码保持任务本地。
61. 保留**环境风险教训**：出口信誉与连续拒绝，是与「算法回归」**分开的一张失败面**。
62. 保留**正向样本卫生教训**：被自动化污染的失败，**首先**是环境证据，不是轨迹真相。
63. 保留**族证据门槛教训**：族专用脚手架与 playbook 需要**多于一个证据表面**的佐证，而不是一个走运的标记。
64. 保留**惩罚性伪装教训**：当请求节奏过于激进时，限流或滥用冷却会**伪装成**密码错误或字段错误。

#### 传输前置闸门与指纹

65. 保留**本地噪声 vs 闸门教训**：名字长得像服务器的字段不能证明它由服务器下发；要证明写入方、容忍度与阻塞值。
66. 保留**本地 mint 状态教训**：长得像 session 或指纹的 cookie，可能就是本地协议产物（精确 UUID、摘要或紧凑 JSON 结构），而不是拷贝来的 `Set-Cookie` 值。
67. 保留**槽位放置教训**：一个 blob 可以在**值上正确**却在**位置上错误**；字段放置是协议契约的一部分。
68. 保留**传输前置闸门教训**为「窄准入矩阵 + 路由局部例外」，而不是冻结的厂商 UA cargo cult。
69. 保留**pre-HTTP 身份教训**：拷贝来的 `User-Agent`、header 或 cookie，**通不过**那些在正常请求语义存在**之前**就由 ClientHello 或 HTTP/2 profile 决定的闸门。
70. 保留**传输摘要教训**：JA3、JA4 或类似哈希只是更深传输契约的**摘要** —— 要存原始 ClientHello、ALPN 与 H2 规则，而不是一个走运的哈希。
71. 保留**最贴近栈教训**：优先选最近的真实传输族，或一个窄的路由局部适配器，而不是逐字段手改一个遥远的默认 TLS 栈。
72. 保留**运行时优于枚举教训**：已实现的 cipher、group 或 extension，在 enablement、policy、platform、ordering 与抓包一致之前，都**不是**出站 profile 的证据。
73. 保留**一致 profile 教训**：各自独立随机化的 cipher、extension、group、ALPN 或 H2 设置，可能造出一种**没有任何真实浏览器会发出**的客户端族。
74. 保留**代理终结教训**：先证明 CONNECT 隧道是端到端 TLS，还是中间人替换了 ClientHello，然后再把指纹归因给本地后端。
75. 保留**传输形态与解码链教训**为通用参考，而不是逐站点笔记。

#### 序列化、包族与媒体

76. 保留**完整请求序列化教训**为规范输入规则：query 顺序、空字段、编码方式，都可能是契约的一部分。
77. 保留**原始 body 序列化教训**：某些老式表单端点在意的是**前端字节流的精确形态**，而不只是等价的键值语义。
78. 保留**兄弟路由族教训**：一旦解开了 packet family 里的**一条**路由，就先探测相邻的 list / detail / download / export 方法，再去另找新 crypto。
79. 保留**构建顺序教训**：当顺序重要时，记下 `payload → 紧凑 JSON → 签名 → 时间戳 → 加密 → 包装` 这类顺序。
80. 保留**JSONP 与 callback wrapper 教训**为 framing 规则，而不是某一个回调名。
81. 保留**公共 bootstrap 与加密信封教训**为可复用清单，而不是厂商秘闻。
82. 保留**会话 bootstrap、帧族与媒体密钥教训**为通用参考，而不是某个聊天应用的花边。

#### 交付形态与运行时

83. 保留**原生包教训**：原生 adapter 必须保留池化会话行为、硬超时、有界 body、带类型的诊断信息、wheel 来源证明，以及干净环境下的加载。
84. 保留**本地挑战执行器教训**为「Python 拥有的 HTTP + 最小宿主 I/O 契约」，而不是浏览器自动化。
85. 保留**声明式宿主输入教训**：当还原出的签名器**只把这些浏览器形状的值当数据字段消费**时，它们可以保留为显式的 config 输入。
86. 保留**确定性 vs 线上教训**：一条固定种子的重放路径可以证明逆向成立，而另一条线上生成路径负责真实流量。
87. 保留**请求形状产物教训**：后缀、header、token 以及与页面、关键词、body、referer 或时间戳绑定的 cookie header，属于**线上请求循环内部**，而不是某一次过期的预计算。
88. 保留**自助式 helper 教训**：只抽取所需的常量与变换，而不是 import 一堆依赖运行时、会把隐藏依赖一起唤醒的前代代码。
89. 保留**稳定脚手架 vs 易变捕获教训**：把用户维护的 fixture 与 helper 接线，同「新鲜捕获的目标产物」与「每次运行的运行时 blob」分开存放。
90. 保留**内层原语教训**：如果编排胶水层失败，就把下面那个更底层的序列化器、打包器、签名器或导出 salvage 出来，而不是把整条 SDK 路径一起丢掉。
91. 保留**响应优于回调教训**：如果决定性数值住在某个响应或状态写入里，就去建模那个**权威写入方**，而不是把脆弱的回调编舞凝固下来。
92. 保留**VM 边界教训**：先去映射 VM 的公开输入、输出、wrapper 返回、状态写入与请求出口，再去动 opcode handler 或解释器内部。
93. 保留**稳定分发教训**：在公开边界已被证明不足之后，先追踪**有序的**模式或变换输入输出，再把仪器化范围扩大到 opcode 级。
94. 保留**原子 profile 教训**：保持一次成功运行时捕获的内部一致性，保留带来源的不透明块，并要求在跨运行拼接片段之前先有**反向证据**。
95. 保留**交付真相教训**：区分「算法生成」「快照驱动生成」「池化重放」三种形态，而不是把所有浏览器无关路径都描述成「纯生成」。
96. 保留**池控制教训**：把已接受的产物池当作诊断对照或显式的有界回退；要求一次「无池」测试，并把「目标侧拒绝」与「传输异常」分开。
97. 保留**错误阶梯教训**为调试规则：变化的 subcode 是**进展标记与下一闸门提示**，不只是噪声。
98. 保留**坐标空间教训**：还原图像的像素、渲染 UI 的坐标、提交的 proof 字段，可能处在不同空间里 —— 即使它们描述的是同一个缺口或同一次点击。
99. 保留**分页路由 pivot 教训**为路由族规则，而不是拷贝来的分页 URL。

#### 数据面、来源与内省

100. 保留**证据面 vs 原始源码**教训为「行内路由元数据以源码为准」的规则，而不是某个特定解析器的 hack。
101. 保留**分阶段水合教训**：尽早枚举稳定 id、持久保存原始解码 payload、把昂贵的详情路由**单独回填**，等下游规则演进时再处理。
102. 保留**async 观察教训**：在触发那个发出决定性产物的事件**之前**，先建立 baseline 邮箱 / webhook / 队列 / 回调的观察。
103. 保留**微型桥教训**：当 Python crypto 或序列化器与已验证的前端 JS 出现漂移时，把桥保持得**又小又本地**，而不是发布一个半对的移植或一个更大的隐藏运行时。
104. 保留**跨运行时一致性教训**：把 JS helper 移植到 Python 时，保留确定性向量与中间检查点，好让线上重放由**证明**支撑，而不是靠「看起来相似」。
105. 保留**外部缓存不是输入教训**：外来的高熵指纹缓存不是运行时输入（foreign high-entropy fingerprint cache ≠ runtime input）。
106. 保留**混合身份元组教训**：一个混合了外域身份的元组会导致**后续**路由失败 —— 这在早期看不出来。
107. 保留**helper 完整性教训**：损坏的本地运行时、拷贝来的包树、占位的链接文件、路径解析损坏，都会**伪装成**目标侧拦截；在改动逆向假设之前先把它们分离出来。
108. 保留**本地 helper 桥不得拥有任意出口教训**：helper bridge 只能发它被授权的那几类请求，不能成为任意 egress 通道。
109. 保留**出口准入门面教训**：以出口为准的访问拒绝，不是算法回归（exit-gated access denial ≠ algorithm regression）。

#### 交付闸门、升级与文档

110. 保留**证据优先 vs 源码实现表教训**：运行时捕获胜过源码里的实现表。
111. 保留**指纹随机化教训**：指纹随机化不等于浏览器真实度。
112. 保留**代理可能替换被测指纹教训**：中间代理可能替换掉你以为在被测的指纹。
113. 保留**原生 helper 加载成功不是传输交付教训**：helper 在 Node 里加载成功，不等于它在原生传输链路上工作。
114. 保留**多阶段 sidecar 教训**：多阶段 sidecar 链**不能**在第一次 POST 之后就停。
115. 保留**sidecar 成功不是业务成功教训**：sidecar 返回成功，不等于业务接口接受。
116. 保留**最终状态值缺少转移顺序教训**：只有一个最终状态值、却没有转移顺序，不是溯源（provenance）。
117. 保留**前置式 verifier 重定向教训**：业务 API 返回的导航 URL 可能**先于** cookie 或加密重建就给出了决定性产物。
118. 保留**固定 trace 纯 Python 重建教训**：先有 fixture，再做重建。
119. 保留**artifact 证据 + URL 的教训**：有 artifact 证据和 URL 时，**先走离线**。
120. 保留**裸 URL 不是线上重放许可教训**：用户给一个裸 URL，不等于授权你去线上重放它。
121. 保留**非空签名 + 一个 200 不等于验收教训**：见 `./official-self-test-task-suite.md` 中 Task 0U 的具体判定。
122. 保留**历史案例复用教训**：复用历史案例需要**独立信号**佐证，不是凭相似就套。

#### 反模式与知识沉淀

123. 保留**反模式教训**为反例：同一个诱人捷径反复出现时，**点名这个诱惑**、解释它为什么是假进展、记录最小诚实的一步，并以一个直接的自检收尾。
124. 保留**升级阶梯教训**：记录「还有证明支撑的最后一档」、**迫使**升级的那个确切失败，以及为什么下一档是最小诚实的一步。
125. 保留**最小可验证事实教训**：当某个族很可能复发时，存下 5 到 15 条**结构性事实**，可以在升级后逐条复查，而不是只写一段叙述性总结。
126. 保留**更贴近的输出不是成功教训**：输出「更接近」不等于成功。
127. 保留**临时捷径措辞应触发反模式库教训**：一旦回答里出现「临时」「先凑合」这类措辞，就应转去 `../principles/anti-patterns-playbook.md`，而不是把它当作豁免。
128. 保留**实现简报教训**为「真正有歧义或需要扩权时才写的决定记录」，而不是强制的阶段仪式。
129. 保留**敏感产物教训**：脱敏报告、仅本地存放的秘密、带哈希的 proof manifest，而不是拷贝来的凭据或 cookie。
130. 保留**双写者教训**：同一个字段名可能有「短命研究写者」和「长命 wire 成功写者」两类；**只交付线上被接受的那一类**。
131. 保留**独立闸门教训**：应用签名器与挑战 verifier 可能**同时**出现，但对某条重放路径而言**只有一个是必要的**。
132. 保留**AST 路线教训**：供给的 JavaScript 走非执行式 AST 路线；AST 解析失败时**原样保留源码**。
133. 保留**动态重建需要第二个独立样本教训**：只靠一份样本做出的动态重建不算证明。
134. 保留**CryptoJS cipher hook 只产出元数据教训**：hook 到 cipher 只给你元数据，不给你明文语义。
135. 保留 **gRPC 分帧教训**：分帧需要长度与 trailer 的**负向对照**才能确认。
136. 保留 **crypto 原语名不定义 wire 格式教训**：`AES-CBC` 这个名字不等于 wire 上的字节布局。
137. 保留**窄环境运行时契约教训**：窄 env runtime 契约保持显式且有界，不外溢。
138. 保留**一次成功任务仍只是经验候选教训**：见 `./experience-card-schema.md` 的可复现经验闸门。
139. 保留**专家交接不能扩权教训**：专家（specialist）交接只转移工作，不转移授权。
140. 保留**证据有自己的完成闸门教训**：证据的完成标准与最终交付的完成标准不同。
141. 保留**provider 写入路径是强制白名单教训**：写入路径受 `./provider-work-order.md` 的 `allowedPaths` 白名单约束。
142. 保留**静态 AST 依赖保持任务本地教训**：静态 AST 分析的依赖保持任务本地，不进包。
143. 保留**静态校验不执行候选代码教训**：静态校验只解析，不执行。

#### 结构偏好（收尾两条）

144. **优先**在根级新增通用参考，而不是新增站点专属的案例文件。
145. **只有当** helper 脚本能改善许多未来任务（而不只是当前这一个目标）时，才新增它。

## 常见坑（Common traps）

- **把静态 `validation=PASS` 当成抗退化证明**。静态校验只解析和指纹，碰不到模型行为。
- **新增站点专属案例文件**，而不是往根级通用参考里加一条规则。124/145 条沉淀规则里几乎没有一条该写成站点笔记。
- **同时把两个证据族放进同一个并行工具批次**。`TARGET_ACTIVE` 只能有一个持有者。
- **把 `PARKED` 写成「已关闭」**，或者干脆把不可重放的状态销毁掉。用 `RETAINED_EXCEPTION` 保留它。
- **引用 `references/xxx.md` 这种平铺路径**。本包没有这种布局，实际是 `references/<group>/<name>.md`。写之前确认文件存在。
- **引用不存在的脚本**（`scripts/validate_skill.py`、`scripts/forward_test_report.py` 等）。本包**没有 `scripts/` 目录**。要执行校验动作，就写实际可执行的人工步骤。
- **为了「显得完整」而强行给每个交付写一份实现简报**。简报是条件式的，写多了它就不再携带信号。
- **把「helper 加载成功」当成「证明完成」**。见 `../deliver/delivery-gate-playbook.md`。
- **默认上 Camoufox**。它只在已证明的指纹压力或干净 baseline 失败时才该升级。
- **为了小 bug 派一大包人工检查给用户**。缺失证据的请求必须保持最小化。
- **把知识抄进 `../../SKILL.md`**。入口只负责路由。
- **沉淀了经验却没同步 `../../../field-journal/KB-INDEX.md`**。那等于没沉淀 —— 索引是检索入口。
- **把笔记连同站点 URL、账号 cookie、挑战配置一起留下**。沉淀规则的价值恰恰在于「不留下这些」。
