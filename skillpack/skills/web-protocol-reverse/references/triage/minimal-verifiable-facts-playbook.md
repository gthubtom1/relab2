# 最小可验证事实手册（Minimal Verifiable Facts Playbook）

> **来源声明**：本文改编自外部仓库 `aoyunyang/spider-king-skill`（MIT License）的 `minimal-verifiable-facts-playbook.md`。原始内容为英文原文，此处译为中文并按本包六段式规范重排；技术术语保留英文原词并附中文。
>
> **什么时候用**：解决了一个目标、目标做了升级、或同族路由教会了你一件「以后一定会再遇到」的事。
>
> **目标**：保住一小套事实，让它能熬过记忆漂移（memory drift），并让未来的 diff 变得便宜。
>
> **数量约定：记录 5 到 15 条最小可验证事实。** 少于 5 条通常还太含糊；多于 15 条通常又变回「笔记」而不是可复用的检查点集。
>

---

## 适用信号（Recognition signals）

- 刚破解了一个目标，准备收工 —— 现在是沉淀的最好时机
- 服务端「更新」了，之前解好的东西开始报错
- 同族路由上又遇到了几乎一样的问题
- 你担心「下次再来这个站我什么都不记得了」
- 现有笔记已经长成了没人能读的长文

## 前置（Entry conditions）

- **至少有一次成功 replay**，并且它能被复现两次。没有被证明过的东西不能写成事实。
- 有一个能放笔记的地方。建议 `js_reverse_cache/tasks/<task-id>/report.md`（任务局部）或本包内对应手册（可迁移的经验）。

## 步骤（Working method）

### 什么是一条好事实（What a good fact looks like）

一条好事实：

- **能从抓包、运行时工件或本地重放中观察到** —— 不是推测
- **是二值或可测量的** —— 能判断「是/否」「长度 248」「前 8 字节」
- **稳定到可以在后续运行里重新校验**
- **绑定在协议边界上**，而不是「关于这个页面」的故事
- **可以安全存储**：不含密钥、活 cookie、完整浏览器状态

### 什么**不是**一条好事实

不要把下面这些当事实存下来：

- 拷贝来的密钥
- 活的 cookie 值
- 完整会话头
- 「看起来像 Firefox」
- 「Python 失败了所以我们用了运行时」
- 没有任何可复检边界的长篇叙述

> **那些是笔记，不是可验证事实。**

### 事实类别（Fact categories）

选**能覆盖这个家族**的最小组合。

#### 入口与 bootstrap 事实（Entry and bootstrap facts）

例：

- 第一个响应是**被挑战的文档**，不是最终 API
- 同一个文档 URL 在**本地 bootstrap 之后**变得可重放
- 只需要**一个**链接出来的挑战资产，不是整棵 bundle 树
- 业务路由本身**先返回一个机器可读刷新 tuple，然后在同一路由族上本地重新生成之后才成功**

#### 真实请求事实（Real request facts）

例：

- 真正的列表路由在**第 5 页之后**变成 `/ui`，不是静态文件名族
- 有用的数据来自**同族 API**，不是页面上那个详情页
- 协议契约住在 **GraphQL 信封字段**里，不在 URL 上

#### 位置事实（Placement facts）

例：

- 反 bot 的 blob 住在**自定义 header** 里，不是 `ETag`
- 决定性 cookie **只以出站 `Cookie` 头的形式**才起作用
- 封装后的载荷被放进**一个外层字段**（例如 `param`）

#### 工件形态事实（Artifact-shape facts）

例：

- token 是 URL-safe Base64，长度稳定在 248 附近
- 响应前缀是真实载荷锚点之前**固定 8 字节**
- cookie 形态里包含一个**校验和段**或**定宽拼接**
- `document.all.length` 会随某个元素挂载/卸载而变
- `iframe.contentWindow` 只在 iframe 保持挂载时存在

#### 解码与封装事实（Decode and framing facts）

例：

- 解码顺序是 去前缀 → Base64 → protobuf
- **紧凑 JSON 的字段顺序**在签名前有影响
- URL query、body、响应**共享同一个报文族**，只是字段有各自变体

#### 会话与 bootstrap 事实（Session and bootstrap facts）

例：

- 链接出来的 bootstrap 资产**必须留在同一条会话链上**
- 页面播种的状态与**请求作用域**的 signer 状态是**两个不同的活动部件**
- 一个全新的匿名会话能建立传输可达性，但**不能**建立业务准入

#### 验收事实（Acceptance facts）

例：

- **一条全新会话的单页重放连续成功两次**，才可以尝试分页
- 该路由在**公开路径上接受简化 sidecar，但在业务路径上不接受**
- 「helper 输出看着像浏览器那样」**在没有活重放之前不算够**

### 好例子 vs 坏例子（Good versus bad examples）

**好**：

- 第 6 页从静态文件名切换到 `/ui?page=6`
- 决定性 blob 加在 **header** 里，不在 query 里
- 本地运行时外发的 `Cookie` 头与 `document.cookie` **不同**
- verifier sidecar 的长度在恢复 `canvas` 与布局面之后**大致翻倍**
- **被挑战的那个文档 URL 本身**才是 bootstrap 之后的重放目标

**坏**：

- 「用这个 cookie 值」
- 「复用我的浏览器 profile」
- 「这个站很严」
- 「答案大概在大 bundle 里」
- 「运行时看起来是必要的」

### 记录模板（Capture template）

一次可复用的胜利之后、或升级开始漂移时，用这块：

```markdown
最小可验证事实
- 家族：
- 事实 1：
- 事实 2：
- 事实 3：
- 事实 4：
- 事实 5：
```

**只有在每一条新行都能收窄未来 diff 的情况下，才加到 15 条。**

### 升级工作流（Upgrade workflow）

一个之前已解的家族开始坏掉时：

1. 抓一条全新的最小样本
2. **逐行**重新校验旧事实集
3. 把事实切成 `仍然成立` / `已变化` / `未知`
4. **只**逆向变化的那个边界
5. **在新 replay 被证明之后**才更新事实集

> 这把「整个站都变了」变成「三条事实移动了」。

### 存放规则（Storage rule）

放在**最小可复用的家**里：

| 知识的性质 | 放哪 |
|---|---|
| 经验可广泛迁移 | 拥有它的那篇手册（本包内） |
| 仍是单目标、未被互证 | 任务局部分析笔记（`js_reverse_cache/tasks/<task-id>/report.md`） |
| 模式已经重复出现多次 | 家族专属的案例笔记 |

> **优先记结构性事实，而不是拷贝来的工件。**

## 判据（Completion criteria）

1. **事实条数在 5–15 之间**，且每一条都能收窄未来的 diff
2. **每一条都是可测量的**，写完之后你自己能回答「怎么判断它还成立」
3. **零秘密**：没有任何密钥、活 cookie、完整会话头被写进去
4. **每一条都能对应到一段证据**（哪次抓包、哪次运行时工件、哪次本地重放）
5. **升级工作流可执行**：事实集是逐行可复检的清单，不是散文
6. **存放位置符合「最小可复用家」原则**：可迁移的去手册，单目标的去任务笔记

判据的反例（**以下情况算没沉淀**）：

- 写了 3 条含糊的
- 写了 25 条，其中一半是「可能是…」
- 事实里混进了 cookie 值或密钥
- 写的是「看起来像 Firefox」这类不可复检的判断
- 一次可复用的胜利之后什么都没记

## 常见坑（Common traps）

- **把笔记当事实**。「感觉很严格」不是事实。
- **把工件当事实**。「这个 cookie 值能用」不是事实，「这个 cookie 由 bootstrap JS 写出且每轮刷新」才是。
- **不写数量**。少了太含糊，多了不可用。
- **事实里藏密钥**。事实应该是**结构性**的。
- **一次把整站重新逆向**，而不是逐行校验旧事实找出哪几条动了 —— 这是升级工作流存在的原因。
- **在事实里写「运行时看起来是必要的」**。这是结论，不是事实。
