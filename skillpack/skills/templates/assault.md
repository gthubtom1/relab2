# Assault 滚动报告（受保护目标攻坚）

> **动手前先读「攻坚者五条」**（搬运工与货物 / 工具输出是线索不是结论 / 优先查矛盾 /
> 宁可写卡住不许写完成 / 调整路线是正常的）→
> `../reverse-engineering/references/assault-entry.md` 第一屏。姿态在前，判据表在后。
>
> **这是字段清单，不是填写顺序。** 下面的每一格都是「报告必须能回答的问题」，
> 不规定什么时候填、填几次、按什么顺序填。有些格 SURVEY 时就有了，有些 EXECUTE 一半
> 才出现，有些会被推翻重写——都合法。报告是滚动修订的，越改越准。
>
> **三条铁律**：①任何时刻打开本报告，先看 §0 状态行——必须能回答「现在到哪了、凭什么」；
> ②新证据推翻判断时允许且必须跳回任何状态（改动写 decision_delta，不许静默改）；
> ③终点只有三种成品（源码项目 / 复刻实现 / patch 后原程序），验证只有一种方式
> （同输入对照 + `review_case.py` 审计）。
>
> **每一步动手前问一句：「这一步是否让成品更近？」答不上来就是白做。**
>
> 生成：`case-init -Preset assault`。状态机定义与分层判据：`../reverse-engineering/references/assault-entry.md`。

## layers

> 分层台账。判定顺序 L0 容器 → L1 壳 → L2 混淆 → L3 自检 → L4 业务
> （判据不是步骤：任何时刻都要能说清目标在哪几层）。
> 过层判据（外部可观测）见 `../reverse-engineering/references/assault-entry.md` Q2。
> `blocked` 行必须写清 原因/影响/替代。

| 层 | 类型 | 状态 | 证据 |
|----|------|------|------|
| L0 | 容器层（安装包/ASAR/固件/双体） | | |
| L1 | 壳层（加壳/压缩/加密/虚拟化） | | |
| L2 | 混淆层（OLLVM/虚假控制流/MBA/串加密） | | |

| L4 | 业务层（授权/算法/协议/格式/网络） | | |
