# 一次性探索（Spike）

本技能管**一次性的原型探索**：为了回答一个尚未确定的问题，写最小的验证代码，产出的是**判断**（可行 / 不可行、选 A 还是选 B），不是可以合并的代码。

原型代码是消耗品。它的价值在结论，不在仓库里的存量。

## 判据（本技能的核心）

- 若产出是**可合并代码**而非结论 → 走错了技能：spike 的产物是一份结论文档，代码**不合并**、可直接删除。
- 若问题已经确定要做，只是不知道写法 → 不适用本技能，用 `../implement-feature/SKILL.md`；本技能只回答"要不要做 / 哪个方案"。
- 若任务属于**技术选型、可行性验证、方案 A/B 比较** → 适用：为每个候选写出最小可跑验证，用同一组维度比较。
- 若给原型写**生产级测试**（覆盖率、边界、CI 集成） → 停：spike 不写生产级测试；验证脚本能重复跑出结论即可。
- 若原型的**时间盒**已经用完而结论仍未收敛 → 停手，写出当前已知与未知、给出有限度的建议，或升级换技能；不要无限延长原型。
- 若探索过程中发现**问题本身改变了**（真问题是性能 / 是数据模型 / 根本不是这条路） → 记下判据并换技能，不要顺着旧假设继续。
- 若两个方案**证据打平** → 明说打平，并给出可打破平局的下一步判据（一次可测的实验），不要凭喜好钦定。
- 结束时 MUST 给出**"推荐哪个方案 + 凭什么"**：推荐要落到一条可检验的比较维度上，附证据（跑出来的数字、日志、失败复现）。

## When NOT to use（近邻负例）

- 已经确定要做、只是要把它实现好 → 用 `../implement-feature/SKILL.md`
- 要为已确定的行为写正式测试 → 用 `../write-tests/SKILL.md`
- 要评审别人的改动 → 用 `../code-review/SKILL.md`
- 前置条件：原型代码必须放得**可整目录丢弃**（临时分支 / 临时目录），不与主线纠缠

## When to Pivot

信号与判据见 `../ops/skill-pivot-contract.md`。本技能去向：

| 触发证据 | 换到 |
|---|---|
| 结论是 go，且范围已定 | `../implement-feature/SKILL.md` |
| 结论是 go，需要先补测试策略 | `../write-tests/SKILL.md` |
| 结论要交给别人评审 / 交付 | `../code-review/SKILL.md` 或 `../pr-ship/SKILL.md` |
| 结论要以正式文档形式留存 | `../docs-generator/SKILL.md` |
| 探索暴露的是安全或依赖链问题 | `../code-audit/SKILL.md` / `../supply-chain-security/SKILL.md` |

## 定义完成

本技能产出算「完成」的**外部可观测**条件（不许写形容词）：

- 一份结论文档落盘，含：比较维度表（每维每方案一格）+ 明确的推荐 + 支撑证据（命令、数字、日志）
- 每个被验证方案都有可重复运行的命令与观测到的结果
- 原型代码的路径在文档中明确标为 throwaway（可删除，不合并）；主线代码未被其污染

## 输出契约

```
FACT:       <观察，带来源：命令 / 文件:行 / Evidence ID>
HYPOTHESIS: <可测试断言 + confidence: high|medium|low>（状态见 ../ops/binary-model.md）
QUESTION:   <当前最大不确定点>
NEXT:       <继续 | 换技能 | 停止（附成本判据）>
```

## 置信度词表

词表见 `../ops/confidence-vocabulary.md`。本技能特有判据：

- `confirmed`：结论由可直接复跑的验证命令支撑，且两（多）个方案在同一组维度上都被实测过
- `low`：结论仅来自阅读文档 / 设想，原型没有真正跑起来
