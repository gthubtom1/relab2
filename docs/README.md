# relab2 全局文档总导航（进场必读）

> **⚠️ 仓库里有三类文档，规则不同，别搞混：**
> 1. **`docs/` 下的现行文档** —— 可以作为依据（清单见下）。
> 2. **`docs/_history/`** —— **历史件，已退出依据链**（复盘 / 完成状态 / 一次性脚本）。可以读、**不许当现行事实用**：
>    里面的数字与结论描述的是**写下它的那一刻**，例如 `_history/AUDIT-2026-10-15-*.md` 的「本机没有 Node.js」现在就是错的。
>    引用前先自己复算；不确定就按现行文档走。
> 3. **`_归档-禁读-历史文档/`** —— **⛔ 禁止 AI 读取**。
>    口令与理由见仓库根 [`START-HERE.md`](../START-HERE.md) 开头的硬禁令，以及该目录自己的 `README-禁令.md`。
>    一句话：那是留给**人**的存档（前几轮 AI 的方案/清单/复盘/完成状态），描述的是**当时那个版本**，读了会被带偏 —— **不是资料**。

4. **需求档案（灵魂）** → [`lcs-core/`](./lcs-core/)：`00` 总章、`01` 老板原话、`02` 终极需求、`03` 为什么旧模型偏航、`04` 业界方法论、**`05` REA 可借鉴的四条工程写法**、**`06` 卡片体系与换机适配需求档案**（源自 45 轮那个会话）。
5. **完工台账 / 剩余清单** → [`FINAL-彻底完工交接-2026-10-15.md`](./_history/FINAL-彻底完工交接-2026-10-15.md) —— **进度与剩余以它为准**。

   它的「修正指令」已执行（见 `FINAL` §12.1 第 13/14 项），且它 §4.1.1 的结论「本机装不了 REA 的包：无 Node.js / npm，所以『装』这条路物理上不存在」**已被推翻** ——

7. **已知边界** → [`KNOWN-BOUNDARIES.md`](./KNOWN-BOUNDARIES.md)；一条命令列全：`.\relab2.ps1 known`（`-Json` 出结构化）。

## 冲突裁决

> 当仓库里任何文档、注释、历史 rules 与 **`START-HERE.md` + `环境初始化.md` §11** 冲突时，**以后两者为准**。
>
> `_history/` 里的两份**令**继续管它们各自的主题：**施工方法**以 [`HANDOFF`](./_history/HANDOFF-终极交接与施工任务书-全AI通用.md) 为准，
> **进度与剩余**以 [`FINAL`](./_history/FINAL-彻底完工交接-2026-10-15.md) 为准。
> 「退出依据链」指的是 —— **里面的实测数字与「已完成」结论不得直接引用**（先自己复算），
> 不是否定这两份文件作为「令」的身份。两者不矛盾：**令管方向，数字要复算。**

## 严禁

- ❌ **不许读 `_归档-禁读-历史文档/`**（见该目录 `README-禁令.md`）。
- ❌ 不许把"旧文档里写着已完成"当成已完成 —— 只认代码与实测。
- ❌ 不许把探测出来的本机路径写进任何文档（`环境初始化.md` §10）。
