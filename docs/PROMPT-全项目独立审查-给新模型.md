> **设计说明（给主人看，不要发给它）**：上一版提示词列了 11 条"具体建议"——
> 那些**全是我的结论**。它照着打勾就等于把我的答案抄一遍，长不出自己的判断。

> ② 禁读区（防止被旧文档带偏）③ **方法与覆盖面的纪律**。
> **怎么审、审什么、先看哪里，全部由它自己定** —— 报告里必须自述方法，且必须有一节"我自己发现的问题"。

## 一、这个项目要干什么（**这是目标，不是检查清单**）

它叫 `relab2`。主人（一个自称"零基础、靠直觉掌舵"的人）要的东西，用他的话说是：

> **把「一堆技能卡 + 本机装好的工具」组装成一个"像真人老手一样干活"的全域技术中枢。**

他自己反复强调过这么几层意思：

- **换机就能用**：他以后把它托管在自己的 GitHub；换任何一台新电脑，拉下来 → 跑一遍适配 → 就能干活。
  他说过：「我不希望未来再改动这个项目的任何东西，除了换新电脑、加技能、加工具。」
- **不挑智能体**：今天用 omp，明天用 Claude Code / Cursor / Codex / Gemini CLI，换哪个宿主都要能用。
- **不挑机器上的工具**：今天这台装了 10 个软件它能认；换台装了另外 5 个、**名字它没见过**的同类软件，
  也必须能认出、能用。他明确反对「新增一个工具就往清单里加一条、打个补丁」这种活法。
- **工具要在"手边"**：模型得知道本机有哪些工具、并且真的会用。
  （注意一个他亲自定的约束：MCP **按需开启**，不许常驻/看门狗 —— 他要的是"工具常驻可见、后端被调用时才起"。）
- **绝对不许给模型定死流程**：他认为任何软件都千变万化，写死 `Step 1 → 2 → 3` 会把模型限死。
- **四大战场平权**：深度逆向 / 协议抓包与算法还原 / 安全渗透 / 日常软件开发，**不能只有逆向能跑**。
- **破甲卡要干净**：`kernel/04-console/cards/base/` 里的卡只负责身份锚定与反拒答；
  **里面不许有工序、路由、工具路径** —— 因为他以后会**随时从网上换别人的破甲词**，卡里一有流程，换卡就会把路由带歪。
  卡片体系只留两张：`base`（破甲，可换）+ `guest`（全能专精指引卡，指向技能路由）；旧的 hub 卡已废弃。
- **最痛的一条**：他说过上百次「每次都说完成了，一用就出问题」。
  所以他最恨**自证式完成** —— 自己编一份清单、自己打勾、自己宣布成功。

**判断标准不是"它有没有按上面这几条做"，而是**：
**如果他说的这些是对的，一个真做到位的项目该长什么样？这个仓库离那个样子还差多远、差在哪？**
**如果上面某条要求你觉得根本站不住脚（技术上做不到、或者本身就是坏主意），你也要说出来。**

## 三、怎么审 —— **由你自己定**

**唯一的要求是：不许只挑几个文件看两眼就下结论。** 自己决定：

- 先怎么摸清这个仓库是什么、有哪些层、各自承诺了什么；
- 用什么办法抽样、用什么办法交叉验证"文档说的"和"代码做的"是不是一回事；
- 怎么判断一条承诺是"真做到了"还是"只是写下来了"；
- 要不要跑点什么、算点什么、复现点什么。

**别把任何东西当权威**：仓库里的文档、注释、索引、自述数字，全都只是"有人这么写过"，
只有你自己读到的代码和跑出来的输出才算证据。

## 四、报告必须包含这五节

1. **我决定怎么审的、为什么这么审。**
   （如果这一节看起来像在回答别人给的清单，那这份报告作废 —— 没有清单。）
2. **这个仓库在我眼里是什么**：它到底承诺了什么、哪几层是真的、哪几层是摆着的。
3. **★ 我自己发现的问题**：**不是**回答我上面说的那几层意思，而是**你在审的过程中自己撞见的**。
   每条给证据（`文件:行` 或命令输出原文）+ 根因 + 影响 + 怎么改。
   **这一节空了不行**：如果你一个都没发现，请写清你实际读了多少文件、跑了什么、用了什么方法，
   以及**为什么**什么都没发现 —— 但不要把「我没发现」写成「没问题」。
4. **覆盖面**：你实际读了/跑了多少（文件数、门数、命令数），占全仓多大比例，**哪些没看、为什么没看**。
5. **无法取证的**：哪些结论你只能推测、哪些你根本没法验（写清楚，别糊过去）。
