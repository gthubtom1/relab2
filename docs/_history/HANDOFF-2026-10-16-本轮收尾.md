### 1.1 换机 P0：全新 clone 的第一入口是死的（BOM）

**症状**（真 PS 5.1 + 936 码页，在 HEAD clone 上复现）：
```
C:\tmp\...\relab2.ps1:33 字符: 45
+     $script:Results.Add([pscustomobject]@{ 椤?= $Name; 缁撴灉 = $Status;  ...
哈希文本中的键后面缺少"="运算符。   ← MissingEqualsInHashLiteral
```

**已修**（补 BOM，6 个文件）：

`skills/scripts/experience-cards/fixtures/scope-probe.ps1`、

### 1.3 工具解析被 PATH 遮住 → `_map.json` 别名形同虚设

**症状**：`test-tool-recipes` 红 2 条 —— `tool.ropgadget` 报 `WinError 193`（不是有效 Win32 应用）、
`triage.capabilities` 报 `default embedded rules not found`。

**根因**：`Resolve-ReverseToolSpec` 是**四级递进、命中即停**（env → PATH → `_map.json` 别名 → 工具根）。
本机 `D:\Tools\cli` 在 PATH 第 **13** 位，而 `%APPDATA%\Python\Python314\Scripts`
（含**无扩展名 POSIX 脚本** `ROPgadget` 和**裸** `capa.exe`）在第 **11** 位 → 第 2 级 PATH 命中就跑不起来的形态，
**永远轮不到第 3 级别名**（别名表里明明登记了 `cli\ROPgadget.cmd` / `cli\capa.cmd`）。

**已修（两处，缺一不可）**：
1. **仓库侧** `skills/scripts/lib/Bootstrap.ps1`：原逻辑
   `if ($pathList -notcontains $cliCandidate) { 前置 }` —— 只要 `cli` 已在 PATH 就什么都不做（不管排第几）。
   改成**「`cli` 不是第一个 PATH 段就挪到最前」**（幂等）。
2. **工具根侧** `D:\Tools\_map.json`：给 `capa` 的 `deny` 补 `*\Tools\cli\capa.exe`
   （`cli\capa.exe` 也是裸 exe、同样缺 rules 包装）。**备份在 `%TEMP%\_map.json.bak`**。

**实证**：修后 `ROPgadget`/`capa` 都解析到 `D:\Tools\cli\*.cmd`；`test-tool-recipes` 从 `ok=67 fail=2` → **`ok=69 fail=0`**。
