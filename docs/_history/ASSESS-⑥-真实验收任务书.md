## 1. 出题要求（给主人）

1. **目标**：一个**本模型没见过**的加壳 / 反调试 / 授权判定类软件（本机 Windows 上可运行）。
   - 优先「真家伙」：带壳（UPX / VMProtect / Themida / 自研壳任选）、或有反调试、
     或有本地授权判定。
   - 找不到现成的：也可以给一个**自己编的小程序**（加一层简单壳 / 一个序列号校验），
     只要**模型没见过**即可。
2. **零提示**：只给两样东西 ——
   - 文件路径（或目录）；
   - 一句话要求，例如「做出能正常使用的成品」。
   **不要**提示壳的种类、不要提示该用哪把刀、不要提示入口在哪。
3. **可复现**：目标要能在本机直接跑起来（不然连"做没做出来"都没法判）。

## 2. 验收判据（照 `HANDOFF-终极交接与施工任务书-全AI通用.md` 的「唯一验收标准」）

**产出必须是一个能跑的成品，不是一份报告。** 三者任选其一（按目标形态）：

| 目标形态 | 合格成品 |
|---|---|
| 有本地授权判定 | 破解版可执行文件（原功能正常、授权门被绕过）**或** Keygen（能算出该程序接受的序列号） |
| 有自研算法 / 加密 | 算法还原脚本（对给定输入产出与原程序一致的输出，逐字节可对账） |
| 只有壳 / 反调试 | 脱壳后可运行的程序，**且**原功能被验证过（不是"能跑就算"） |

**过程必须留下可观察的轨迹**（不是只看结果）：
- 自己判壳 / 判保护（`diec -d -e -j` 之类）→ 决定换工具 → 换技能；
- 至少一次**真实的技能切换**（例如 `reverse-engineering` → `x64dbg-reverse` → `code-patching`），
  且 `timeline.md` 里写清**为什么换**（换了什么证据触发的）。

## 3. 记录格式（跑完交回这几样）

```
work/<case>/
  scope.md                 # case-init 落地：目标、网络档、产出物
  route-scope.md           # master-route 选中 PRIMARY 的原始输出
  timeline.md              # 过程；每次换技能写一行「换技能：<旧> → <新>，因为 <信号>」
  workitems.md             # 工单
  evidence/                # E-*.md，每条带 repro_command 与原始输出
  <成品文件>                # 破解版 / keygen / 算法脚本
```

成品必须附**哈希**（`Get-FileHash` 或 `sha256sum`），并在 `evidence/` 里留一条带哈希的证据。

## 4. 失败也算结论（重要）

卡住不是失败，**卡住不说清才是**。若推进不下去，交回：

1. 卡在哪一步（现象 + 原始输出）；
2. 缺哪把刀（工具 id + 探测层怎么说：`Resolve-ReverseToolSpec -Name <id>` 的实际返回）；
3. 已经试过什么、为什么不行。

第 2 条要写进 `docs/KNOWN-BOUNDARIES.md` §9（那是"已知未闭环项"的正规去处），
而不是留在聊天里。
