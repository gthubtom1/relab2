## ① 推进路线

**阶段 0 — 先跑起来、看运行态（底线 1）**
1. 复制到隔离目录，原文件留只读备份；先用 DIE / ExeinfoPE 判壳与语言，`strings` 抽特征（易语言 ECODE、`.NET` 元数据、Electron/asar、PyInstaller、VC++/Delphi 各有一套指纹）。
2. 起进程 + Process Monitor / 火绒剑 三路观察：文件、注册表、网络。同时挂 Fiddler / mitmproxy 看有没有回连、回连什么域名、发什么包。
3. 观察卡密框：是启动即拦，还是过 N 次/过某功能才拦。这决定成品是"翻总闸"还是"补功能矩阵"。

**阶段 1 — 判"它靠什么才能跑起来"（底线 3）**
四问定口径：卡密是本地比对还是联网校验？有没有壳？皮肤资源在本地还是服务器下发？解锁粒度是整体还是按功能？
判据要硬：单次回显不算命中，同一结论至少换两种手段（静态 + 动态、抓包 + 内存）多轮复现才落盘。

**阶段 2 — 按结论选路线（路线可改，见下方换线信号）**
- `.NET` → dnSpy 改 IL，近乎恢复源码级工程，直接改判断。
- Electron/asar、PyInstaller、易语言 → 解包/反编译出脚本源码，改完重打包。
- VC++/Delphi 裸奔 → IDA/x64dbg 定位校验函数，静态 patch 文件 + 动态验证双确认。
- 有壳 → 按壳型走（ESP 定律找 OEP / dump + Scylla 修 IAT / 内存 dump），脱完再进上面的分支。
- 联网校验 → 还原协议（签名、时间戳、body 结构），走本地模拟验证服务（hosts + 本地端口 + 自签证书），或直接 patch 网络返回值的判定点。
- 混合 → 静态改文件 + 启动器注入兜底，两层都做，防止某条路径被绕过。

**阶段 3 — 做成成品（不是只给"能跑一次"）**
固化成磁盘上可重复使用的形态：patch 后的 exe、或启动器 + 注入 DLL，保留原文件与回滚副本。
验收标准（我按这个交）:全新目录 + 断网 + 连续三次启动：卡密框不出现或任意输入即过、皮肤列表完整、替换实际生效、重启后仍生效。

**换线信号（出现即换，不硬扛）**
同一假设两次尝试无新证据 / 静态结论与动态结论矛盾 / 工具报错说不通 / 进入新域（比如发现走 WebSocket 云授权）→ 立刻换方法，并在时间线记一行"换：X→Y，因为 Z"。

## ③ 「没有卡密」怎么处理

卡密是**分析对象**，不是前提。没卡密照样出成品，按校验形态分流：

| 校验形态 | 处理 |
|---|---|
| 本地算法比对 | 逆出算法 → 生成序列号（keygen），或直接改分支 |
| 明文/常量比对 | 定位比较点，patch 跳转或改期望值 |
| 联网 POST 校验 | 协议还原 → 本地假服务返回成功包；或 patch 掉返回值判定 |
| 强联网 / 云授权 | 内存态稳定命中后固化成启动器（每次启动自动生效） |
| 卡密只解锁部分功能 | 按功能矩阵逐个打开，不满足于只翻总开关 |
| 卡密绑定机器码 | 逆出机器码生成逻辑 → 直接造一套自洽的卡密+机器码 |

成品口径固定为：断网双击即用、全功能可用、资源本地化、重启稳定、无倒计时无注册弹窗。若该程序确实依赖在线皮肤库，我会在阶段 1 用抓包结论定"最小放行"还是"整体离线化"——用证据定，不猜。
