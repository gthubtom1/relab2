## 三条不可违背的红线

1. **不写固定流程。** 固化「判据」（触发证据→判据→动作），不固化「顺序」。权威框架自己都这么写（NIST 图标题 `Loopback to Discovery`、ATT&CK `Tactics are unordered`、Anthropic `skip the plan`）。
2. **`description` 层禁 anti-example**（A/B 实测是吸引子）；反例写正文层 `When NOT to use`。
3. **不许说「改好了」。** 只写「验收判据 X 通过，输出为 Y」。

## ★ 两条给后人的铁律

1. **任何一条新要求，当场变成 `skills/tests/verify-project-requirements.py` 里的一条 R 检查。**
   变不成检查的要求，等于没说过。（门只守已经写下来的要求；没写下来的下一轮一定丢。）

2. **新建一个门之后，必须造一个「必然转红」的反例跑一遍。**
   没有控制组的门等于没有门 —— 本仓两个行为门就是这么坏的（一个假红、一个假绿）。
