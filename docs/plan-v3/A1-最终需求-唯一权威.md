## 〇、一句话

> **换机 + 换智能体，跑一遍适配流程就能用；此后除「换机 / 加技能 / 加工具」外不再改动任何东西。**
>
> 逆向一个目标时，给个软件就能自己思考、自己换技能、配工具，**做出成品**（不是报告）。

## 二、三层架构与边界（最硬的设计约束）

### 2.1 只留两张卡

```
base（破甲提示卡）  →  宿主 PERSONALITY.md    只管一件事：不许拒答
guest（全能专精）   →  宿主 RULES.md          只管一件事：点火 + 指路
skillpack（技能包） →                        管工序、工具、判据、产物
hub（01-04）        →  已搬进技能包，不再挂
```

依据：
- 〔原话 74〕「以后就是 **base 和 gust 两张卡**使用了」
- 〔原话 74〕「**HUB 卡暂时就几乎没有用了**…也许未来我会加其他的新的 Hub 卡，当然是不和技能中枢冲突的，那是未来的事情」
- 〔原话 44〕「omp 和其他智能体不一样：**破甲放人格 md，全能专精放规则里**；其他智能体是三层融合…**我们只需要这两个**」

### 2.2 铁律（哪些能互相影响，哪些不能）

| 铁律 | 内容 | 依据 |
|---|---|---|
| **①** | **破甲词里不许出现**「点火 / 路由 / 工序 / 工具路径 / 分几段交付」 | 〔原话 68〕「点火明明在 Rules 里有，我们为什么还要在这个破甲词里面要有呢」；〔原话 69〕「原型里既然没有那些流程，我们现在也不应该有」 |
| **②** | **技能包里不许出现**「拒绝策略 / 破甲措辞」 | 卡片体系铁律二；`RULES.md` 明写 no target-authorization gate |
| **③** | 两者唯一交汇点：入口卡里那一句「**点火 → 读 PRIMARY**」 | 同上 |

**④ 是①②存在的理由** —— 不是洁癖，是换卡时不破坏路由的必要条件。

- 〔原话 52〕「我担心 **HUB 那个卡片会影响到我们的技能中枢**，就那技能路由啊、那些工具链。如果说那个 Hub 里面限制太多，不就冲突了嘛」
- 〔原话 74〕「为什么不要那个 HUB 的卡呢？就是因为**昨天发现了一个问题，HUB 的卡和技能路由里面是冲突的**」

## 四、逆向攻坚（不许固定流程）

### 4.1 目标口径

| # | 需求 | 依据 |
|---|---|---|
| **A1** | **要的是成品**：「所有功能都正常，我拿来就能用」 | 〔原话 92〕「我最终要的就是一个成品软件。原软件的所有功能都要一样，都要能正常能用」 |
| **A2** | **不是分析报告、不是"主要功能可用"、不是"部分完成"** | 〔原话 84〕 |
| **A3** | **最怕搞到一半**；做不出就要把"为什么真做不出"钉死 | 〔原话 84〕 底线4 |
| **A4** | **别跑偏、别缩、别拒绝** | 〔原话 84〕 |

### 4.2 四条底线（〔原话 84〕 原话）

1. **先让它跑起来看运行态**，再谈逆向（运行中的程序 ≠ 磁盘上的文件）
2. **判据要硬**：原子值 + 多轮稳定；回显 ≠ 命中；工具静默 ≠ 没发生；关键结论要 **≥2 条独立证据**
3. **先判"它靠什么才能跑起来"**（别的进程/服务器/授权/硬件/账号），再定成品口径 → 别拿"要真环境"当借口
4. **路线可改，但不许"改着改着就不做了"**；要停必须说清原因

### 4.3 ★ 不许固定流程（〔原话 64〕 是最硬的一条）

> 〔原话 64〕「你这个逆向你**没办法固定流程**，因为那个软件都是不一样的，难度是不一样的，你固定流程，对吧？它肯定是**靠 AI 自己去思考**，再搭配我们的技能、路由和工具什么的。」

> 〔原话 74〕「我担心限制流程…不同的项目、不同的软件去逆向，他就给固定了，限制住了，他就搞不定。」

**落地原则：固化的只能是"判据"（触发证据 → 判据 → 动作），绝不能是"顺序"（先做 X 再做 Y）。**

### 4.4 实弹的硬约束

- 〔原话 93〕「**我没有卡密**…设置好 /goal 模式，然后持续推进吧，我要睡觉了，我需要最终的成品」
- 〔原话 98〕「**我强调了很多次，我没有卡密。**」

→ **不许把"给我一张卡密"当成必要前置。** 没凭据时给不依赖凭据的路线。

### 4.5 主人可见性（〔原话 84〕 汇报要求）

只在四个关键点报（定完路线要开打 / 卡住要停 / 成品出来 / 需要我决定），**用人话四句**：
① 现在到哪了 ② 成品到没到 ③ 要不要我给东西 ④ 下一步

## 十、可直接执行的验收判据

| 需求 | 怎么验（外部可观测） |
|---|---|
| **G1/G2** | 换机脚本走完 → `git status` 干净、`run-ci-gates` 全绿 → 之后**再没有任何一次"必须改"的对话** |
| **G3/S4** | 在**另一个**智能体里问技能清单 → 能列出全部技能 |
| **S1/S2** | 新会话问「有哪些技能能用于当前这个任务」→ 模型自己答得出来、且说明"可随时换" |
| **S5** | 问「本机注册了哪些 MCP、谁在监听」→ 答得出（`mcp-status.ps1`），而 MCP 进程平时不在跑 |
| **①②③④铁律** | `grep` 破甲卡：0 处「流程/步骤/路由/工具路径」；`grep` 技能包：0 处「拒绝策略」停门 |
| **A1–A3** | 给一个 exe + "做成成品" → 产出可用成品（或钉死的卡点），不是报告 |
| **§4.3 不固定流程** | 技能包里**没有任何** "第 1 步 / 必须按顺序" 的编排；只有条件式判据 |
| **M1/M2** | 新机器读 start here → 输出一份"本机适配清单"并逐项更新 |
| **M4/M5** | 全仓 `grep` 旧机路径 / 旧机用户 / 会误导的说法 → 0 命中 |
| **C1** | 控制台无模式选择控件 |
| **C2** | 对一个没有入口文件的智能体点载入 → 自动创建成功 |
| **O3** | 远端与本地 `git rev-parse HEAD` 相同 |
