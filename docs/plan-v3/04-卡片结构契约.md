# 卡片结构契约（47 张 SKILL.md 的统一骨架）

> 依据见 `02-判据表-可固化与禁固.md` 与三方调研。
> **本契约规定"每张卡必须有什么"，不规定"按什么顺序做"。**

---

## 1. Frontmatter（已有，保持）

```yaml
---
name: <gerund 或名词，禁 helper/utils/tools>
description: <一句话做什么>。用于：<触发场景，含用户可能的原话>。
---
```

**description 层红线（上一轮 A/B 实验结论）**：
- 单行、≤220 字节、总量 ≤10000 B（已有 `check-prompt-budget` 门）
- **不写 `不要用于：`** —— 实测是吸引子，会把模型推向错邻居（windows-ad 写"全链→attack-chain"，模型真去选 attack-chain）
- 反例放**正文层**（见 §2.2）

## 2. 正文必含 5 段（本次 L1.1 新增）

### 2.1 `## When NOT to use` —— 近邻负例（正文层）

```markdown
## When NOT to use（近邻负例）

- <情况 A：与本文共享关键词但需求不同> → 用 `<另一技能>`
- <情况 B> → 用 `<另一技能>`
- 前置条件型：<若无法安全运行样本 / 缺工具 / 超出本域> → <去 eps/XXX 或停下说明>
```

**规范依据**：agentskills 要求负例必须**近邻**（共享关键词但需求不同）；弱负例（"天气怎么样"）测不出任何东西。

### 2.2 `## When to Pivot` —— 换技能钩子

```markdown
## When to Pivot（我不适用了 → 换谁）

| 触发证据 | 换到 |
|---|---|
| <判出壳/判出语言/判出协议…> | `<技能>` |
| <工具或环境报错且说不通> | `<技能>` 或停下查为什么 |
| <同一假设连续两次无新证据> | 回 `ops/analysis-decision-framework.md` R43 |

换技能时在 timeline 记一行：`换技能：<旧> → <新>，因为 <证据>`
```

### 2.3 `## 定义完成`（definition of done）

```markdown
## 定义完成

本技能产出算"完成"的**外部可观测**条件（不许写形容词）：
- <产物真实存在于磁盘的路径>
- <可运行/可构建的最小命令>
- <功能对照一致，或"受限 + 具体原因">
```

**依据**：hackersifu 贡献规范；Google：no such thing as perfect code, only better；Anthropic：门禁绿/能启动/报告厚**单件都不等于成品**。

### 2.4 `## 输出契约`

```markdown
## 输出契约

FACT:      <观察，带来源（命令/文件:行/证据 ID）>
HYPOTHESIS: <可测试断言 + confidence: high|medium|low>
QUESTION: <当前最大不确定点>
NEXT:      <下一步：继续 | 换技能 | 停止（说明成本判据）>
```

**依据**：binary-re 的 FACT/HYPOTHESIS(confidence)/QUESTION/Next phase 四行契约。

### 2.5 `## 置信度词表`

```markdown
## 置信度词表

| 词 | 可观测标准 |
|---|---|
| confirmed | ≥2 独立证据（最好 1 静 1 动），已跑 ≥3 轮 |
| high | 1 条强证据 + 无反面证据 |
| medium | 1 条证据，未交叉验证 |
| low | 推断；**MUST** 在标 validated 前安排动态验证 |
| contextual | 仅在本案例上下文成立 |
```

**依据**：hackersifu 的 confidence vocabulary；本项目 ADF-R1/R4*。

## 3. 保留的既有结构（不动）

- `ACTION REQUIRED`（46/47 已有）
- Prerequisites / Additional Resources
- Problem-Solving Workflow（**其中"8 步"等是快速通道，不是强制顺序** —— 已在 reverse-engineering 卡注明，其余卡需检查是否有同样误导）
- Quick Wins

## 4. 阶段措辞的修订规则（L1.5 配套）

**禁止出现**：
- "必须按顺序" / "第一步必须是" / "然后才能"
- "先 X 后 Y" 且无反证条件

**改为**：
- "若 <证据条件> → <动作>；否则 <另一分支>"
- "完成本阶段的判据：<外部可观测>"（而不是"做完本阶段后进入下一阶段"）

**依据**：NIST SP 800-115 图标题即 "Loopback to Discovery"；OWASP WSTG "should not be seen as prescriptive"；ATT&CK "Tactics are unordered"；Anthropic "If you could describe the diff in one sentence, skip the plan"。

