> 文档所有者：Little Code Sauce (LCS)
> 核心背景：YG 坦言自己是零基础，凭借敏锐直觉提出“绝不能固定死流程”，并明确要求 AI 去网上论坛、资深专家的真实经验中汲取营养。
> 调研来源：USENIX Security、SOUPS、NIST SP 800-115、PTES、ATT&CK、Anthropic / Google 官方最佳实践、资深一线逆向/渗透工程师博客。

# 一、逆向工程域：真实逆向高手到底怎么思考？

### 1. 绝不从头到尾读代码（Mantovani USENIX'22《RE-Mind》）
- 专家逆向小目标时，不仅不做全局扫描，反而直奔核心逻辑（快速跳过 20+ 基本块）；
- 资深职业逆向 Ryan Stortz 原话：“从 `int main()` 开始读通常是最蠢的做法，只在极小的玩具程序上有用。”
- **真经**：**Middle-out（从中间向两端剥）**。先找与目标直接相关的关键行为（如弹窗、网络发包、报错字符串、注册表访问），以该点为锚点向上下游回溯。

### 2. 假设驱动而非盲目探索（Ryan Stortz）
- “最好的逆向工程师首先是一个合格的软件开发者。”
- 高手面对一个功能，先想：“如果是我写这个软件，我会怎么实现验证/加密/防调试？”先列出 2-3 种最可能的代码实现，再去二进制里找对应的特征。
- 用假设去验证，而不是在大海里盲目捞针。

### 3. 极速切换手段，绝不在死胡同里耗费超过 2 分钟（SOUPS'24）
- 一线专家原话：“与其花 2 个小时在 IDA 里死磕一段被混淆的代码，不如花 2 分钟用动态调试或 Hook 跑一次！”
- **换法阈值**：静态分析遇到花指令/加壳/混淆 → 立刻转动态转储或 Hook；动态调试遇到进程秒退/断点被清 → 立刻转反调试探测与补丁。

# 二、渗透测试与攻防域：真实黑客怎么打点与横向？

### 1. 战术无序，高度动态回流（NIST SP 800-115 / MITRE ATT&CK）
- ATT&CK 官方明确：“ATT&CK Tactics are unordered（战术是没有固定顺序的）”；
- NIST 标准明确指出：“攻击是一个持续发现并随时回流的循环过程（Loopback to Discovery）。”
- **真经**：拿到一个资产，绝不是死板地“端口扫描 → 漏洞扫描 → 漏洞利用”。在任何一个节点拿到新凭据、新路径、新指纹，立刻回流到侦察面，动态开辟新路径。

### 2. 避免工具过载与过早承诺（arXiv 2602.17622 论文）
- Agent 做渗透最大的失败（58%）是“复杂度壁垒”：过早死磕某一条看起来像漏洞的死路，上下文被大量无用扫描日志占满，忘掉了最初的目标；
- **真经**：只保留高置信度的证据，工具输出必须提炼成结构化结论，随时评估当前路径难度，难度过高立刻止损换面。

# 三、日常软件开发域：工业级工程师怎么高效交付？

### 1. “看起来做完”是最大的陷阱（Anthropic Claude Code 官方实践）
- 官方直言：“没有一个可以运行的客观检查，‘看起来做完了’就成了唯一的信号，人类就不得不沦为验证循环的苦力。”
- 严禁空口宣称完成，必须跑通真实的端到端行为验证。

### 2. 小步快跑，拒绝过度工程（Google Engineering Practices）
- 单次变更控制在自包含的小范围内，不做无用的抽象，不为了“未来可能用到”去加一堆花哨的代码；
- 保持规则极简短小（<500行），只在反复踩同一个坑时才固化为硬规则。

# 四、YG 全域技术中枢的灵魂装配

把上述真经全部熔铸到 relab2 的中枢神经中：
1. **逆向**：目标驱动，快速寻找锚点，静态卡住立刻转动态，有壳脱壳，有反调试过反调试，做出成品；
2. **渗透**：情报动态回流，拿到蛛丝马迹随时换攻坚技能，工具输出提炼结论，不让模型迷失；
3. **日常开发**：小步验证，快速交付，拒绝空洞代码与死板清单，能跑通才是真本事。
