# 06 · 卡片体系与换机适配 · 需求档案（源自 `01a135bf` 会话，45 轮）

> 而**卡片三层结构、破甲卡为什么必须干净、MCP 为什么按需开启、换机适配到底怎么走**这些架构决策，
> 全部出自更早、更长的 `01a135bf`（45 轮）。**信息空洞就在这儿，补齐。**

## 一、卡片体系：三层 → 只留两张

| 层 | 是什么 | 现状 |
|---|---|---|
| **base（破甲卡）** | 身份锚定 + 反拒答。**主人以后会随时从网上换别人的破甲词** | ✅ 保留，5 张（每个模型一张） |
| **guest（全能专精指引卡）** | 指向技能路由 | ✅ 保留，1 张 |
| **hub** | 原来承载"工程距离 / 工作流"那一套 | ❌ **废弃**，功能已并入技能路由 |

**为什么废 hub**（原话大意）：
> 「HUB 的卡和技能路由里面是冲突的。所以说昨天那个对话，他就把 HUB 里面的卡的功能放到了技能路由里面，让它去路由。」
> 「以后就是 base 和 guest 2 张卡使用了。」

**hub 卡要留备注**（原话）：
> 「hub 卡里面加备注，或者 txt 格式，里面写清楚不用刻，功能都已经在技能路由里面了。这样以后不会误解了。」

---

## 二、破甲卡**必须干净** —— 这是为了「随时换卡」

> 「破甲词的卡片是我以后随便都能更换的，我在网上找到的好的破甲，我都可以放进去。**所以说我就为什么让你把那些流程给禁掉，
> 因为我就担心，如果说流程是在这里面的话，以后换卡了，我们的路由就会有问题。**」

推论（现在写死在 `verify-project-requirements.py` 的 **R1** 里）：
- 破甲卡里**零**「工序 / 路由 / 工具路径 / 第 N 步 / 分几段交付」；
- 它只管**减少拒绝**（原话：「它里面一些约束也是为了破甲」）。

**但不要往卡里加别人的东西**：
> 「你不要加他们里面那些东西，因为我们自己做的这几张卡是我们经过多轮打磨的。」

**换卡时问一句**：
> 「你在他这里面加一下，就是运行的时候会提前问我用哪些模型，然后那个 API 和 key 他也会问我，然后我会指引他。」

---

## 三、MCP：**必须按需开启**，不许常驻

> 「那个 mcp 这些东西我们不要再让他一直开启了，就是我们一定要设置为**按需开启**……
> 因为换了机什么 IDA 啊，有些他有可能版本不一样，或者什么情况。之前换了机……它总是那个 **cmd 窗口弹一下，因为它后面有 watchdog**。」

→ 本包因此**不注册任何计划任务 / 看门狗 / 开机自启**（`环境初始化.md` §11 的 D 组、`tool-registry.md` §1）。

**主人在同一会话里的怀疑（很重要，说明他要的不是"永不开启"）**：
> 「我们之前加了工具/mcp **按需开启，是不是导致他不用工具？不知道用工具？**」

→ 这正是 2026-10-15 那次施工要解决的：**按需开启是对的，但工具必须"在手边"** ——
于是有了 stdio·懒启动代理（`mcp-lazy-http.py`）：**工具常驻可见，后端被调用时才起**。

---

## 四、换机适配：他真正要的流程

> 「我们换了机之后就会让那个**新的智能体去读这个 start here**，它就会根据我们当前电脑的实际情况，
> 比如说你现在这个电脑装了 20 个工具，然后另外一台电脑我换了台新的之后它只有 10 个工具，对不对？
> 它这样读一遍之后，它就会去把**所有关联东西**给它进行更新。」

**关键澄清（别理解反）**：
> 「**不是说让你现在把一些东西都改成那种通用的**，并不是这个道理。就是说为了保证以后，
> 因为以后不是说拷贝过去就能用，我们肯定要适配一下……要的是刚开始的那些**指引文件**。」

→ 所以 `START-HERE.md` + `环境初始化.md §11` 是**指引文件**，不是"通用化改造"。
→ 终局目标（原话）：**「以后彻底换电脑，就开始的一套全部的适配流程走完就 OK 了，就不需要再修改任何东西了。」**

**旧机残留必须清**：
> 「不要留那些，为什么保留啊？因为我们现在**彻底换了台电脑**啊，我们不应该有之前那些残留的那种说明啊……
> 加了一些很多的多余的说明不是会让以后智能体使用的话，那个大模型会产生误解吗？」

## 五、omp 与别的智能体**不一样**（分层不同）

> 「omp 它跟其他的智能体不同……我是把那个破甲**装到你的人格的那个 md 里面**，
> 然后那个全能专精那个**放到 rules 里面**，你这个 omp 它是跟其他不一样的，
> 其他的软件它是放在**整合在一起**，你是可以分开的。」

→ `PERSONALITY.md` ← base 卡；`RULES.md` ← guest 卡。
→ 别的智能体是"三层融合"；**omp 只要这两张**。
→ 这条已经落到 `kernel/04-console`（工作台）与 `环境初始化.md §11.1-B`。

---

## 六、工作台：入口文件不存在 = **首次安装，自己建**

> 「你那个外置中枢，我们那个工作台启动之后，你那些扫描到的那个智能体啊，
> 如果说它本来就没有那个放那个我们那个卡片的、比如说 `AGENT.md` 这种位置，它因为我是新装的那些嘛，它就空的，
> 它没有这个文件你就**会报错，必须得手动创一个**。这个应该不合理的。」

→ 已修（2026-10-14）：工作台**直接把文件建出来再写**，不再报错要求人手动建。

---

## 七、GitHub CLI 的全局指令，要放在**技能路由**里

> 「这个应该是全局都可以用的，就全部换电脑，我肯定会要登这个 GitHub CLI 的。
> 所以说保证他一定能知道……你看这句话到底加在哪里比较合适？**我觉得技能路由里面比较合适吧**，
> 就是保证以后**所有指令都能读得到**的。**我不太希望放在卡片里面，因为卡片后期我应该可能会编辑。**」

→ 落在 `skills/SKILL.md`（COMMAND DISCIPLINE 的「GitHub 访问（硬门）」）。

---

## 八、收尾时他明确要求做的事

> 「确定没有问题了吗？如果没有问题，清理一下垃圾和一些容易误解的东西。然后**推到我的 gh 仓库**。
> 推上去保证和现在本地是一模一样的。然后**清理那些仓库里的旧的中枢仓库。比如 `relab` 这些**。因为我改版太多，只保留我们这一份。」
> 「本机上有垃圾吗？都清理干净了吗？各个文档里有没有啥残留？别以后换机，那几个引导文档误导新 AI。」

---

## 九、这条档案对今天的直接约束（一句话版）

1. 破甲卡 = 随时准备被换掉 → **不许带流程/工具路径**（R1 在管）。
2. 只留 base + guest 两张；hub 已废并留了「不用了」备注（R7 在管）。
3. MCP **按需开启**是对的，但**工具必须常驻可见**（懒启动代理在管）。
4. 换机靠的是**指引文件 + 适配流程**，不是把项目通用化。
5. 旧机残留、误导性说明 —— **一律清掉**，别让下一个 AI 读偏。
