# 二、四大战场保姆级实战作战剧本（Runbook · 照着做就能出结果）

### 剧本 1：深度逆向攻坚实战剧本（目标：做出可用成品）
1. **第一步（30秒侦察）**：
   运行 `D:\Tools\cli\diec.CMD --extended target.exe`，检查加壳情况；
   运行 `D:\Tools\cli\floss.EXE target.exe` 导出关键可疑字符串。
2. **第二步（判断分支）**：
   - 若检测到无壳/轻量壳 → 打开 IDA 批处理分析关键校验函数；
   - 若检测到 UPX 等压缩壳 → 直接运行 `upx -d target.exe` 脱壳；
   - 若检测到 VMP / 强保护壳 → 严禁死磕虚拟代码，按照《文档 05》执行外围 Hook 或内存 Dump 策略。
3. **第三步（动态验证与绕过）**：
   - 挂上 x64dbg（确保 ScyllaHide 插件勾选），断在关键判断跳转（如 `jz` / `jnz`）；
   - Patch 内存或改写二进制字节（记录原始字节与修改字节）；
4. **第四步（成品验收）**：
   在干净命令行双击运行修改后的程序，确认无需卡密、无需联网即可正常运行，交付最终成品。

### 剧本 2：日常软件开发实战剧本（目标：高质量交付功能/修复Bug）
1. **第一步（需求与边界澄清 · req-clarify）**：
   明确输入格式、预期输出、异常情况，严禁盲目猜需求。
2. **第二步（切分切片 · design-slice）**：
   将任务切成 ≤100 行的自包含改动，绝不搞一次性修改几千行的巨石工程。
3. **第三步（测试先行验证 · write-tests）**：
   先写一个能够准确复现 Bug（或覆盖新功能）的失败测试用例，实测证明它确实失败。
4. **第四步（编码实现 · implement-feature / fix-bug）**：
   做最小必要代码修改，再次运行测试，证明测试变绿。
5. **第五步（全量回归 · verify-done）**：
   运行全量测试套件，确认既有功能零退化，交付干净代码。

---

### 剧本 3：协议分析与算法逆向实战剧本（目标：输出独立通信脚本）
1. **第一步（抓包与通信全貌）**：
   通过代理或本地网络监控捕获完整交互流，找出核心业务请求（URL、Header、Body）。
2. **第二步（特征参数提取）**：
   提取出请求中的加密字段（如 `signature`、`token`、`nonce`、`data`）。
3. **第三步（算法回溯与打桩）**：
   - 若是 Web 接口 → 搜索前端 JS 源码，定位加密函数（AES/RSA/自定义混淆），必要时用 Node.js 补环境执行；
   - 若是移动端/桌面端 → Hook 核心加解密 API（如 OpenSSL、CommonCrypto 或 Java `Cipher`）。
4. **第四步（独立可用成品）**：
   用 Python 编写一段独立脚本，完整复现签名计算与发包流程，脱离原客户端独立成功获取响应。

### 剧本 4：安全攻防与渗透测试实战剧本（目标：打点与情报回流）
1. **第一步（资产指纹与被动侦察）**：
   快速收集目标开放端口、服务版本、Web 中间件指纹。
2. **第二步（脆弱面聚焦）**：
   根据指纹查询已知 CVE 漏洞与配置缺陷，禁止盲目进行全端口大流量扫描。
3. **第三步（动态情报回流）**：
   只要在任意接口拿到新凭据、新路径、新报错信息，立刻回流到侦察面，动态更新攻击假设。
4. **第四步（无害化验证与报告）**：
   编写 PoC 验证漏洞真实可达性，附带完整的复现 HTTP 数据包证据链。
